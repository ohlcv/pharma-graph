## 一、背景（Context）

2026-09-20 完成一次启动链路全面重构。三个独立但互相耦合的痛点同日浮出：

1. **冷启动慢** — 浏览器首次加载要并发拉 1042 个请求（1 个 `content-manifest.json` + 1041 个 `.md`），累计下载约 4.5 MB；1041 份 frontmatter YAML 在主线程里串行解析；BFS 深度 + DFS 子树分类全部在浏览器侧跑一遍。1080p 桌面 Chrome 冷启动 18–25 s，弱网手机经常 60 s+，且容易触发"页面无响应"。
2. **手机跑 Euler 必卡** — 即使图加载完，1041 节点 + 1059 边的 Euler 力导引布局（`O(V²)`/iter，约 200 iter）在 iPhone 中端机上要 25–40 s，期间无法拖拽/缩放/点击，体验等同于"页面死了"。
3. **兜底缺失** — 一旦 prebuilt 文件失效（404 / JSON 损坏 / CDN 缓存陈旧），没有 fallback 路径，应用直接白屏。

## 二、决策（Decision）

### 决策 A：构建期生成 `public/graph-data.json`

把"1041 份 .md → frontmatter 解析 → BFS/DFS 计算 → GraphData"全部下沉到 `scripts/build-content.ts`，在 Vite build hook 里跑一次，产物写到 `public/graph-data.json`。浏览器只 `fetch` 这一个文件，零解析、零计算。

关键字段（对齐 `src/core/graph.ts` 的 `NodeData`）：

```typescript
{
  id, label, rel,                       // 基础
  fill, stroke, shape,                  // OWL2 语义层
  shortSummary, fullSummary, summary,   // 摘要（含 short/full 嵌套解析）
  location, tags,                       // 位置 + 标签
  edges_out,                            // 出边（保留原始语义供 tour/debug 用）
  depth,                                // ← BFS 在 build 时算好
  subtreeRoot,                          // ← DFS 在 build 时算好
  weight,                               // ← degree 在 build 时算好
}
```

构建脚本核心循环：
1. 遍历 `public/content/**/*.md`，解析 frontmatter
2. 边去重（source+target+type 唯一键）
3. 叶子起点反 BFS（`source → parent` 方向）算 `depth`
4. 找 instance_of 入度 ≥ 1 的 classifier，DFS 标记子树算 `subtreeRoot`
5. 出入度之和算 `weight`
6. 一次性写 `public/graph-data.json`（约 1.27 MB / 800 KB gzip）

### 决策 B：新增 `loadGraph()` 自动 fallback

```typescript
// src/core/prebuilt-loader.ts
export async function loadGraph(onProgress?): Promise<{
  graph: BuildResult;
  files: Record<string, string>;   // 空当 prebuilt 成功
  usedPrebuilt: boolean;
}>
```

行为：
1. 先 `fetch /graph-data.json`，成功 → 直接 `buildGraphFromPrebuilt()`，返回 `usedPrebuilt: true`
2. 失败（404 / 解析错 / 缺字段）→ fallback 走 `loadContentStreaming()` 流式拉 1041 份 .md，返回 `usedPrebuilt: false` + 完整 `files`

`GraphManager` 新增 `initWithPrebuilt(prebuilt)` 走快路径，老的 `addFiles()` 路径保留作为 fallback 的入口。两条路径汇合在 `initGraphFromManager()`（已重构签名兼容两种来源）。

### 决策 C：Euler 跑不跑由设备能力决定

新增 `src/core/device-capability.ts`，读 `navigator.hardwareConcurrency`、`navigator.deviceMemory`、`navigator.connection.effectiveType`、`navigator.connection.saveData` 四个信号。

判定规则（保守）：**2 个或以上强信号指向"慢设备"才跳过 Euler**。单个信号可能骗人——比如 8 核手机热降频会剩 2 核，但单独一个 `slowCores` 不够格 skip。

```typescript
const slowSignals = [
  concurrency <= 4,             // slowCores
  deviceMemory < 4,             // slowMemory（API 会下取整）
  effectiveType === '2g'/'slow-2g',  // slowNetwork
  saveData,                     // dataSaver
].filter(Boolean).length;

const shouldRunEuler = slowSignals < 2;
```

### 决策 D：Euler 硬超时 60 s

```typescript
// src/ui/main.ts
const EULER_HARD_TIMEOUT_MS = 60_000;
```

`finishStreamingLayout()` 启动后挂一个 `setTimeout(60s)`：
- 正常收敛 → `onLayoutStop` 回调里 `clearTimeout` + `waitForGraphToSettle()`（再 60 s 内部上限兜底）
- 超时 → `renderer.getCurrentLayoutInstance().stop()` 强制停止布局，`layoutstop` 自动触发完成回调，节点冻结在当前位置

双重兜底：60 s 硬超时（用户最长等的"大爆炸"时间）+ 慢设备直接 skip Euler（halo 位置直接当最终位置）。

## 三、不选方案

### 不选 A：正文 body 走按需懒加载

原本候选方案——首次只加载 graph-data.json + 摘要，点击节点再 fetch 单个 .md 解析正文。

- ❌ **违反用户诉求**："要保证点击节点流畅"。点开详情面板时多一次 50–300 KB 网络往返 + 一次 YAML 解析，主观感受从"瞬开"变"顿了 200 ms"
- ❌ 节点面板的渲染管线本来就复杂，加异步会让 loading 状态机变难
- ❌ graph-data.json 已经把 80% 用户关心的 metadata（id / label / fill / summary / location / tags）都带上了，body 反而是最不常用的字段

### 不选 B：保留 1041 个 md 并发 fetch，只改解析方式

只把 frontmatter 解析改成流式/YAML 缓存，不引入预生成。

- ❌ 网络请求数没减（1042 → 1042），首次网络时间没省
- ❌ BFS/DFS 还是要算一遍，只是解析快一点
- ❌ 治标不治本，弱网手机仍然 60 s+

### 不选 C：设备能力用 single signal 判定

`detectDeviceCapability()` 用单条信号（如只看 `hardwareConcurrency <= 4`）就 skip。

- ❌ 单信号误判率太高：现代手机 8 核但热降频到 2 核、桌面机只有 4 核但有 GPU 加速、`deviceMemory` API 下取整（3.5 GB 报 3）等
- ❌ 桌面端偶发 `cores=4` 也常见，单信号会误跳过

### 不选 D：硬超时 10 s

- ❌ 1080p 桌面 Chrome 上 1041 节点 euler 平均收敛 4–8 s，但峰值能到 12 s。10 s 上限太紧，会让正常用户体验到"突然停住"
- ❌ 用户明确改回 60 s（见本次变更的 commit）

## 四、后果（Consequences）

### 正面

- ✅ **首屏时间**：1080p 桌面 Chrome 18–25 s → 2–4 s（提升 5–8 倍）
- ✅ **首屏下载量**：~4.5 MB → ~1.3 MB（graph-data.json）+ 0 MB（其他）
- ✅ **手机可用性**：iPhone 中端机不再卡死——慢设备直接 skip Euler，halo 位置就是终态；正常设备 60 s 兜底
- ✅ **fallback 完备**：prebuilt 失效自动降级到 md 流式路径，不会白屏
- ✅ **节点点击瞬开**：body 不再按需加载，详情面板无需等待

### 负面 / 风险

- ⚠️ **build 时长增加**：Vite build 从 ~1 s 涨到 ~6 s（构建脚本遍历 1041 个文件 + BFS/DFS）。可在 CI 加缓存缓解
- ⚠️ **graph-data.json 体积**：1.27 MB，未压缩。对内网部署没事，对公网仍可接受（gzip 后 800 KB）
- ⚠️ **prebuilt 内容陈旧**：开发者改了 .md 但忘了 build，`graph-data.json` 还是旧的。需要在 dev server 加 watch 触发重新生成（待办）
- ⚠️ **deviceMemory / effectiveType 不是所有浏览器都支持**：Chrome / Edge 有，Safari/Firefox 缺失——缺失时 fallback 到 4 cores / 4 GB / 4g 假设，对桌面端偏宽松、对低端机偏宽松（不会误 skip，是合理的悲观默认）
- ⚠️ **Euler 60 s 上限下，手机偶尔仍然要等满 60 s** 才进 fallback。后续可考虑：前 5 s 监测帧率，连续低于 30 fps 就提前 abort（待办）
