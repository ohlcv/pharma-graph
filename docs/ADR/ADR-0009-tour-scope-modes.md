# ADR-0009: 漫游范围模式 —— 单选子树与筛选集合

**日期**: 2026-10-03  
**状态**: 已实现  
**决策者**: AI Assistant + 用户

---

## 背景问题

漫游（Tour）是知识图谱的核心复习功能：用户点击「开始漫游」后，系统按选定顺序逐个
高亮并居中节点，形成一轮循环。

最初漫游只有一个范围维度——**选中节点的子树**（ADR-0003 / ADR-0006 确立的
"universe 边界"）。用户先点选一个节点，再点漫游，就在该节点的整棵子树内循环。

但这个模型有一个缺口：**侧边栏的筛选功能**（按药物分类 / 作用特点 / 边关系筛选出
一批节点）只是"看一眼"——筛选出的高亮节点无法直接进入漫游。用户必须先在这批节点
里**手动点选一个**，再点漫游，才会退化成走那一个节点的子树，与"想复习整个筛选结果"
的意图不符。

**核心痛点**：

- 用户筛选出"所有口诀节点"，想逐个过一遍 → 做不到，只能单选后走单选节点的子树
- 用户筛选出"所有等价边涉及的节点"，想逐个看 → 做不到
- 单选节点与侧边栏筛选互不清除，图上可能同时存在"选中节点 + 筛选高亮"两套状态，
  漫游范围不明确

---

## 决策

### 一、漫游范围 = 两种互斥的「选择模式」

把"用户想漫游什么"统一抽象为两种**互斥**的选择模式，漫游范围由当前模式决定：

| 模式 | 触发方式 | 图上表现 | 漫游范围 |
| ---- | -------- | -------- | -------- |
| **单选模式** | 点击单个节点 | 选中节点加 `.selected-node`，邻居高亮 | 选中节点的整棵子树 |
| **筛选模式** | 点击侧边栏分类 / 边关系 | 筛选命中节点整体高亮，无选中节点 | 整个筛选集合 |

两种模式**互斥**：

- 点击节点 → 清除筛选激活态（回到单选模式）
- 点击侧边栏筛选 → 清除选中节点（回到筛选模式）

互斥保证漫游范围在任何时刻都只有一个来源，不会出现"既选了节点又筛了一批"的歧义。

### 二、筛选模式的范围来源

筛选模式的漫游集合直接来自**侧边栏的激活筛选**：

- **分类筛选**（药物分类 / 作用特点等 fill 类）→ 该类别下的全部节点
- **边关系筛选**（等价 / 互斥 / 层级等）→ 该边类型连接的全部端点节点

注意：范围读取的是**筛选器的激活状态**，而不是图上的高亮 class。原因是鼠标单击
节点时，其邻居也会被临时高亮（浏览行为），如果直接读高亮集合，会把"邻居"误卷进
漫游。只有侧边栏筛选是明确的"批量选择意图"，才作为漫游范围。

### 三、单模式下漫游的起始节点

- 单选模式：从选中的节点开始（原有行为，ADR-0006）
- 筛选模式：从筛选集合中取一个代表节点作为起始点（集合顺序的首个），
  但遍历范围是**整个集合**，起始点本身没有特殊语义

---

## 与其他漫游机制的关系

本次决策不改变已有的三个漫游维度，只是**新增一个范围来源**：

| 维度 | 机制 | 说明 |
| ---- | ---- | ---- |
| **范围**（本次扩展） | 单选子树 ↔ 筛选集合 | 决定"走哪些节点" |
| **顺序** | 策略（教材 DFS / 层级拓扑） + 模式（顺序 / 倒序 / 随机） | 决定"先走哪个" |
| **深度** | 5 档过滤（ADR-0005）+ 自动升档（ADR-0006） | 决定"同一范围内是否跳过某些节点" |

筛选集合进入漫游后，仍受深度档位过滤：例如筛选出全部口诀节点、但档位在 L1（仅结构），
则口诀节点会被过滤掉——档位过滤始终是最后的统一闸门。

---

## 替代方案

### 方案 A：直接读图上高亮 class（未采用）

漫游范围 = 所有 `.highlighted` 节点。

否决理由：

- 鼠标单击节点时邻居也会被高亮，会把"浏览邻居"误当"批量选择"，漫游范围失控
- 无法区分"筛选高亮"与"浏览高亮"，行为不可预测

### 方案 B：筛选与单选叠加取并集（未采用）

漫游范围 = 选中子树 ∪ 筛选集合。

否决理由：

- 两种意图混合，用户难以预期漫游到底走哪些节点
- 违反"单选与筛选互斥"的直观心智模型（用户已确认：切换时应互相清除）

---

## 后果

**正面**：

- 筛选从"看一眼"升级为"可以复习"——筛选结果可以直接进入漫游
- 单选与筛选的状态语义清晰，互斥保证漫游范围无歧义
- 现有单选子树行为完全不变，无回归

**需注意**：

- 筛选集合可能跨章节甚至跨体系（如"全部口诀"同时包含药二与生存集合的口诀），
  漫游会全部走一遍。如需限定单体系，可后续增加"按当前体系过滤"选项
- 筛选模式漫游时，`universe` 边界由筛选集合本身构成，不再做子树 BFS——
  集合外的节点（即使与集合内节点有层级关系）不会被包含

---

## 后续优化建议

1. **体系限定**：筛选模式下可选择"仅当前体系"，把跨体系筛选收敛到单一体系内漫游
2. **筛选集合排序**：目前起始节点取集合首个元素，可提供按位置 / 章节 / fill 排序
3. **搜索结果的漫游**：搜索命中了一批节点（也是高亮），可复用同一机制支持"漫游搜索结果"
