# ADR-0010: iOS 息屏连续朗读 —— 本地语音合成 + 媒体播放

**日期**: 2026-10-18
**状态**: 已决策（待实现；前置真机验证未完成）
**决策者**: AI Assistant + 用户

---

## 一、现状

### 1.1 漫游朗读现在怎么工作

漫游（Tour）是本项目核心复习功能。开启朗读后，系统逐个节点把内容念出来，念什么由
用户在朗读设置面板勾选（标题 / 关联 / 标签 / 摘要 / 正文），速率、是否"等这一步读完
再走下一步"、播后停顿也都在同一面板调整，设置持久化在浏览器本地存储。

实体文件是 `src/ui/speech.ts`：它调用的是**浏览器/操作系统提供的语音合成能力**
（Web Speech API），也就是"借用系统的一副嗓子"——所以不需要下载任何东西、也不花钱。

漫游引擎 `src/core/tour.ts` 与朗读是**解耦**的：引擎通过一个"等待朗读结束"的适配器
与语音层交互，引擎自身不依赖任何语音模块，适配器由 UI 层在启动时注入
（`waitForSpeech` / `waitForSpeechEnd` / `postSpeechDelayMs` 三个接口，见该文件内
`TourOptions` 与 `setWaitForSpeechEnd`）。这个信号决定"下一步是否等当前这句读完"。

### 1.2 播放通道现状

项目已有**一个媒体播放通道**：背景音乐播放器 `src/ui/music-player.ts` + `index.html`
里的一个 `audio` 元素，播放 `public/audio/` 下的 mp3，循环、按播完事件切下一首。

### 1.3 部署现状

纯静态站点（Vercel 构建产物目录，无任何服务端组件）；根目录仅有 `vercel.json` 做静态
托管配置；仓库体积约 17 MB。

## 二、问题

### 2.1 用户目标

用户希望在 **iPhone Safari** 上戴耳机、**锁屏后继续听漫游朗读**（省电、不占手）。
当前行为是：亮屏正常，一息屏朗读就停。

### 2.2 根因（平台限制，非本项目缺陷）

1. **锁屏时 iOS 挂起整个网页**（脚本执行被暂停、后台定时器被延迟）。
2. **系统语音合成拿不到后台播放许可**：它不是媒体播放，锁屏即被取消。即使页面当时
   已有别的音频在播、音频会话是活跃的，系统语音合成在 iOS 上**依然**会在锁屏瞬间
   暂停；这一点在原生应用层面已被实测证实（见文末证据），Web 层只会更差。
3. **锁屏后无法继续合成新语音**：合成需要脚本与 CPU 持续工作，而锁屏后两者都不在。

### 2.3 结论性推论

唯一可行方向：**把"朗读"从"现场合成"变成"音频播放"**。因为媒体元素在 iOS 上
默认就属于"播放"类音频会话，锁屏后系统允许其继续播放——这正是所有听书/音乐类应用
能息屏播放的原因。由此得到本决策。

被否掉的两条"就地解决"捷径，理由见第五节。

## 三、决策

### 3.1 总体结构（三层）

| 层 | 做什么 | 说明 |
| --- | --- | --- |
| **朗读供给层** | 在**设备本地**用一份开源中文神经语音模型，把朗读文本合成为音频片段 | 不依赖任何服务端、不调用付费接口 |
| **播放层** | 用一个常驻媒体元素播放这些片段，承担 iOS 后台/锁屏的全部适配 | 与背景音乐共用 iOS 音频通道 |
| **协调层** | 漫游引擎 ↔ 朗读层的适配：把"等这句读完"的语义从"合成结束"改为"音频段播完"；启动/停止预热 | 引擎侧接口已具备，改动很小 |

系统语音合成（现有实现）**保留**为"亮屏实时朗读"通道；两条通道可切换——桌面端与
Android 上系统合成更省事、零下载。二者不是替换关系。

### 3.2 必须遵守的硬约束（来自平台实测经验）

1. **播放元素永不"自然播完"**：音频文件自然播放到结尾且没有其他声音在播时，
   系统会关闭该页面的音频会话；在后台，iOS 不允许重新打开。暂停与拖动进度条不会
   关闭会话——**只有自然播完会**。因此采用"循环播放 + 检测回绕"来切段。
2. **切段必须在媒体事件回调内完成**，不能靠定时器（后台定时器会被延迟）。
3. **锁屏控制按钮需在每次开始播放时重新注册**；否则锁屏只显示"快退/快进"，
   不显示"上一节/下一节"。
4. **提前备好下一段音频**，避免切段处出现空隙。
5. **后台不做重计算**：合成只能在亮屏时进行。

### 3.3 用户可见的流程

1. 用户开启「息屏收听」→（首次）提示需下载语音包（数十 MB）→ 进度条 → 存入浏览器。
2. 开始漫游后，页面在亮屏期间按**即将要走的顺序**预先生成并缓存音频。
3. 用户锁屏 → 耳机里连续播放；锁屏界面提供上一节 / 下一节控制。
4. 解锁回到页面，漫游继续从当前节点往下走。

**关键约束（要如实告知用户）**：锁屏后可听时长 = 锁屏前已预热的时长。例如选择
"预热 40 分钟"，锁屏后大约能听 40 分钟。

预热顺序是**确定的**，不是猜测：漫游序列在启动漫游时就已一次性算好
（`src/core/tour.ts` 中的预计算序列），因此预热可以严格按真实顺序进行。

### 3.4 明确排除的做法

- 不引入服务端组件，不使用任何付费语音接口，不产生订阅/调用费用。
- 不把音频资产提交进仓库（组合爆炸与部署体积上限均不允许）。
- 不使用"静音音频保活"一类依赖未公开行为的手段。

## 五、替代方案（未采用）

### 方案 A：静音音频保活 + 继续使用系统语音合成（否决）

思路是循环播放一条近似无声的音频，吊住音频会话，让系统语音合成得以继续。否决理由：

- **平台层已证伪**：原生应用在"后台音频权限 + 活跃音频会话 + 常驻静音循环"三项
  全满足的情况下，系统语音合成依然在锁屏瞬间暂停（见文末证据）。
- **会破坏后续可用性**：iOS 上系统语音合成在网页进入后台时中断后，往往需要刷新页面
  才能恢复——解锁回来会变成"没声音且要刷新"。
- 副作用：锁屏会冒出一条针对静音文件的假媒体控制条，与背景音乐控制冲突。

### 方案 B：服务端实时合成（否决，依用户约束）

理想上是"随时锁屏随时听"的唯一无损路线，但需要新增服务器、保管密钥、按字数付费、
依赖网络，且"锁屏后继续取新音频"在 Web 上无先例。与"不新增服务器、不产生额外费用"
的约束直接冲突。

### 方案 C：构建期全量预渲染音频资产（否决）

朗读文本是"节点 × 选中的字段组合 × 速率 × 摘要模式"的笛卡尔积，无法穷举；
且整库预渲染的音频体积远超部署上限（本仓库静态上传上限 100 MB，当前已用约 17 MB）。

### 方案 D：一轮漫游合成单条长音频（不采用，留作后续）

后台播放最稳（单文件、无需切段），但与"随时改字段、随时暂停跳步"冲突。
不作为主线，保留为第七节的后续优化项。

### 方案 E：维持现状（不满足需求）

## 六、已知风险与未验证前提

### 6.1 未验证前提（决定方案成立与否，须真机实测）

1. **锁屏后媒体元素能否连续切段播放** —— 整个方案的地基，无先例。
2. **本地合成在目标机型上的速度** —— 决定"预热 N 分钟音频需要亮屏多少秒"，
   进而决定用户能否"无感预热"。
3. **本地生成的音频片段（本地对象地址）与网络音频在后台行为是否一致**。
4. **模型文件能否从公共模型库直接跨域获取**（否则需改分发路径）。

### 6.2 风险

- **系统级清理**：Safari 的跟踪防护规定，网站 7 天无用户交互即删除该站的脚本可写
  存储（模型与音频缓存因此可能被清掉，需重新下载）。频繁使用者无感，低频使用者有感。
- **已知 WebKit 缺陷**：整页音频可能彻底失效（跨刷新存活，需重启浏览器）；
  加进主屏的独立网络应用在旧版 iOS 上存在"播完不续播"；暂停超过约 30 秒会使音频
  失效直到回到前台。
- **用户流量**：每个新用户首次需下载数十 MB 语音模型。
- **与背景音乐共用音频通道**：两种"播放"类音频同时存在时的混音/压低策略需实测。
- **首次体验**：新用户会看到"需要下载语音包"这一步。

## 七、后果

**正面**：

- 锁屏后可继续朗读，满足"戴耳机听、省电"的原始诉求。
- 不新增服务器、不产生费用、模型下载后可离线使用。
- 朗读与播放解耦，播放通道可复用于其他朗读场景；漫游引擎侧几乎不动。

**需接受**：

- 一次性模型下载（数十 MB），且可能被系统清理后重下。
- 息屏可听时长受预热时长限制。
- 新增"设备端合成 + 音频缓存"一块复杂度，且更直接地暴露在 iOS 媒体后台行为的
  缺陷面之上（见 6.2）。

---

## 八、后续优化建议

1. **无感预热**：打开页面即在后台预热，让用户感受不到"准备"这一步。
2. **单条长音频形态**：为"整轮安静听一遍"的场景提供章节化长音频（方案 D）。
3. **音色/语速可选**：多语音模型切换。
4. **与背景音乐联动**：朗读时自动压低背景音乐。
5. **供给层可插拔**：若将来愿意引入服务端，把预热接到云端合成即可，**播放层不用改**。

## 附：外部证据

本决策依赖若干平台行为，均**非本项目代码问题**，来源如下（按结论对应）：

- 锁屏后系统语音合成被暂停（原生应用在后台音频权限与会话均满足的情况下依然如此）：
  Apple Developer Forums — "AVSpeechSynthesizer audio pauses when the device locks,
  despite an active background AVAudioSession"
- 网页进入后台后系统语音合成失效、且需刷新页面才能恢复：
  WebOutLoud — "The State of Speech Synthesis in Safari"
- 锁屏时网页脚本被挂起、音频播完事件与续播行为：
  WebKit Bug 173332 — "HTML5 audio .ended event not fired when app in background or
  phone screen is off"
- 媒体元素默认属于"播放"类音频会话：MDN — Audio Session API
- "自然播完会关闭音频会话 / 循环播放 + 回绕切段 / 锁屏按钮需重新注册"：
  amsyn.org — "Getting my iPhone music app to keep playing on the lock screen"
- 7 天无用户交互删除脚本可写存储：WebKit — Tracking Prevention
- 静态上传体积上限：Vercel — Limits
