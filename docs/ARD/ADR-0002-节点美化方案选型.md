# ADR-0002: 节点美化方案选型（flow/glow 强调节点的视觉实现）

| 字段 | 值 |
|---|---|
| **状态** | Accepted · Implemented |
| **日期** | 2026-09-08 |
| **决策者** | 项目所有者 |
| **影响范围** | `src/core/renderer.ts`（stylesheet、`RendererOptions`、`startFlowAnimations`、`destroy`）；git commits `2d8b917`、`dcc8022`、`cf6db4b` |
| **替代方案** | A: overlay + border-width；C: WebGL 渲染器（opt-in）；D: SVG `background-image`（已淘汰） |

## 一、背景（Context）

### 1.1 需求

药学图谱里有两类节点需要**额外强调**，让用户一眼看出重点：

| 节点 | frontmatter 字段 | 期望视觉 |
|---|---|---|
| `第一节 镇静催眠药`（重点药分类） | `stroke: flow` | 边框虚线"流动"——暗示该分类是活跃学习的入口 |
| `执业药师考试体系`（考试整体结构） | `stroke: glow` | 边框外有"光晕"——暗示这是顶层骨架 |

### 1.2 cytoscape canvas 的先天限制

cytoscape 默认 canvas 后端（不像 SVG / DOM）**不支持**：
- ❌ CSS `@keyframes` 动画
- ❌ CSS `box-shadow`
- ❌ CSS `filter: drop-shadow()`

所以"真正的光晕/流光"必须用 cytoscape 自己的样式系统实现，不是写 CSS。

### 1.3 历史决策回顾（已废）

本任务经历了 4 次迭代，前 3 种实现都不对：

| 迭代 | 实现 | 问题 |
|---|---|---|
| 第 1 次 | `overlay-color` + `overlay-padding` 做光晕；`overlay-opacity` 做流光暗示 | overlay 按节点 bounding box（矩形）画，不按 shape 描边；椭圆/八边形/星形节点外面罩了个矩形光晕 |
| 第 2 次 | `border-style: double` 做光晕 | cytoscape canvas 的 double 间隙按 `border-width` 比例计算；width=3 时双线几乎贴在一起像粗线，width=5 时看着是粗线而非双层光晕 |
| 第 3 次 | 加大 `border-width: 4` 让 `border-style: dashed` 的 dash 段变长 | cytoscape canvas 的 dash 段长度也按 border-width 比例算，width=4 时 dash 段 ~3px 看着像点状虚线，不像"流光" |

> 共同根因：**cytoscape canvas 渲染器把 dash 段长、double 间隙当作 border-width 的派生量**——用户没办法独立控制。

## 二、决策（Decision）

**采用 cytoscape 官方支持的两种样式属性组合**：

1. **`flow` 强调节点**：用 `border-dash-pattern` 显式控制虚线段长 + `border-dash-offset` 配合 `requestAnimationFrame` 循环——做出真正的循环流光动画。
2. **`glow` 强调节点**：用 cytoscape 原生的 `outline-*` 系列属性做光晕外圈（独立于 border 的轮廓层），严格按节点 shape 描边。

同时**加 opt-in WebGL 渲染器配置**作为未来性能扩展路径。

### 2.1 flow 节点的样式

```ts
{
  selector: 'node[stroke = "flow"]',
  style: {
    'border-color': '#3b82f6',
    'border-width': 2,
    'border-style': 'dashed',
    'border-dash-pattern': [6, 4],  // 6px dash + 4px gap
    'border-dash-offset': 0,         // rAF 循环修改这个值
    'transition-property': 'border-color',
    'transition-duration': 300,
  },
}
```

**动画机制**（`src/core/renderer.ts:startFlowAnimations`）：

```ts
private startFlowAnimations(): void {
  this.stopFlowAnimations();  // 防止 render() 多次调用时 rAF 叠加
  const flowNodes = this.cy.nodes('[stroke = "flow"]');
  if (flowNodes.length === 0) return;
  const dashSum = 10;  // 6+4
  let offset = 0;
  const tick = () => {
    offset = (offset - 1 + dashSum) % dashSum;  // 倒序流动
    flowNodes.style('border-dash-offset', offset);
    this.flowRafId = requestAnimationFrame(tick);
  };
  this.flowRafId = requestAnimationFrame(tick);
}
```

### 2.2 glow 节点的样式

```ts
{
  selector: 'node[stroke = "glow"]',
  style: {
    'border-color': '#3b82f6',
    'border-width': 2,
    'border-style': 'solid',
    'outline-color': '#3b82f6',
    'outline-width': 4,
    'outline-style': 'solid',
    'outline-opacity': 0.4,
    'outline-offset': 3,
    'transition-property': 'border-color, outline-color, outline-opacity, outline-width',
    'transition-duration': 300,
  },
}
```

### 2.3 子树颜色覆盖

`flow`/`glow` 节点的 `border-color` 和 `outline-color` 由 subtreeRoot 颜色规则统一覆盖：

```ts
{
  selector: 'node[stroke = "glow"][subtreeRoot = "root-id"]',
  style: {
    'border-color': '#3b82f6',     // 节点本身边框色
    'outline-color': '#3b82f6',    // 光晕色（独立属性）
  },
}
```

### 2.4 生命周期管理

- **rAF 句柄**：存到 `Renderer.flowRafId`，destroy 时调用 `cancelAnimationFrame`
- **多次 render()**：每次 render() 后重新调用 `startFlowAnimations()`（元素重建，旧动画失效）
- **位置不变**：用 rAF 直接改 style，**不**用 `ele.animation()`（后者类型要求 position / renderedPosition，会强制动画节点位置造成抖动）

### 2.5 opt-in WebGL 渲染器

```ts
new Renderer({
  container,
  data,
  webgl: true,  // 默认 false；节点 > 2000 时建议开启
});
```

```ts
renderer: {
  name: 'canvas',
  ...(this.useWebgl ? { webgl: true } : {}),
}
```

## 三、备选方案对比（Alternatives Considered）

### 方案 A：overlay + border-width 控制 dash 段（已废）

```ts
'border-width': 3,                  // 间接控制 dash 段
'overlay-color': '#3b82f6',         // overlay 做光晕
'overlay-padding': 4,
'overlay-opacity': 0.5,
```

| 维度 | 评分 | 说明 |
|---|---|---|
| 真实流光 | ❌ | dash 段长由 border-width 派生，无法独立控制 |
| 真实光晕 | ❌ | overlay 按矩形 bounding box 画，不按 shape |
| 按 shape 描边 | ❌ | 椭圆/八边形外面罩了矩形 |
| 性能 | ✅ | overlay 缓存 |
| 官方推荐 | ❌ | 文档原话 "Avoid many node overlays" |

### 方案 B（采用）：dash-offset rAF 动画 + outline 光晕

| 维度 | 评分 | 说明 |
|---|---|---|
| 真实流光 | ✅ | `border-dash-offset` 是文档原话 "useful for creating edge animations" 的标准做法 |
| 真实光晕 | ✅ | outline 是 cytoscape 原生"轮廓层"，独立于 border，按 shape 描边 |
| 按 shape 描边 | ✅ | outline 严格按节点 shape 描边 |
| 性能 (689 节点) | ✅ | rAF 60fps，只改 ~几十个 flow 节点的 dash-offset |
| 官方推荐 | ✅ | 文档明确支持 |

### 方案 C：WebGL 渲染器（opt-in，未默认开启）

```ts
renderer: { name: 'canvas', webgl: true }
```

| 维度 | 评分 | 说明 |
|---|---|---|
| 真实流光 | ✅ | WebGL 后端用 sprite sheet 复用 canvas 节点样式，**视觉效果与方案 B 完全相同** |
| 真实光晕 | ✅ | 同上 |
| 性能 | ✅✅ | GPU 加速，大图（>2000 节点）优势明显 |
| 官方推荐 | ⚠️ 实验性 | 代码已存在 1.5+ 年（v3.31 → 当前 v3.34.3，2026-09-07），但官方仍未宣布 stable |

### 方案 D：SVG `background-image`（已淘汰）

```ts
'background-image': function(ele) {
  return 'data:image/svg+xml;utf8,' + encodeURIComponent(makeGlowSvg(ele));
}
```

| 维度 | 评分 | 说明 |
|---|---|---|
| 真实流光/光晕 | ✅✅ | SVG 可做任意复杂动画和多重光晕 |
| 性能 | ❌ | 689 节点每个挂一个 SVG 会显著拖慢；cytoscape 不缓存 SVG 背景 |
| 实施复杂度 | 高 | 每个 stroke 写一个 SVG 生成器 |

## 四、加权评分

| 维度 | 权重 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|---|
| 视觉流光/光晕效果 | 30% | 2 | 5 | 5 |
| 性能（689 节点） | 25% | 4 | 4 | 5 |
| 实施风险 | 20% | 4 | 5 | 3 |
| 长期维护成本 | 15% | 4 | 4 | 3 |
| 兼容性（边/复合节点） | 10% | 4 | 5 | 3 |
| **加权总分** | 100% | **3.10** | **4.65** ✅ | **4.10** |

> 评分依据：见第三节"备选方案对比"。
>
> **方案 C 的视觉效果与方案 B 完全相同**——这是关键洞察。WebGL 后端复用 canvas sprite sheet，**所有 stroke / border / outline / dash-offset 动画都和方案 B 一致**。WebGL 只带来性能提升（GPU 加速），不带来更好的视觉效果。在 689 节点规模下 canvas 完全够用，所以方案 B 综合胜出。

## 五、后果（Consequences）

### 5.1 正面

- **视觉满分**：dash 真的"流动"，outline 真的按 shape 描边为光晕外圈
- **零实施风险**：所有属性都是 cytoscape 官方文档明确支持的
- **性能良好**：rAF 60fps，仅修改 ~几十个节点的 dash-offset；outline 由 cytoscape 缓存
- **WebGL 扩展路径**：未来节点规模超 2000 时，只需传 `{ webgl: true }` 一键切换，不需要改 stylesheet

### 5.2 负面与代价

- **rAF 一直跑**：即使所有 flow 节点都被隐藏（深度筛选），rAF 仍然每帧执行 `flowNodes.style(...)`。cytoscape 会增量更新——开销可忽略，但不彻底停止会浪费 CPU。
- **WebGL 仍未默认开启**：因为 v3.31 至今实验性 + 689 节点规模不需要；如果未来 WebGL 宣布 stable，可考虑默认开启

### 5.3 后续改进（2026-09-09）

在"方案 B 基础上进一步美化"，具体改进如下：

#### 5.3.1 Flow 增强：三层 ghost 呼吸光

原有方案只有 dashed 虚线，视觉上像"虚线在抖动"而非"有光在流动"。
改进方案在 dashed 边框**之下**增加三层 ghost 叠加：

| 层 | ghost-offset | ghost-opacity | 作用 |
|---|---|---|---|
| 内层 | 0 | 0.22 | 节点本体的微微发光感 |
| 外层（Layer 2） | 12 | 0.15 | 明显晕染出去 |
| 最外层（Layer 3） | 20 | 0.08 | 淡淡的模糊边缘 |

ghost 是 cytoscape 唯一的"外发光"方案（shadow 2017 年已被官方移除）。
多层 ghost 叠加（opacity 递减）模拟模糊光晕，弥补 outline 无法 blur 的遗憾。

#### 5.3.2 Glow 增强：五层叠加 + 呼吸脉冲

原有方案 outline 是单层实线，视觉上像"双层边框"而非"发光"。
改进方案五层叠加：

| 层 | 属性 | 值 | 作用 |
|---|---|---|---|
| 1 | border（solid） | width=2 | 节点本体清晰轮廓 |
| 2 | outline | offset=4, opacity=0.35, width=6 | 近处有清晰边界 |
| 3 | ghost 内层 | offset=0, opacity=0.28 | 明亮核心发光 |
| 4 | ghost 外层 | offset=10, opacity=0.18 | 晕染出去 |
| 5 | ghost 最外 | offset=18, opacity=0.10 | 模糊边缘 |

同时新增 **glow 呼吸脉冲动画**（rAF 正弦曲线驱动）：
- `ghost-opacity`: 0.18 ↔ 0.38（周期 ≈ 2.4s）
- `outline-opacity`: 0.25 ↔ 0.45（同步）
- `outline-width`: 5 ↔ 8（"光晕在胀缩"感）

#### 5.3.3 Flow 动画改进

| 改进项 | 原方案 | 新方案 |
|---|---|---|
| 速度 | 每帧 offset -1（与 dt 无关，tab 切回后跳帧） | 用 `timestamp` 计算 `dt`，卡帧自动补偿 |
| dash 段长 | [6, 4]（dash 太短，看着像点状虚线） | [10, 5]（10px 长虚线更像"流光"） |
| 周期稳定性 | 依赖帧率（60fps 时 ≈ 1s/周期） | dt 补偿后任意刷新率都稳定 |

### 5.4 未来优化方向

| 方向 | 收益 | 实施成本 |
|---|---|---|
| 调流光速度（当前 dash-offset dt/16） | 视觉调优 | 改 1 行 |
| 调呼吸周期（当前 glowBreathPeriod=2400ms） | 视觉调优 | 改 1 行 |
| glow outline-width 调大（如 8↔12） | 更强的发光感 | 改 2 行 |
| 差异化配色：flow 用冷蓝紫，glow 用暖粉橙 | 视觉调优 | subtreeColorMap 调色 |
| rAF 改 requestIdleCallback | 节省 CPU | 改 5 行，但可能影响流畅度 |
| WebGL 宣布 stable 后默认开启 | 大图性能 | 改 1 行（`webgl: true` 默认） |
