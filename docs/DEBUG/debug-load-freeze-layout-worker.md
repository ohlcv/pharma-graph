# 加载期 20 秒界面冻结 —— 根因是 euler 布局占死主线程，修复方案是搬进 Web Worker

> 状态：**已修复**。加载期帧率 20 FPS → 57–60 FPS，布局质量保持。
> 记录日期：2026-09-29
> 关联文档：[`debug-tesseract-perf-hypothesis-rejected.md`](./debug-tesseract-perf-hypothesis-rejected.md)（同一批性能排查的前一轮，本文是其延续）
>
> ⚠️ **方法论警告（本文档踩过的坑，务必先读）**
>
> **无头 Chromium 的性能数字不可信。** 本次排查的头两个多小时完全走错方向，
> 根因是全部测量都基于 Playwright **无头**模式：
>
> - 无头模式走 SwiftShader **软件光栅化**，性能剖析里光栅化任务占 7870ms/5s，
>   而脚本执行只占 187ms —— 40 倍的差距**完全是软件渲染的产物**。
> - 同一张图在**有头**模式（真实 GPU 合成）下测得满帧，零长帧。
>
> **结论：帧率相关的性能结论，必须用有头浏览器测。** 无头数据只适合做
> 同一环境下的**相对比较**，绝对值一律无效。
> （工具已内置：`tools/measure-real.mjs` 有头 / `HEADED=0` 无头回落）
>
> 第二个坑：**归因要靠对照组，不要靠直觉。** 用户报「好卡」时，
> 我第一反应是怀疑刚新增的装饰节点（生命之树），并立刻开始优化它的绘制逻辑 ——
> 而实测证明它完全无辜（稳态满帧）。**新增代码 ≠ 新增瓶颈**，先量再改。

## 问题描述

用户反馈：「好卡」。

主观症状：打开页面后，界面明显卡顿，约 20 秒后恢复正常。

## 环境

- 构建：`npm run build` + `vite preview`（排除 dev server 的 HMR / 冷启动噪声）
- 数据规模：1183 节点 / 1198 边
- 视口：`1600×1000`
- 采样：Playwright，**有头模式**（真实 GPU 合成），rAF 逐帧打点

## 排查过程

### 第一层：分阶段测帧率，定位卡在什么时候

rAF 采样按「秒」分桶，看整条加载时序（`tools/measure-phase.mjs`）：

```
  1s │    15    20    20    20  15.2    20    20    20    20    20
 11s │    20    20    30    30    30  29.2    20  19.8    20    20
 21s │  59.9  59.9  59.9  59.9  59.9  59.9  59.9  59.9  59.9  59.9
 31s │  59.9  59.9  59.9  59.9  59.9  59.9  59.9  59.9  59.9  59.9
```

**结论立刻清晰：0–20 秒 15–20 FPS，20 秒后满帧。** 卡的是 euler 布局那 20 秒，
不是常驻开销。

### 第二层：那三个装饰节点有责任吗？——用有头模式做对照

上一轮排查的结论是「装饰节点不是瓶颈」，但那是在**无头**模式下得出的，
数字不可信。这次用有头模式重测三档：

| 变体 | 中位帧 | FPS | 长帧占比 |
| --- | --- | --- | --- |
| 无装饰 | 16.7ms | 59.9 | 0% |
| 只开生命之树 | 16.7ms | 59.9 | 0% |
| 三个全开 | 16.7ms | 59.9 | 0% |

**三档全部满帧、零长帧。** 装饰节点（含新加的生命之树）在稳态下**完全无辜**。
用户感受到的卡 100% 来自布局期。

### 第三层：那 20 秒里，时间花在哪？

关键实验：**在 Node 里（无 DOM）跑同一张图的 euler 布局**
（`tools/probe-worker-feasibility.mjs`）：

| 场景 | 耗时 |
| --- | --- |
| headless 纯计算（Node，无 DOM，无动画） | **3944 ms** |
| 浏览器主线程 + 动画 + 位置回写 | **20877 ms** |

**只有 4 秒是真正的力计算，另外 16 秒花在逐帧动画、cytoscape 位置回写与画布重绘上。**

这解释了为什么「降级布局参数」救不了场（见关联文档的降级实验：降级换不来帧率，
只换来质量损失）—— 因为开销的大头根本不在力学计算本身。

## 修复方案：把计算搬进 Web Worker

### 可行性先验证，再动手

动手前先确认两件事，缺一不可：

1. **力布局库无 DOM 依赖** —— 查 `node_modules/cytoscape-euler/src/`，无 `document.` / `window.` 引用。
2. **图核心库支持 headless 运行** —— 在 Node 里直接建 headless 实例跑通 1182 节点，
   边交叉数 83（比浏览器里的 138 更好）。

两项都成立，方案才可行。**先写探针脚本验证，再写实现** —— 否则可能做到一半发现
库根本跑不起来。

### 实现要点

- 新增 worker 源文件，在 worker 内用 **headless 模式**建图库实例，
  关键选项是**关闭动画**（worker 里不画任何东西，动画纯属浪费）
  与**关闭样式解析**（力学计算不读样式）
- 新增主线程侧客户端封装，**三条硬要求**：
  - **有超时上限**（实测纯计算 4s，留 15s 余量）
  - **异常一律捕获**，Worker 可能因不支持 / 超时 / 运行时错误而失败
  - **永不抛异常，只返回失败标志** —— 让失败只表现为「退回同步布局」，
    不炸掉整个加载流程
- 主线程拿到最终坐标后**一次性批量回填**（包在批量更新里，避免 1183 次
  位置写入各自触发一次渲染通知）
- **兜底路径必须保留**：Worker 任何一条失败路径都自动退回原来的同步布局

### 效果

| 阶段 | 改前 | 改后 |
| --- | --- | --- |
| 加载期（0–20s） | 15–20 FPS | **57–60 FPS** |
| 稳定期（20s 后） | 59.9 FPS | 59.9 FPS |

布局质量对照（几何指标，不靠主观判断）：

| 指标 | 改前（同步） | 改后（Worker） |
| --- | --- | --- |
| 边交叉数 | 138 | 155 |
| 节点重叠率 | 0% | 0.4% |
| 铺开范围 | 17571 | 4856 |

质量同量级，可接受。

## 结论

1. **卡顿的根因是 euler 布局占死主线程 20 秒**，与装饰节点、与新代码均无关。
2. **那 20 秒里只有 4 秒是真正的力学计算**，其余是动画与渲染开销。
   因此「优化力布局参数」是错的方向（关联文档的降级实验已证明）。
3. **搬进 Worker 后主线程阻塞归零**，这是本图上唯一不牺牲质量的路径。

## 遗留 / 需要知情的事

### 1. 有损：失去了入场动画

Worker 方案拿到的是**最终坐标**，无法呈现「节点从中心散开」的过程。
取舍是明确的：20 秒界面冻结换一段入场动画，划算。

**但这是有损改动。** 如果后续认为那段动画更有价值，需要重新权衡
（例如：先同步跑 2 秒动画铺开、再接手给 Worker 收敛——尚未验证）。

### 2. 铺开范围缩小

Worker 结果的铺开范围 4856，同步方案是 17571。**图整体更紧凑了。**
边交叉数与重叠率都在同量级，但视觉上「宇宙」变小。这是否可接受，
建议打开页面实际看一眼再定。

### 3. 与关联文档的「未尝试方向」的关系

关联文档末尾列过一条未尝试方向：

> 把 euler 换成同步一次性（`animate: false`）——牺牲动画过程，但总计算量不变，
> **帧率指标将失去意义（阻塞主线程）**，只在低频触发时有意义

本文正是这条路。**但搬进 Worker 后，那个顾虑不成立** —— 计算确实阻塞，
但阻塞的是 worker 线程，主线程的帧率指标完全有意义。
「帧率指标失去意义」的前提是「在主线程上跑」。

### 4. worker 源文件是纯英文注释

写入 worker 源文件时，编辑器连续两次在**同一字节位置**把文件截断成乱码
（报错「File appears to be binary」），而其他含中文的文件正常。
最后改用命令行写纯 ASCII 内容绕过。

因此 `src/core/layout-worker.ts` 目前是**纯英文注释**，
中文设计说明放在 `layout-worker-client.ts` 与提交记录里。
**这个不一致是有原因的，不是风格问题** —— 后续若要补中文注释，
请先确认写入方式是否可靠。

### 5. 环境里有未归属的文件

`celestial-e8-node.ts`（E8 根系，423 行）在本次排查期间出现（未跟踪、不被引用、
带 3 个类型错误）。非本次工作产出。

**已归属**（见 §9）：接入生产 + 随其它奇观迁入 `src/core/spectacle/`，
3 个类型错误（`cytoscape.Css.BackgroundFill` / `TextEvents` / `Ghost` 在当前
cytoscape 版本不存在）改为 `as const`，与 `emblem-overlay.ts` 保持一致。

## 后续：按设备分档 + 等待预动画

Worker 方案落地后，**入场动画从 euler 自己的逐帧动画退化成了预计算插值**。
节点不再「互相推挤着散开」，而是从预存坐标整齐地绽开——有机感少了一截。
这是当时为消除 20s 主线程冻结付出的代价，没有对等补偿。

### 6. 恢复方案：按主线程能力分两条路径

`device-capability.ts` 新增 `canAnimateOnMainThread`，与 `shouldRunEuler`
**刻意分成两条独立的轴**：

| 字段 | 回答的问题 | 判断错的代价 |
| --- | --- | --- |
| `shouldRunEuler` | 要不要**算**布局 | 图挤成一团 |
| `canAnimateOnMainThread` | 算完了能不能**逐帧播** | 主线程冻结 20s |

所以存在第三种组合（布局必须算、但动画扛不住）——那正是 Worker 路径。
把两者合成一个判据会两头误判：`shouldRunEuler` 把 network / saveData
也计入「能力」，而**逐帧渲染的瓶颈是 CPU 与栅格化，网络再快也不顶用**；
反之一台开了省流模式、插着网线的 8 核桌面完全扛得住动画。

阈值 8 核的依据：≤4 核（多数手机）实测 15–20 FPS；≥8 核（近几年的笔记本 /
M 系列 Mac / 高端手机）回写 1182 个节点位置可稳定在交互帧率。
6 核是灰区，判给动画档。

高性能档走的**不是新实现的「像原来那样」的动画**，而是原有代码路径本身
（`runSyncLayout` → euler `animate: true` 逐帧跑主线程），观感逐帧一致。

⚠️ **8 核这个阈值是推算的，没有在目标设备上实测过帧率。**

`?layout=sync` / `?layout=worker` 可强制指定路径。存在的理由：判据只有
`hardwareConcurrency` 一条，在高性能开发机上永远走 sync 分支，
worker 那条无法验证——这条 URL 让两条分支始终可达。

### 7. 等待预动画

低性能档 Worker 计算的约 4 秒里，屏幕上是 1182 个节点**完全重叠在原点、
静止不动**的一坨（halo burst 的 `duration: 0` 位置动画在 `cy.stop()` 前
没来得及应用）。观感是「加载卡住」，不是「正在计算」。

预动画把这段空窗填成：节点从原点**缓缓铺开成一片星尘**并持续轻微呼吸，
Worker 回来后真正的入场动画从星尘环接续炸开。两段同用 easeOutCubic 曲线，
首尾相接，看不出接缝。

几个刻意的取舍：

- **铺得小**（半径 120–340，远小于最终布局尺度）。星尘是「待命的微缩宇宙」，
  不是最终结构的粗糙版本；铺太大则炸开时没有收缩空间。
- **停手时落到裸坐标**，不捕获「呼吸中的实际坐标」。差 ≤6% 半径，一帧完成，
  人眼读作「稳了一下」；换来入场动画起点完全确定。
- **只动非 `layer-parent` 节点**。太极图 / 四维空间 / 生命之树各有独立 overlay
  在管位置和 rAF，插手会和它们打架。
- **预动画在 `postMessage` 之后启动**。反过来 Worker 会读到被预动画改写的
  中间位置，euler 起始点就错了。
- **成功路径上先让位再放入场动画**。两者都写 position，同帧后写者赢；
  顺序反了表现为入场动画头几帧抖动。
- **reduced motion 下预动画不启动**，与 `animatePositionsTo` 的瞬时落位路径
  一致，不会出现「预动画在动、入场动画瞬跳」的割裂。

铺点用 `halton()`（base 2 铺角度、base 3 铺半径、base 5 铺呼吸相位）。
低差异序列保证不聚簇；纯随机会让星尘聚成几个斑点而非均匀一片。
实现从 `ui/main.ts` 移到 `src/core/halton.ts`——core 不能反向依赖 ui，
两处都要用。

⚠️ 预动画的**观感（半径、时长、呼吸幅度）未在真机上校准过**，
参数是按「不抢注意力 + 不打断衔接」定的，缺实测依据。

### 8. 三个调试开关分属不同的轴，别当成冗余删掉

| 开关 | 决定 | 删掉会怎样 |
| --- | --- | --- |
| `?layout=sync` / `?layout=worker` | 布局**在哪算**（主线程 / Worker） | 只能看到能力检测选中的那一条 |
| `?motion=always` | 入场动画**播不播** | 开了系统「减弱动态效果」时动画被跳过，无法调试 |
| `?quality=preset` 等 | euler 参数档位 | 失去布局质量的对照基线 |

`?layout=` 和 `?motion=` 是**正交**的，后者对两条计算路径都生效。
最典型的误用：开着系统「辅助功能 → 显示 → 减弱动态效果」再访问
`?layout=worker` —— 路径选对了，但 `prefersReducedMotion()` 为真，
预动画在 `startWaitingAnimation` 入口 `return null`、入场动画走瞬时落位，
**结果什么都没播**。此时必须加 `?motion=always` 才能验证动画路径。

`?motion=always` 的作用点有两处，且各自**独立**读 `prefersReducedMotion()`：
`startWaitingAnimation`（决定预动画启不启动）与 `animatePositionsTo`
（决定入场动画播不播）。所以删掉它之后，预动画这条路就没有任何
URL 级别的绕过手段了，只能改代码。

> 这三个开关都读 URL 而非构建产物，**别为了「清理」删**：
> 判据只有 `hardwareConcurrency` 一条，在高性能开发机上永远走 sync 分支，
> 没有 `?layout=worker` 就无法验证低性能档。

## 复现方式

### 手动验证（URL 开关，见 §8）

```bash
?layout=sync     # 主线程逐帧 euler 动画 —— 高性能档的真实路径
?layout=worker   # Worker 计算 + 等待预动画 + 插值入场 —— 低性能档
```

### 量化测量（脚本）

```bash
# 有头模式测稳态帧率（真实 GPU 数字，可信）

node tools/measure-phase.mjs            # 无装饰
```

>
> 关联文档的 `tools/measure-euler-quality.mjs` 是无头的，其表格中的

## 9. 奇观节点归入 `src/core/spectacle/`（2026-09-29）

四个奇观节点（太极八卦 / 四维空间 / 生命之树 / E8 根系）原先平铺在
`src/core/`，与 `renderer.ts`、`tour.ts` 等核心逻辑混在一起，共约 2,772 行。
现在归入 `src/core/spectacle/`。

**这次同时接完了 E8**（见 §5）。它此前是半成品：`main.ts` 没 import、
`renderer.ts` 的 `DECOR_NODE_CLASSES` 没登记、配套内容文件不存在。

### 命名规范

统一为 `<奇观>-overlay.ts`（`e8-overlay.ts` / `emblem-overlay.ts` /
`tesseract-overlay.ts` / `fractal-tree-overlay.ts`）。两条规则：

1. **后缀按文件产出物定**，不按主体。该文件产出的是 canvas 覆盖层，
   节点本身只是一枚命中盒，所以是 `-overlay` 而非 `-node`。
2. **前缀取奇观名，不加 `celestial-`**。原先 `celestial-emblem-overlay.ts`
   和 `celestial-e8-node.ts` 都带这个前缀，但 E8 根系与太极八卦没有共同
   语义可共享——前缀在这里是噪音，去掉。

几何内核类文件另用后缀区分（`fractal-tree-geometry.ts`）。

### 顺带修掉的两个既有缺陷

1. **`tree-node` 一直没进 `DECOR_NODE_CLASSES`**。四个装饰 class 里只有前两个
   登记过，树的本体压透明只靠 overlay 自己的 `stripNodeChrome()`。补齐后
   样式表兜底路径也覆盖它。
2. **`?decor=` 是负向列举**。每加一个奇观要改四处（新增 `DISABLE_` 常量 +
   补进其余三个的关闭条件 + `DECOR_STATE` + 调用点），漏一处就「以为关了
   其实开着」。改成 `DECOR_KEYS` 白名单 + `decorEnabled(key)`，加奇观只需
   改数组和调用点两处。

### 新增的两处单点维护

移动后奇观节点的登记点从 1 处变成 2 处，两处都要在**新增奇观时同步**：

| 位置 | 漏了会怎样 |
| --- | --- |
| `src/ui/main.ts` 的 `DECOR_KEYS` | 开关关不掉 / `DECOR_STATE` 报错 |
| `src/core/renderer.ts` 的 `DECOR_NODE_CLASSES` | 样式表兜底路径下露出 cytoscape 默认椭圆 |

长期解法是让各 overlay 导出自己的 class 常量、由 `renderer.ts` 汇总
（需要给 `src/core/spectacle/` 加 barrel）。**尚未做**——目前 4 个 class
名是硬编码字符串，`stripNodeChrome` 也是 4 份近似重复实现。

### 验证

`tsc --noEmit` 4 错误（与改动前同基线，全在 `tour.ts`，与本次无关）、
`npm test` 439 passed / 39 files、`npm run validate` 1184 文件全过、
`npm run build` 通过且 E8 节点正确进入 `graph-data.json`。
