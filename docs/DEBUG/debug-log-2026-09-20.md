# 调试记录 — 2026-09-20

图谱可视化前端（Cytoscape.js + TypeScript，1000+ 节点规模）本次排查与修复的完整记录。涉及文件：`renderer.ts`、`highlight-engine.ts`、`graph-events.ts`、`tour-controller.ts`，新增 `glow-overlay.ts`。

---

## 问题一：点击节点后约 1 秒才有反应

### 现象
点击节点，动画和详情面板要等将近 1 秒才出现。Chrome DevTools 录的 trace 里，每次点击后主线程都有约 0.85 秒的持续 100% 占用。

### 根因 1：漫游条的全图扫描监听器是 O(N²)

`tour-controller.ts` 里有一个"从这里开始"提示的显示逻辑，依赖一个判断当前是否有节点被选中的函数。这个函数每次都要遍历全部节点去查有没有带"已选中"标记的节点——Cytoscape 对这种基于 class 的查询没有索引，是线性扫描。

问题出在触发时机：代码绑定了一个监听器，监听"任意节点的任意 class 发生变化"，一旦触发就重新跑一遍上面那个全图扫描。而点击一个节点，仅仅是高亮流程本身，就会连续产生几百次 class 增删（重置旧的高亮状态、给新节点及其邻居加高亮标记、把其余节点标记为变暗，等等）。每一次 class 变化都触发一次全图扫描，几百次乘以全图扫描，就是这 337 毫秒的由来。这是本次排查中占比最大的单一原因。

### 根因 2：点击也会触发"拖拽模式"的全节点切换

Cytoscape 在检测到"抓取一个节点"和"释放一个节点"时会发出对应事件，而单纯点击（没有实际拖动）也会触发这两个事件，不只是真正拖拽才会。原代码在这两个事件上都会给全部节点加一个"拖拽简化"样式类再摘掉，用来在拖拽时降级渲染细节以提速。结果是：每次点击，不管有没有拖动，都白白多跑两轮全节点的样式类切换。

### 根因 3：高亮/变暗操作里有可以合并的逐条操作

给节点、边加减样式类的几处代码是逐个元素调用的，每调用一次就是一次独立的样式失效和潜在重绘。这类操作可以用集合层面的一次性操作替代，减少调用次数。另外，Cytoscape 提供了"批处理"模式，可以让一系列样式改动只在结束时统一触发一次样式重算，而不是每次改动都各自触发一次；这部分代码之前没有使用批处理。

### 根因 4：过渡动画本身也占了大头

除了监听器和无谓的样式类切换，trace 里另外接近一半的时间花在 Cytoscape 内部的过渡动画逐帧计算上。原来的样式表给节点设置了四个属性的过渡（透明度、边框色、边框宽度、背景色），给边设置了四个属性的过渡（颜色、透明度、宽度、箭头色）。点击一次会让几百个节点、上千条边同时进入"变暗/取消变暗"的状态切换，等于同时起了几千个独立的过渡动画在逐帧插值，这些计算全部压在主线程上。

### 修复
- 把"从这里开始"提示的刷新请求合并到下一帧执行——同一帧内不管触发多少次，只在帧尾巴真正扫一次图。删除了那个监听"任意 class 变化"的冗余绑定，改为在真正会改变选中状态的地方（点击节点、点击空白处取消选中）显式调用一次刷新。
- "拖拽简化"样式的切换从"抓取即触发"改成"确认发生了实际拖动位移才触发"，区分点击和拖拽两种手势。
- 逐条元素操作的地方改成集合层面的一次性操作；把几个高亮相关的方法内部的多步样式改动包进批处理模式，让 Cytoscape 只在最后统一重算一次。
- 节点的过渡属性从四个减到只留透明度一个；边的过渡直接去掉，边框色、背景色、连线颜色这些改成瞬时切换，只有明暗渐变还保留动画感。

### 效果
点击路径上的全图扫描从"每次点击几百次"降到"每帧最多一次"；点击不再触发多余的全节点样式切换；过渡动画的逐帧计算量大幅减少。预期卡顿从 0.85 秒量级降到 100 毫秒量级以内，具体数字要重新录 trace 验证。

## 问题二：光晕呼吸效果不会动

### 现象
用户反馈某些标记了发光效果的节点，理论上应该有呼吸般的明暗脉动，实际却是静态的，完全不动。

### 根因：动画从未真正启动，而且原实现本身有性能陷阱

代码里其实写了一个呼吸动画的循环，但它只在初始化和整体换图这两个时机被调用一次。项目走的是"流式加载"路径——图数据分批陆续加进来，初始化那一刻图还是空的，所以判断"有没有需要发光的节点"时结果是零，循环直接不启动。后续陆续加进来的发光节点，因为这个判断只在最初执行过一次，永远赶不上。

更严重的是，即便把触发时机的 bug 修好，原实现的做法本身就不可取：它是每一帧都去改发光节点的样式属性来实现明暗脉动的。但只要改动任何元素的样式，Cytoscape 就会认为整张画布"脏了"，需要整体重绘——哪怕只有三五个节点在发光，也会带着场上全部 1000+ 个节点一起，以每秒 60 次的频率被无限重绘。这和问题一里"过渡动画占满主线程"是同一类代价，规模还更大，因为它是没有终止条件的持续任务，不是点击一次才触发一次。

### 修复
新增了一个独立的覆盖层方案：另起一张透明画布叠在 Cytoscape 的画布之上，专门用来画呼吸光晕，光晕本身用自己的动画循环驱动，完全不去碰 Cytoscape 节点的样式，因此不会牵连整张图重绘。画的是中间镂空的光环，节点本体、边框、文字标签仍然从光环中间正常透出来，不会被遮挡。

这个方案里还处理了几个配套问题：
- 监听图数据的增删事件，保证流式加载进来的新节点、被移除的旧节点都能被正确纳入或排除，不再是构造时的一次性快照。
- 只画视口内可见的发光节点，屏幕外的不计算。
- 动画帧率做了限流，明暗渐变这种缓慢变化不需要跟主渲染一样跑满帧率。
- 每帧只清除并重绘上一次画过的局部区域，而不是整张画布。
- 页面切到后台、或系统开启了"减少动态效果"这类无障碍设置时，动画会暂停或降级为静态。
- 加了一个安全阈值：如果视口内同时有大量发光节点，超过阈值就自动降级为静态光晕并停止动画循环，避免节点特别多时这个效果本身又变成新的性能瓶颈。

原有的节点边框静态光晕效果做了相应收窄——之前它自己也承担了一部分"外扩光晕"的视觉表现，宽度和不透明度都比较大；现在这部分外扩交给新的覆盖层负责，原有边框只保留一圈细而清晰的轮廓线，避免两层叠加显得臃肿。同时把它自己的过渡属性也精简了，去掉了两个已经不再需要逐帧变化的属性，避免无意义的过渡开销。

## 顺带的节点视觉优化

用户提出趁着改动，一并给节点做一些美化，但强调必须注意性能，因为已经到了 1000+ 节点的规模。

- 节点背景从纯色改成了径向渐变：中心保持亮色，边缘过渡到一个更深的同色系颜色，让节点看起来有体积感，不再是一块死板的色块。用的颜色都是配置里本来就存在但之前没被用上的一组"暗色"变体，没有引入任何新的配色。这是静态样式，会被 Cytoscape 的元素纹理缓存机制复用（相同形状、尺寸、配色的节点共享同一张缓存位图），额外开销较小，但不是零，建议在正式上线前用性能工具实测确认。
- 缩小到一定程度时，节点上的文字标签（包括标签背后的圆角背景矩形）会被直接跳过绘制，不再尝试渲染。这是因为 1000+ 节点场景下，标签本身是单项开销最大的绘制内容之一，而缩得足够小的时候文字本来也看不清，跳过绘制不影响可用性，却能明显降低全图缩小观察时的重绘成本。

## 一处已经加上又撤回的改动：视口拖动/缩放期间的渲染降级

### 曾经的改动
为了进一步压低大图在拖动和缩放这类连续手势期间的渲染成本，一度给 Cytoscape 开启了两个官方提供的选项：手势期间把当前画面当成一张静态截图去做变换而不是逐元素重绘；以及手势期间直接不绘制边。这两个选项是 Cytoscape 官方给超大规模图（通常几千节点往上）在明显感觉到卡顿时的标准建议。

### 用户反馈的问题
开启之后，用户反馈一拖动或缩放，边就完全消失了；而且一些原本在屏幕外、拖动过程中应该进入视野的节点，也要等松开鼠标才会出现。

### 原因
这正是那两个选项设计上的固有代价，不是缺陷。"把画面当成静态截图去变换"意味着这张截图是手势开始那一刻拍的快照，手势进行中平移出来的新画面内容根本不存在于这张快照里，自然不会显示，必须等手势结束后触发一次完整重绘才会补上。"手势期间不画边"同理，是直接跳过而不是延迟。

### 处理方式
权衡下来，这个视觉代价对当前 1000+ 节点的规模来说不划算——官方建议的适用场景是"图更大、且已经明显卡顿"，目前的规模还没到必须用这种降级换流畅度的地步。因此把这两个选项撤回关闭，同时在代码里留了说明和现成的开启方式，如果以后节点规模继续增长、拖动缩放确实感觉到卡顿，可以按需再打开。
