# 节点重构规则

> 适用范围：在已有图谱上，将旧版 frontmatter（12 种边、6 种 essence、无 level）迁移到新版规范（6 种边、11 种 essence、6 级 level），以及迁移完成后的结构性清理（合并、拆分、骨架补齐）。
>
> 配套文档：[frontmatter.md](./frontmatter.md) — 字段定义与视觉编码规范（权威来源）。
>
> 原则：忠实保留药学语义，不丢边、不丢正文；边类型迁移与内容合并分离提交。

***

## 一、迁移总览

当前图谱有 **1083 个 .md 文件**，使用 12 种旧边类型和 6 种旧 essence 值，无 `level` 字段。需要迁移到新规范：

| 维度       | 旧版                                                                                                                   | 新版                                                  | 迁移方式                      |
| -------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------- |
| 边类型      | 12 种（isa/has/treats/relates/prerequisite/mechanism/activates/sibling/specializes/causes/contraindicates/metabolizes） | 6 种（parent/branch/link/relate/support/contrast）     | 批量脚本 + 人工校验               |
| essence  | 6 种（medication/module/illness/concept/process/section）                                                               | 11 种（新增 classification/mnemonic/summary/table/note） | 按语义逐个重分类                  |
| level    | 不存在                                                                                                                  | 1-6 级                                               | 按 location 层级批量赋值 + 人工微调  |
| ADR-0001 | isa/has 方向规则                                                                                                         | parent/branch 方向规则                                  | isa→parent，has→branch 或删除 |

## 二、边类型迁移映射表

每条旧边必须按下表迁移到新边类型。**具体药学语义写进** **`reason`，不再各占一个** **`type`。**

| 旧边类型              | 数量   | 新边类型         | reason 写法             | 迁移说明                                               |
| ----------------- | ---- | ------------ | --------------------- | -------------------------------------------------- |
| `isa`             | 1096 | `parent`     | 保留原 reason            | 层级归属，子→父方向不变                                       |
| `has`             | 598  | `branch` 或删除 | 保留原 reason            | 父→子的 has：改为 branch；子→父的反向 has：删除（已由子节点的 parent 覆盖） |
| `treats`          | 345  | `link`       | `reason: 治疗{疾病名}`     | 药物→疾病的明确关系                                         |
| `relates`         | 318  | `relate`     | 保留原 reason            | 一般关联，兜底关系                                          |
| `prerequisite`    | 261  | `link`       | `reason: 前置依赖——{说明}`  | 学习前置关系，是明确知识关系                                     |
| `mechanism`       | 114  | `link`       | `reason: 机制——{说明}`    | 药物→机制的明确关系                                         |
| `activates`       | 14   | `link`       | `reason: 激动{靶点}`      | 药物→靶点的明确关系                                         |
| `sibling`         | 12   | `relate`     | 保留原 reason            | 同级关联                                               |
| `specializes`     | 9    | `link`       | `reason: 特化——{说明}`    | 特化/衍生关系                                            |
| `causes`          | 5    | `link`       | `reason: 导致{不良反应}`    | 药物→ADR 的明确关系                                       |
| `contraindicates` | 3    | `link`       | `reason: 禁忌——{人群/状态}` | 药物→禁忌的明确关系                                         |
| `metabolizes`     | 1    | `link`       | `reason: 代谢——{说明}`    | 药物→代谢酶的明确关系                                        |

### 迁移后的 6 种边类型语义

| 边类型        | 回答什么             | 方向     | 视觉       | 典型场景                          |
| ---------- | ---------------- | ------ | -------- | ----------------------------- |
| `parent`   | "A 属于 B 的层级"     | 子→父    | 灰色实线无箭头  | 药物→类别→节→章                     |
| `branch`   | "A 展开为 B"        | 父→子    | 蓝色实线无箭头  | 章节展开节、模块展开亚类                  |
| `link`     | "A 和 B 有明确的药学关系" | A→B    | 绿色实线三角箭头 | 治疗/导致/禁忌/机制/代谢（reason 承载具体语义） |
| `relate`   | "A 和 B 有弱关联"     | A→B    | 灰紫点线无箭头  | 同级关联、一般参考                     |
| `support`  | "A 配一个学习辅助 B"    | 主知识→辅助 | 橙色虚线三角箭头 | 药物→口诀、考点→注意、亚类→对比表            |
| `contrast` | "A 和 B 需要横向对比"   | A↔B    | 紫色虚线双向箭头 | 易混药物对比、跨类比较                   |

### 关键迁移规则

1. **`has`** **的双向清理**：旧版 A has→ B 和 B has→ A 同时存在的双向配对，迁移后只保留 `branch`（父→子方向），删除子→父的反向边。
2. **`reason`** **不可空**：迁移到 `link` 的边，如果原 reason 为空，必须补写具体语义（如 `reason: 治疗癫痫`）。
3. **`parent`** **和** **`branch`** **不共存**：同一对节点不能同时有 `parent` 和 `branch`。层级归属用 `parent`（子→父），分支展开用 `branch`（父→子），选一个方向写。
4. **`support`** **是新关系**：旧版口诀/注意内嵌在正文里没有边。迁移时，如果口诀/注意已升级为独立节点（essence: mnemonic/note），则从主知识节点发起 `support` 边指向它。

## 三、essence 迁移

### 3.1 保留不变的 essence（6 种，直接沿用）

| 旧 essence    | 新 essence    | 说明                                          |
| ------------ | ------------ | ------------------------------------------- |
| `medication` | `medication` | 不变                                          |
| `module`     | `module`     | 不变                                          |
| `illness`    | `illness`    | 不变                                          |
| `concept`    | `concept`    | 不变（但需逐个检查是否应改为 `notion` 或 `classification`） |
| `process`    | `process`    | 不变                                          |
| `section`    | 见下           | 需逐个重分类                                      |

### 3.2 `section` 重分类

`section` 是位置标记（"这是第几节"），不是知识本体。按实际语义重分类：

| section 节点的实际内容      | 迁移到              | 理由            |
| -------------------- | ---------------- | ------------- |
| 章节入口（如"第二节 抗癫痫发作药物"） | `module`         | 是结构容器，不是独立知识点 |
| 分类标准（如"按作用机制分类"）     | `classification` | 本质是分类依据       |
| 学习认知单元（如"用药监护"）      | `notion`         | 本质是学习性认知      |

### 3.3 `concept` 拆分检查

旧版 `concept` 是万能兜底。逐个检查，按新语义重新归类：

| concept 节点的实际内容   | 迁移到              | 理由                        |
| ----------------- | ---------------- | ------------------------- |
| 药物分类/分组标准         | `classification` | 本质是分类                     |
| 学习性认知单元（监护、评价、原则） | `notion`         | 本质是"怎么学/怎么用"              |
| 纯概念/术语（如"首过效应"）   | `concept`        | 保留不变                      |
| 口诀/记忆辅助           | `mnemonic`       | 独立后用 support 边挂回主知识       |
| 总结/归纳             | `summary`        | 独立后用 support 边挂回主知识       |
| 对比表格              | `table`          | 独立后用 support/contrast 边挂回 |
| 注意/提示/笔记          | `note`           | 独立后用 support 边挂回主知识       |

### 3.4 新增节点类型的使用条件

以下 4 种新 essence 在旧版中不存在，迁移时**按需创建**：

| 新 essence  | 何时创建独立节点                 | 何时内嵌正文不建节点         |
| ---------- | ------------------------ | ------------------ |
| `mnemonic` | 覆盖多个药物/亚类的章级或模块级大口诀      | 单个药物的局部小口诀         |
| `summary`  | 整章/整节的核心总结，需要被多个节点引用     | 单个段落的临时小结          |
| `table`    | 需要在图谱中作为独立对比节点存在的横向对比表   | 药物正文内的 Markdown 表格 |
| `note`     | 需要在图谱中作为独立标签存在的【注意】/【提示】 | 药物正文内的一句话提醒        |

> **判断阈值**：如果这条口诀/总结/表格/注意在纸质思维导图上**有独立框/独立分支**，就建独立节点；如果只是考点旁边的标注文字，就内嵌正文。

## 四、level 赋值规则

`level` 是新字段，决定节点边框色。按以下规则批量赋值：

### 4.1 按 location 层级赋值（默认规则）

| location 最深层级  | level | 典型节点             |
| -------------- | ----- | ---------------- |
| `book`         | 1     | 学科总入口（药学专业知识一/二） |
| `part`         | 1     | 篇级入口             |
| `chapter`      | 2     | 章级入口（第一章 XXX）    |
| `section`      | 3     | 节级入口/伞形 module   |
| `item`         | 4     | 具体药物、疾病、机制       |
| 无 location 或更深 | 5-6   | 考点维度、口诀、注意等辅助节点  |

### 4.2 按 essence 微调（覆盖默认规则）

| essence          | 默认 level | 说明                     |
| ---------------- | -------- | ---------------------- |
| `module`         | 2-3      | 章级=2，节级=3              |
| `classification` | 3        | 分类节点一般在节级              |
| `medication`     | 4        | 具体药物                   |
| `illness`        | 4        | 具体疾病                   |
| `process`        | 4        | 具体机制                   |
| `concept`        | 4-5      | 核心概念=4，细分考点=5          |
| `notion`         | 5        | 学习认知单元                 |
| `mnemonic`       | 4-5      | 药物级口诀=4（与药物同级），模块级口诀=5 |
| `summary`        | 5-6      | 模块总结=5，章级总结=6          |
| `table`          | 5        | 对比表                    |
| `note`           | 5-6      | 药物级注意=5，末级标签=6         |

### 4.3 赋值优先级

1. 有 `location` 的节点：按 §4.1 的 location 层级赋值。
2. 无 `location` 但有 `essence` 的节点：按 §4.2 的 essence 默认赋值。
3. 两者都有但矛盾的：以 §4.2 的 essence 为准（因为 location 是教材目录，level 是思维导图结构，两者不一定一致）。

## 五、合并规则（沿用旧版，调整后保留）

### 5.1 核心原则

1. **语义不丢**：合并节点的正文必须全部内化进目标节点。
2. **边不丢**：合并前先确认入边；若 > 0，需先迁移边再删除。
3. **不重建已删节点**：合并提交只改源节点正文 + 删除源 md，不新增节点。
4. **schema 修复 vs 内容合并分离**：边类型迁移、essence 重分类、level 赋值各自独立提交。

### 5.2 合并候选识别（4 条信号）

| 信号                                                 | 含义         | 处置                     |
| -------------------------------------------------- | ---------- | ---------------------- |
| ① `in_deg == 0` 且 essence 非 `medication`/`illness` | 零散节点       | 优先就地扩伞形/节正文；无合并去向则直接删除 |
| ② 伞形 module 正文缺机制/口诀段，但同级伞形都有                      | 结构不对称      | 把 in\_deg=0 的零散节点内化进伞形 |
| ③ 伞形 module 正文已包含与同目录 concept 完全重复的内容              | 已合并但忘了删 md | 直接删除 concept           |
| ④ 节节点正文已包含与同目录 concept 完全重复的内容                     | 同上         | 同上                     |

**不视为合并候选**：

- `in_deg == 0` 但 essence 是 `medication` 或 `illness`（具体药物/疾病是图谱一等公民）

- `in_deg > 0`（有入边即被引用，需先迁移边再合并）

### 5.3 合并去向决策

1. **伞形 module 正文的对应段** — 零散 concept 的内容天然属于伞形语义。
2. **节节点正文的相关段** — 跨伞形总论性 concept 归节。
3. **直接删除** — 当节点纯粹是孤立冗余，无任何合并价值时。

### 5.4 新版变化：口诀/注意不再强制合并

旧版 REFACTOR-RULES §零 规定"口诀禁止独立成节点，必须内嵌"。**新版推翻此规则**：

- 口诀（`mnemonic`）、总结（`summary`）、表格（`table`）、注意（`note`）**可以独立成节点**。

- 判断标准：纸质思维导图上有独立框/独立分支的 → 独立；只是考点旁标注文字的 → 内嵌。

- 独立的口诀/注意节点用 `support` 边从主知识节点指向它。

### 5.5 骨架边补齐（与合并正交）

当某章节的伞形 module in\_deg=0，但本来应该有 `parent` 边指向父级时，属骨架缺失而非过度拆分。

| 场景                      | 处置           |
| ----------------------- | ------------ |
| 节点零入度 + 有自身语义           | 合并到伞形/节正文    |
| 节点零入度 + 是骨架本身（伞形/药物/疾病） | 补 `parent` 边 |
| 节点零入度 + 是图入口（节、章、book）  | 不动           |

### 5.6 禁止冗余空模块

**不得创建纯视觉分区的空 wrapper 节点。** 每个节点必须有独立知识语义。

| 场景                           | 处置               |
| ---------------------------- | ---------------- |
| 创建"分类与代表药品"空模块（只做视觉分区，无独立语义） | ❌ 删除，药物直接挂到分类节点  |
| 创建"临床用药评价"空模块（只做视觉分区，无独立语义）  | ❌ 删除，临床评价下沉到药物节点 |
| 章级入口（有完整 summary + 语义）       | ✅ 保留             |
| 节级入口（有完整 summary + 语义）       | ✅ 保留             |

### 5.7 临床内容下沉模式

药物节点的临床内容（药理作用、适应症、禁忌、相互作用）**写入** **`summary.full`** **字段**，不拆成独立的 `link` 边。

```yaml
# ✅ 正确：临床内容在 summary.full
summary:
  short: 吡拉西坦是酰胺类代表药，改善脑代谢。
  full: >-
    【药理作用】作用于大脑皮质，激活神经细胞…
    【适应症】急慢性脑血管病所致记忆减退…
    【禁忌】锥体外系疾病、亨廷顿舞蹈症禁用…
    【相互作用】与华法林合用延长凝血酶原时间…

# ❌ 错误：为每个临床关系建独立边
edges_out:
  - target: some-disease
    type: link
    reason: 治疗
  - target: some-adr
    type: link
    reason: 导致
```

**何时用** **`link`** **边、何时用 summary.full？**

| 场景                     | 做法                |
| ---------------------- | ----------------- |
| 药物→疾病的对应关系需要图谱导航       | `link` 边 + 独立疾病节点 |
| 药物的药理/适应症/禁忌/相互作用是知识文本 | `summary.full` 内嵌 |
| 药物之间的相互作用需要可视化         | `link` 边          |
| 单纯的文字描述考点              | `summary.full` 内嵌 |

### 5.8 summary 字段填写原则

**`summary.full` 必须由用户手动提供，禁止 AI 自动填充。**

这是创建/重构节点文档时最容易越权的点，必须严格区分两类字段：

| 字段                | 创建时可自动初始化？   | 何时可填充/替换                                          |
| ----------------- | ------------- | ------------------------------------------------- |
| `summary.short`   | ✅ 可以（建议留空或简短占位） | 用户主动提供或确认后 **替换**（包括沿用旧值、手写改写、按用户指令重写）         |
| `summary.full`    | ❌ 禁止          | **仅当用户主动提供文本时** 才可写入；任何"智能补充"、"自动总结"、"按药理推断"都被禁止 |

**反模式（绝对禁止）**：

1. ❌ 创建新节点时由 AI 撰写 `full:` 内容，即使看起来"药理学上是正确的"。
2. ❌ 用通用占位字符串填充 `full:`（如 `"待补充"`、`"暂无内容"`），用户未要求时不得加占位。
3. ❌ 在用户改 `short` 时顺手重写 `full`，除非用户明确指示。
4. ❌ 把 `full` 拆成独立 `link` 边的同时，还往 `full` 字段里塞文字。两选一（见 §5.7）。
5. ❌ 用其它同章节、同分类节点的 `full` 文本进行"模板套用"——除非用户明确要求参照。

**正模式**：

1. ✅ 创建新节点时：若用户未提供 `full`，**该字段完全不写**（让 YAML 解析为 `undefined`，UI 自然隐藏"展开详情"按钮）。
2. ✅ 用户手写或口述一段内容并明确说"写入 full"：原样写入，不二次润色。
3. ✅ 用户明确要求"参考 X 节点的格式改写本节点的 full"：可以改写；否则不参照。
4. ✅ 用户只提供 `short`：仅替换/写入 `short`，**`full` 字段保持原样或不写入**，不留占位文本。
5. ✅ 用户提供多个药理点（如"作用：…用途：…禁忌：…"）：按用户给的标题分段写入 `full`，段落间用空行分隔（marked 会拆出多个 `<p>`）。

**汇报约定**：

- 创建/重构一个节点时，在最终汇报里**明示** `short`/`full` 两个字段分别做了什么（哪个是用户提供的、哪个是沿用旧的、哪个未改动、哪个为不写入）。
- 若用户未提供 `full`，汇报里必须出现 "未写 full / full 留空 / 待用户提供" 字样，便于用户知道该字段需要后续补充。

**判断锚点（self-check）**：

> "如果我不在场，用户能否接受我写进 `full` 的每一个字？"  
> 不能 → 删掉或留空；能 → 写。  
> 默认答案：**不能**，所以默认不写。

## 六、提交拆分原则

一次提交只做一类事：

| 提交类型        | 内容                    | 示例                                                    |
| ----------- | --------------------- | ----------------------------------------------------- |
| 边类型迁移       | 旧 12 种 → 新 6 种批量转换    | `refactor(content): 第一章边类型迁移 isa→parent, treats→link` |
| essence 重分类 | section/concept → 新类型 | `refactor(content): 41 个 section 节点重分类`               |
| level 赋值    | 批量添加 level 字段         | `chore(content): 全仓 level 字段批量赋值`                     |
| 内容合并        | 扩伞形正文 + 删 concept     | `refactor(content): 第六节 6 个零入度节点合并`                   |
| 骨架边补齐       | 仅新增 parent/branch 边   | `chore(content): 药一第一篇补齐骨架边`                          |

## 七、迁移后验证清单

每次提交前必须确认：

1. ✅ `npm test` 全部测试通过
2. ✅ `npm run validate` 0 error（warning 可接受，但需记录）
3. ✅ 0 悬空边（所有 edges\_out.target 在仓库中存在）
4. ✅ 0 YAML 解析错误 / 0 ID 重复

### 10.3 边类型使用

整个样板仅使用 2 种边类型：

| 边类型       | 用途         | 数量               |
| --------- | ---------- | ---------------- |
| `parent`  | 子→父层级归属    | 20 条（每个非根节点 1 条） |
| `support` | 主知识→口诀学习辅助 | 4 条（药物/分类→口诀）    |

不使用 `link`/`relate`/`branch`/`contrast` — 临床关系全部在 `summary.full` 文本中。

### 10.4 关键设计决策

1. **无冗余空模块**：不建"分类与代表药品"和"临床用药评价"空模块。层级链直接章→节→分类→药物。
2. **临床内容在 summary.full**：药理/适应症/禁忌/相互作用全部写入 summary.full 的【标签】格式文本。
3. **口诀与药物同级**：口诀 level=4，与药物同级（不是更深层级），因为口诀是药物的平行学习辅助。
4. **口诀用 support 边**：从主知识节点发起 support 边指向口诀节点。口诀节点本身 edges\_out 为空。
