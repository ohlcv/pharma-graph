# Pharma Mindmap Transcribe — 纸质思维导图 → 节点 md

把纸质思维导图照片忠实转录为符合规范的独立节点 `.md` 文件。

**开始任何转录前必须读取：**
- `docs/frontmatter.md` — 通用字段定义、OWL2 实体类型、三维度视觉编码（权威）
- `docs/RULES.md` — 药学领域特化参数：fill 取值、外观配置、渲染参数、迁移映射

> 本 SKILL 与 RULES 冲突时，以 RULES.md 为准。

---

## 一、核心硬性约定（违反即不合规）

### 1.1 文件名 = label（中文），id = 英文/拉丁文

- **文件名** = `label`（中文），如 `地西泮.md`
- **`id`** = 英文/拉丁文，用于图的 id 寻址、edges_out 引用
- 两者分工，不可混用

### 1.2 id 命名格式

**`id` = 前缀-节点英文名-书简写-章号-节号**

| 前缀 | fill | 节点类型 | 示例 |
|---|---|---|---|
| `sec-` | `cls-structure` | 组织结构（书/篇/章/节入口） | `sec-sedative-y2-01-01` |
| `cls-` | `cls-classification` | 药物分类 | `cls-benzodiazepine-y2-01-01` |
| `med-` | `cls-drug` | **重点药**（有完整药理卡片，stroke: glow） | `med-diazepam-y2-01-01` |
| `drug-` | `cls-drug` | **普通药**（仅提名，stroke 不填） | `drug-trizolam-y2-01-01` |
| `disease-` | `cls-disease` | 疾病/症状 | `disease-insomnia-y2-01-01` |
| `bio-` | `cls-biomolecule` | 生物实体（靶点/受体/酶） | `bio-gabaa-y2-01-01` |
| `feat-` | `cls-feature` | 作用特点/临床评价 | `feat-barbiturate-y2-01-01` |
| `adr-` | `cls-adverse` | 不良反应/禁忌/毒性 | `adr-barbiturate-y2-01-01` |
| `concept-` | `cls-concept` | 抽象概念/总论/术语 | `concept-bioavailability-y1-04` |
| `sum-` | `cls-summary` | 总结/表格 | `sum-barbiturate-y2-01` |
| `mem-` | `cls-mnemonic` | 口诀 | `mem-barbiturate-y2-01-01` |

**重点药 vs 普通药判定**：纸质版中该药物有独立框且框内有正文内容 → 重点药（`med-`，stroke: glow）；仅提名无独立画像 → 普通药（`drug-`，不填 stroke）。**所有药物都必须建独立节点**。

**章节后缀**：`y1`=药一、`y2`=药二、`y3`=药综、`y4`=法规，格式 `{书简写}-{章号}-{节号}`。

### 1.3 summary 规则（short 留空，full 只写纸质版有的）

| 字段 | 规则 |
|---|---|
| `summary.short` | **全部留空**，不写任何内容。荧光笔标注/关键词不写入 short（后续可基于 full 加粗关键词提取） |
| `summary.full` | 仅写纸质版（含手写）上有的内容，纸质版没有的一律不填，不推断、不编造、不占位 |

**核心原则**：纸质版有的写到 full，纸质版没有的不填，short 空着。

**反模式（绝对禁止）**：
- ❌ 给分类节点、普通药节点擅自加 short 描述（如"钠通道阻滞剂"）
- ❌ 按药理推断填充 full（即使"药理学上正确"也不行）
- ❌ 用占位符（"待补充""暂无内容"）
- ❌ 口诀写入 short（口诀只建独立节点，见 §六）

### 1.4 stroke 规则（只写 glow，不写 auto）

- **不填** = 默认 auto（无特效），**禁止显式写 `stroke: auto`**
- **`glow`** = 呼吸光晕，只给纸质版"临床用药评价"分支下的节点（重点药/有临床评价的分类）
- 分类与作用机制分支里的分类，即使列出了多个代表药，也不加 glow

| 节点类型 | stroke | 判定标准 |
|---|---|---|
| 重点药（临床用药评价里有独立评价框） | `glow` | 纸质版"临床用药评价"分支下有该药物的独立框 |
| 普通药（仅提名） | 不填 | 仅在分类框中提名 |
| 重点分类（临床用药评价分支下有该分类） | `glow` | 临床用药评价分支下直接出现该分类名 |
| 普通分类（仅在分类与作用机制分支出现） | 不填 | 仅在"分类与作用机制"分支出现 |
| 跨节大总结/表格 | `glow` | 跨节汇总对比 |
| 节内总结 | 不填 | 仅本节内总结 |

### 1.5 平铺结构（无 data 包装）

所有字段直接平铺，不使用 `data:` 包装。

## 二、命名规范（label / id / 父节点 / 结构框映射）

### 2.1 label 命名总原则

| 节点类型 | label 命名 | 示例 |
|---|---|---|
| 药物节点 | 药名本身，不加节名/分类前缀 | `地西泮`、`唑吡坦`、`丙戊酸钠` |
| 分类节点 | 分类名本身 | `苯二氮䓬类`、`巴比妥类`、`非苯二氮䓬类` |
| 节入口 | `第X节 {节名}` | `第一节 镇静催眠药`、`第二节 抗癫痫发作药` |
| 章入口 | `第X章 {章名}` | `第一章 精神与中枢神经系统用药` |
| 口诀节点 | 口诀内容本身 | `爸比不焦急`、`全心全意` |
| 总结节点 | 纸质版原标题 | `根据癫痫发作类型合理选药` |
| 代际分类 | **加节名后缀**，避免跨节冲突 | `第一代抗癫痫发作药`（不是裸`第一代`） |

**核心规则**：
- 药物/分类节点 label 不加节名前缀（如不写"第一节地西泮"）
- 代际分类（第一代/第二代/第三代）必须加节名后缀，否则多节都有"第一代"会冲突
- 口诀节点 label 直接写口诀内容，不用"XX口诀"式命名（特殊情况除外，如丙戊酸钠有两个口诀时用`丙戊酸钠口诀`）

### 2.2 结构框 → 节点名映射表

纸质版思维导图中的结构框，按以下规则转换为节点 label：

| 纸质版结构框 | 处理方式 | 节点 label 示例 |
|---|---|---|
| 总论 | 不单独建节点，写入节入口 full | —（写入`第一节 镇静催眠药`的 full） |
| 分类与作用机制 | 不单独建节点，是分区标题 | — |
| 分类 | 不单独建节点，分类节点本身就是分类 | — |
| 代表药物 | 不单独建节点，写入分类节点 full【代表药】 | — |
| 临床用药评价 | 不单独建节点，不拆子节点，内容合并写入重点药 full | — |
| 作用特点 | 不单独建子节点，合并写入重点药 full【作用特点】 | — |
| 典型不良反应 | 不单独建子节点，合并写入重点药 full【不良反应】 | — |
| 主要临床应用 | 不单独建子节点，合并写入重点药 full【临床应用】 | — |
| 总结 | 有独立内容的建节点，用纸质版原标题 | `不同种类的镇静与催眠药剂量与药理作用的关系` |
| 第一代/第二代/第三代 | 建节点，**加节名后缀** | `第一代抗癫痫发作药` |
| 抑制兴奋性/增强抑制性 | 建节点，用纸质版原标题 | `抑制兴奋性`、`增强GABA抑制性` |
| 抑制电压门控钠通道 | 建节点，用纸质版原标题 | `抑制电压门控钠通道` |
| 对肝药酶无影响 | 建节点（手写补充特殊内容），用原标题 | `对肝药酶无影响` |
| 备孕或妊娠期女性癫痫用药 | 建节点（总结节点），用原标题 | `备孕或妊娠期女性癫痫用药` |
| 根据癫痫发作类型合理选药 | 建节点（总结节点），用原标题 | `根据癫痫发作类型合理选药` |

**判断标准**：结构框内有独立正文内容 → 建节点，用纸质版原标题；结构框只是分区标题或通用连接词 → 不建节点，内容融合到对应节点。

### 2.3 代际分类命名（防冲突）

**第一代/第二代/第三代这种通用代际名，必须加节名后缀，否则跨节会冲突。**

| ✅ 正确 | ❌ 错误 |
|---|---|
| `第一代抗癫痫发作药` | `第一代` |
| `第二代抗癫痫发作药` | `第二代` |
| `第三代抗癫痫发作药` | `第三代` |

**原因**：如果每一节都分为第一代/第二代/第三代，裸名"第一代"会在多个节中重复，id 也会冲突。加节名后缀后，label 和 id 都唯一。

**id 对应**：
- `第一代抗癫痫发作药` → `cls-gen1-epilepsy-y2-01-02`
- `第二代抗癫痫发作药` → `cls-gen2-epilepsy-y2-01-02`
- `第三代抗癫痫发作药` → `cls-gen3-epilepsy-y2-01-02`

### 2.4 id 命名规则

**`id` = 前缀-节点英文名-书简写-章号-节号**

| 前缀 | 节点类型 | id 示例 |
|---|---|---|
| `sec-` | 节入口 | `sec-sedative-y2-01-01` |
| `ch-` | 章入口 | `ch-cns-y2-01` |
| `cls-` | 分类 | `cls-benzodiazepine-y2-01-01` |
| `med-` | 重点药 | `med-diazepam-y2-01-01` |
| `drug-` | 普通药 | `drug-trizolam-y2-01-01` |
| `mem-` | 口诀 | `mem-barbiturate-y2-01-01` |
| `sum-` | 总结 | `sum-seizure-selection-y2-01-02` |
| `disease-` | 疾病 | `disease-insomnia-y2-01-01` |
| `bio-` | 生物实体 | `bio-gabaa-y2-01-01` |

**id 唯一性**：所有节点 id 必须唯一，口诀节点 id 不使用 label 首字等易重复方式。

### 2.5 父节点 ID（章/节入口）

| 层级 | id 格式 | 示例 |
|---|---|---|
| 章入口 | `ch-{章节英文名}-{书简写}-{章号}` | `ch-cns-y2-01` |
| 节入口 | `sec-{节英文名}-{书简写}-{章号}-{节号}` | `sec-sedative-y2-01-01` |

**edges_out 引用**：
- 节入口 → 章入口：`part_of → ch-cns-y2-01`
- 分类/药物/口诀 → 节入口或分类节点：`instance_of` / `part_of`

### 2.6 同名冲突解决

| 冲突场景 | 解决方式 |
|---|---|
| 多节都有"第一代/第二代/第三代" | 加节名后缀：`第一代抗癫痫发作药` |
| 多节都有"临床用药评价" | 不单独建节点，内容合并写入重点药 full |
| 同一药物出现在多个分类下 | 只建一个节点，多条 `instance_of` 边 |
| 纸质版同一名称出现在多个分支下 | 合并为一个节点 |
| 口诀内容相同但挂载不同 | 用 id 区分，label 可相同（但尽量避免） |

## 三、工作流（两步走：框架版 → 内容版）

### Step 1 — 读规范

读取 `docs/frontmatter.md` 与 `docs/RULES.md` 全文。

### Step 2 — 读照片（放大、多轮细读）

1. 读取全部思维导图照片（多张图时逐张读取）
2. 文字过小或过密时放大裁剪再读
3. 记录：分支结构、各节点名称、药物画像正文、**荧光笔高亮/有色字体**、手写补充、口诀文字

### Step 3 — 用户确认模糊点（不猜，附 A/B/C 候选）

识别所有读不清/有歧义的内容，**一次性列出向用户确认**。有自己推断的附上候选答案 A/B/C：

| 模糊点 | 候选答案 |
|---|---|
| OCR 模糊的药名/术语 | A. 候选名1  B. 候选名2  C. 其他（用户补充） |
| 归属不明的口诀 | A. 挂药物X  B. 挂分类Y  C. 挂作用特点Z |
| **分类层级完整性**（几层子分类？每层哪些药？） | A. 已全部识别  B. 有X层未识别  C. 用户补充 |
| **临床用药评价分支判定**（哪些节点在临床评价下？） | A. 已明确  B. 需确认  C. 用户列出 |
| **"本节不重点介绍"的分类下是否有药名** | A. 有，需建节点  B. 无  C. 用户确认 |
| 荧光笔/有色字体标注的关键词 | A. 已全部识别  B. 有X处不确定  C. 用户指出 |

> **Step 3 必查**：分类层级完整性是最高频错误点——必须确认有几层子分类、每层列出哪些药名、"本节不重点介绍"的分类下是否也有药名。

### Step 4 — 第一步：建节点框架（不填 full）

**只建节点框架，不填写 `summary.full`。**

- 输出目录：`书名/章名/节名/`
- 文件名 = label（中文）
- frontmatter 含 `id/label/location/shape/fill/stroke/tags/summary/edges_out`
- `summary.full` 留空，`summary.short` 留空
- 按 §四 结构节点原则处理
- 口诀节点独立建 md（见 §六）
- tags 先按框架信息填写（药品名+分类+药理作用），ADR/禁忌等内容版再补

### Step 5 — 第一步自查（框架版检查清单）

按 §七.1 框架版检查清单逐项检查。

### Step 6 — 第一步交付（框架版 zip + 节点说明总结）

- 打包节级 zip
- 附节点说明总结（层级树、节点数、stroke 分布、glow 节点列表）
- **明确告知用户：这是框架版，full 内容尚未填写，请审批节点结构**
- 用户审批通过后进入第二步；用户提出修改则修改后重新交付

### Step 7 — 第二步：填写 full 内容

**用户审批框架通过后，逐节点填写 `summary.full`。**

- 逐节点读取纸质版原文，填写 full
- 重点药的临床评价内容按 §4.4 规则，合并写入 full，用 `【作用特点】`、`【临床应用】`、`【不良反应】` 标签分段
- **full 中纸质版视觉强调的关键词（荧光笔/有色字体）必须用 `**加粗**` 标注**（见 §5.3）
- 严格遵守 §1.3：纸质版有的写，没有的不擅自添加
- 补全 tags（ADR、禁忌等从 full 中提取，见 §5.4）

### Step 8 — 第二步自查（内容版检查清单）

按 §七.2 内容版检查清单逐项检查。

### Step 9 — 最终交付（内容版 zip + 节点说明总结）

- 重新打包节级 zip
- 更新节点说明总结（含 full 填写情况、加粗关键词统计、tags 统计）

#### 交付物格式

**交付物 1：节级 zip**
- 命名：`{节名}.zip`，如 `第一节 镇静催眠药.zip`
- 用 `unzip -l` 反查文件数，确认与节点总数一致

**交付物 2：节点说明总结**

| 项目 | 内容 |
|---|---|
| 节名 | 如「第一节 镇静催眠药」 |
| 节点总数 | 用 `unzip -l` 反查的实际文件数 |
| 层级结构 | 节入口 → 分类 → 子分类/药物/口诀 的层级树 |
| glow 节点 | 列出所有 stroke: glow 的节点 |
| full 填写情况 | 哪些节点填了 full、哪些留空 |
| 口诀归属 | 每条口诀 part_of 指向哪个节点 |
| 已知未完成项 | 哪些节点 full 未填、哪些关系待确认 |

## 四、结构节点原则（完全以纸质版为准 + 电子版去冗余）

### 3.1 核心原则

1. **完全以纸质版为准**：纸质版有框 → 电子版有对应节点，不随意删减层级
2. **认清纸质版局限性**：纸质版受纸张大小限制，需要"分类与作用机制""临床用药评价"等结构节点分区；电子版不受此限制
3. **通用结构词不单独建空壳节点**：分类、总论、代表药物、临床用药评价、作用机制、典型不良反应、总结——能融合就融合
4. **必须单独建的加前缀/后缀**：纸质版中该框有独立正文内容时，保留为单独节点，但 label 必须加具体药名/分类名
5. **纸质版同名重复框合并**：同一名称出现在多个分支下（如巴比妥类同时在"分类"和"临床用药评价"下），电子版合并为一个节点

### 3.2 通用结构词融合清单

| 通用结构词 | 处理方式 |
|---|---|
| 总论 | 写入节入口节点的 `summary.full` |
| 分类 | 不单独建，分类节点本身就是分类 |
| 代表药物 | 写入分类节点的 `summary.full【代表药】` |
| 临床用药评价 | **不单独建，不拆子节点**，其下内容合并写入对应重点药/分类的 full（见 §4.4） |
| 作用机制 | 写入分类/药物节点的 `summary.full` |
| 总结 | 节内总结可建节点（`cls-summary`），跨节大总结建节点并加 glow |

### 3.3 分类层级完整性（禁止药物直挂节入口）

**纸质版中每一层分类框都必须建对应节点，药物必须挂到所属分类下。**

| 规则 | 说明 |
|---|---|
| 逐层建节点 | 有几个子分类就建几个分类节点，即使"本节不重点介绍"也必须建 |
| 药物挂分类 | 所有药物节点的 `edges_out` 必须 `instance_of` 指向所属分类，禁止直接挂节入口 |
| 不遗漏药名 | 分类框中列出的所有药名都必须建独立节点 |
| 口诀挂分类 | 分类级口诀 `part_of` 指向该分类节点 |

**正模式：**
```
第八节 中枢肌松药 (节入口)
├── 苯二氮䓬类 (分类，本节不重点介绍，但仍需建节点)
│   ├── 三唑仑 (普通药，instance_of → 苯二氮䓬类)
│   └── 艾司唑仑 (普通药，instance_of → 苯二氮䓬类)
└── 非苯二氮䓬类 (分类)
    ├── 乙哌立松 (重点药，instance_of → 非苯二氮䓬类)
    └── 氯唑沙宗 (普通药，instance_of → 非苯二氮䓬类)
```

### 3.4 临床用药评价：合并写入重点药 full（不拆子节点）

**临床用药评价分支下的内容，不拆分"作用特点""临床应用""不良反应"子节点，全部合并写入对应重点药/分类的 `summary.full`。**

| 规则 | 说明 |
|---|---|
| 不拆子节点 | 不建 `{药名}作用特点`、`{药名}主要临床应用`、`{药名}典型不良反应` 等子节点 |
| 合并写入 full | 所有临床评价内容写入重点药的 `summary.full`，用标签分段 |
| 需读原文分类 | 纸质版可能把所有内容写到一个框里，需要读原文分清楚哪段是作用特点、哪段是临床应用、哪段是不良反应 |
| 格式清楚 | 标签分段，段落间空行，编号用 (1)(2)(3)，**每个编号换行** |

**full 格式示例：**
```yaml
summary:
  full: |
    【作用特点】
    (1) 肝药酶抑制剂，用于各种类型癫痫。
    (2) 有肝毒性，3岁以下儿童风险较大。

    【临床应用】
    (1) 各种类型癫痫，包括全身性强直-阵挛发作及部分性发作。
    (2) 双相情感障碍相关躁狂发作。

    【不良反应】
    (1) 肝毒性，肝功能损害。
    (2) 避免与肝毒性药物合用。
```

**反模式（绝对禁止）**：
- ❌ 把重点药拆成"作用特点""临床应用""不良反应"3个子节点
- ❌ 纸质版内容混在一个框里，不分类就直接原样写入 full
- ❌ full 里不写标签，内容堆在一起不分段
- ❌ (1)(2)(3) 不换行，挤在一行

### 3.5 药物节点处理（所有药物都建独立节点）

| 类型 | 前缀 | stroke | summary.full | 判定标准 |
|---|---|---|---|---|
| **重点药** | `med-` | `glow` | 有完整临床评价内容 | 纸质版有独立框且框内有正文 |
| **普通药** | `drug-` | 不填 | 留空 | 仅提名，无独立正文框 |

- 纸质版一个框里列出多个药名（如"长效：苯巴比妥、巴比妥"），每个药各建独立节点，不合并
- 普通药节点 `edges_out` 写 `instance_of → 父分类节点`
- 分类节点的 `summary.full【代表药】` 仍保留，作为该分类下药物的概览清单

### 3.6 多父节点药物（多条 edges_out）

**当一个药物同时出现在多个分类分支下时（如按代分类 + 按作用机制分类），只建一个节点，但 `edges_out` 写多条边。**

```yaml
edges_out:
  - target: cls-gen2-y2-01-02
    type: instance_of
    reason: 第二代抗癫痫发作药的代表药物
  - target: cls-nmda-y2-01-02
    type: instance_of
    reason: 抑制NMDA型谷氨酸受体的代表药物
```

### 3.7 总结节点合并规则

**当纸质版有一个总标题（如"根据癫痫发作类型合理选药"），其下包含多个子类型且每个子类型涉及多个药物时，合并为一个总结节点，不拆分。**

| 规则 | 说明 |
|---|---|
| 合并为一个节点 | 总标题作为一个 `cls-summary` 节点，不拆成多个子类型节点 |
| 挂节入口 | `edges_out` 为 `part_of → 节入口`，不连大量 `has_instance` 边 |
| 内容写 full | 各子类型内容写入 `summary.full`，用 `【子类型】` 标签分段 |
| short 留空 | 总结节点的 short 永远不写 |

**反模式**：
- ❌ 把"根据癫痫发作类型合理选药"拆成"局灶性癫痫""失神发作"等多个子节点
- ❌ 给总结节点连大量 `has_instance` 边指向每个药物（导致图混乱）

### 3.8 其他常见错误

| 错误场景 | 正确做法 |
|---|---|
| 机制分类节点只写代表药在 full，没给代表药加边 | 代表药用 `instance_of` 边指向分类 |
| 药物级口诀挂到分类节点上 | 口诀挂载以纸质版为准，药物级口诀 `part_of` 指向药物节点 |
| 纸质版同一框里的多个内容被拆成多个节点 | 同一框里的内容合并为一个节点，不拆分 |
| 机制分类下的子分类（如"激动GABAA受体"下的"苯二氮䓬类"）没建节点 | 纸质版中有明确子分类的，建子分类节点 |

## 五、字段制作规范

### 4.1 shape / fill

- **fill**（必填）：药学顶层类 IRI，决定背景色 + 默认形状 + 默认边框。取值见 RULES §三
- **shape**（可选）：OWL2 实体类型，不填或 `auto` 时用 fill 的默认形状

### 4.2 summary.full 格式

- 多段结构，每段以 `【标签】` 起头
- 常用标签：`【作用特点】` `【临床应用】` `【不良反应】` `【代表药】` `【禁忌】` `【药理作用】` `【口诀】`
- **段落之间必须空行**
- **(1)(2)(3) 每个编号换行**，不挤在一行
- 关键医学术语 `**加粗**`（见 §5.3）
- 必须用 `full: |`（block scalar）

**禁止**：整段不换行、`#` 标题、HTML 标签。

### 4.3 full 中重点关键词加粗规则

**纸质版上被荧光笔标注、有色字体（蓝色/红色等）、或视觉上强调的重点关键词，在写入 full 时必须用 `**加粗**` 标注。** 这关系到后续抽取 tags。

| 加粗对象 | 示例 |
|---|---|
| 药物成分/结构名 | **咪唑并吡啶**、**环吡咯酮**、**三氯乙醇** |
| 关键酶/代谢途径 | **肝药酶诱导剂**、**CYP3A4**、**凝血酶原时间** |
| 关键受体/通道 | **GABAB**、**MT1**、**MT2**、**觉醒通路** |
| 特殊不良反应 | **Stevens-Johnson综合征**、**宿醉**、**戒断综合征** |
| 关键参数/数值 | **生物利用度约为80%**、**Q-T间期** |
| 特殊人群/禁忌 | **胎盘屏障**、**肝功能不全** |
| 代表药名 | **地西泮**、**瑞马唑仑** |

**规则**：
- 只加粗纸质版上**视觉强调**的关键词，不自行判断加粗
- 同一关键词多次出现时每次都加粗
- 加粗不改变原文措辞，只添加格式标记

### 4.4 tags 抽取规则

#### 三铁律

1. **复用优先**：full 里已有合适关键词直接复用，不另造同/近义词
2. **去重优先**：不写语义重复的标签
3. **不杜撰**：严禁把 full 里没出现的概念放进 tags

#### 节点类型专属规则

| 节点类型 | tags 必须包含 | 可选包含 |
|---|---|---|
| **重点药**（glow） | 药品名 + 分类 tag + **药理作用 tag** | 适应症、禁忌、ADR（最多3个）、化学分类、代际 |
| **普通药** | 药品名 + 分类 tag | —（可简化） |
| **分类节点** | 自身 label | 子分类名、机制、重点代表药 |
| **口诀节点** | `口诀` + 对应药名/分类名 | — |
| **总结节点** | 核心关键词 | 相关分类/作用 |

#### 四种前缀 tag（必须区分）

| 类型 | 定义 | 标注方式 | 示例 |
|---|---|---|---|
| **药理作用** | 药物在体内产生的药理效应（必填） | `药理作用：XXX` | `药理作用：镇静催眠`、`药理作用：抗癫痫` |
| **适应症** | 临床用于治疗的疾病/症状（可选） | `适应症：XXX` | `适应症：失眠`、`适应症：癫痫` |
| **禁忌** | 禁用的人群/情况（可选） | `禁忌：XXX` | `禁忌：妊娠期禁用`、`禁忌：肝功能不全` |
| **ADR** | 不良反应（可选，最多3个） | `ADR：XXX` | `ADR：宿醉`、`ADR：肝毒性` |

**规则**：
- 重点药必须至少有一个**药理作用 tag**（必填）
- 适应症、禁忌、ADR 均可选，有则加对应前缀
- 普通药可简化，不需要严格区分
- 禁止把适应症当药理作用写（如把 `失眠` 写成药理作用）
- 禁忌 tag 只写禁用情况，不写慎用

**示例：**
```yaml
tags:
  - 唑吡坦              # 药品名
  - 非苯二氮䓬类         # 分类
  - 药理作用：镇静催眠    # 药理作用（必填）
  - 适应症：入睡困难      # 适应症（可选）
  - ADR：宿醉           # ADR（可选）
  - CYP3A4             # 代谢途径
```

#### 抽取流程

1. **扫 full**：抽出所有 `**加粗**` 短语 / 专有名词 / 药理分类词
2. **按三铁律 + 节点类型规则过滤**
3. **语义去重**
4. **硬约束再过滤**：不重复 fill 枚举值、不写本质词、不写整句
5. **兜底自取**（仅当前4步拿不到目标数量时）：基于 full 上下文自取，**必须向用户汇报"自取了哪些"**

### 4.5 edges_out 填写规则

#### 边方向铁律：每个节点自管自己的 edges_out

| 关系 | 由谁写 | type |
|---|---|---|
| 类-类层级（子类→父类） | 子类写 | `subclass_of` |
| 药物→分类 | 药物写 | `instance_of` |
| 节入口→章入口 | 节入口写 | `part_of` |
| 口诀→主知识节点 | **口诀节点**写 | `part_of` |
| 总结节点→节入口 | 总结节点写 | `part_of` |

**禁止**：
- ❌ 父节点写 edges_out 指向子节点
- ❌ 用 `subclass_of` 表达 `part_of`
- ❌ 双向边正反都写

#### reason 措辞规范

- **必填**，不可空
- 必须包含具体对象（药名/分类名），不能是"治疗""相关"等空泛词
- 必须能独立成句

### 4.6 location 字段

```yaml
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
  item: 一、（一）①   # 可选
```

- 知识节点的 label 不附目录序号（如药物节点写「地西泮」，不写「第一节 地西泮」）
- 结构节点（节入口）的 label 可包含序号（如「第一节 镇静催眠药」）
- location 只是来源坐标，不决定 fill/shape，也不决定边类型

## 六、口诀处理（独立节点，不写入 short）

口诀**只建独立节点**（`fill: cls-mnemonic`），不写入挂载节点的 short（因为 short 全部留空）。

### 5.1 口诀归属：完全以纸质版挂载位置为准

| 纸质版挂载位置 | 电子版 part_of 指向 |
|---|---|
| 挂在具体药物下 | 该药物节点 |
| 挂在分类下 | 该分类节点 |
| 挂在节/章入口下 | 该节/章节点 |

### 5.2 口诀节点 label

直接写口诀内容本身（如 `爸比不焦急`），不用"XX口诀"式命名。特殊情况（如丙戊酸钠有两个口诀）可用 `丙戊酸钠口诀` 作为 label，full 里写两个口诀。

### 5.3 口诀节点 tags

必须包含 `口诀` + 对应的药品名/分类名。

### 反模式

- ❌ 口诀写入挂载节点的 short（short 全部留空）
- ❌ 口诀用 `subclass_of` / `instance_of` 挂到分类下（必须用 `part_of`）
- ❌ 口诀归属错位（如把挂在药物下的口诀 part_of 指向分类）

## 八、迁移与重写

### 7.1 同名节点重写规则

| 字段 | 处理 |
|---|---|
| `id` | 保留原值（保持 ID 不变以免破坏边） |
| `label` | 保留原值（除非用户明确要求改名） |
| `shape`/`fill`/`stroke` | 不沿用，按新资料重新判定 |
| `tags` | 不沿用，按规则重新抽取 |
| `edges_out` | 重建（按新资料，不保留旧边除非用户指示） |
| `summary.short` | 留空（不沿用旧文本） |
| `summary.full` | 不沿用旧文本，用户未提供的部分必须留空 |

### 7.2 旧 essence → 新规范迁移映射

| 旧 essence | 新 fill | 新 stroke |
|---|---|---|
| module | cls-structure | 不填 |
| umbrella-class / strict-class | cls-classification | 有临床评价 → glow |
| medication | cls-drug | glow |
| drug | cls-drug | 不填 |
| notion（作用特点/评价） | cls-feature | 不填 |
| notion（不良反应/禁忌） | cls-adverse | 不填 |
| concept | cls-concept | 不填 |
| summary | cls-summary | 跨节 → glow |
| mnemonic | cls-mnemonic | 不填 |

迁移时同时移除 `data:` 包装、`essence` 字段、`depth` 字段，改为平铺结构。
