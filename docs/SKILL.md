# Pharma Mindmap Transcribe — 纸质思维导图 → 节点 md

把纸质思维导图照片忠实转录为符合规范的独立节点 `.md` 文件。

**开始任何转录前必须读取：**

- `docs/frontmatter.md` — 通用字段定义、OWL2 实体类型、三维度视觉编码（权威）
- `docs/RULES.md` — 药学领域特化参数：fill 取值、外观配置、渲染参数、迁移映射
- 本文件 **§零 转录铁律**（最高优先级）

> 本 SKILL 与 RULES 冲突时，以 RULES.md 为准。

---

## 零、转录铁律（最高优先级）

> 本节约束**纸质版转录**。本节与下文任何条文冲突，**以本节为准**。

### 0.1 唯一来源，逐字转录

1. **唯一来源**：节点 `label` 与 `summary.full` 的文字，唯一来源是纸质版（含手写补充）。
2. **一字不漏**：纸质版上的每一个文字、数字、字母、单位、符号，都必须写入相关节点的 `label` 或 `summary.full`；不得遗漏，不得概括。
3. **一字不改**：不改写、不润色、不换同义词、不纠错。疑似印刷错误**原样写入**，并列入交付说明的「待核对清单」（见 §0.4）。
4. **不添加**：纸质版没有的文字一律不写，包括解释、归纳、药理推断、占位符（"待补充"）、自拟的标签词和别名。即使"药理学上正确"也不行。
5. **不确定就问**：读不清的字、归属不明的内容，留空并向用户确认（Step 3），不猜。

### 0.2 允许的格式处理（不算改字）

| 处理 | 说明 |
| ---- | ---- |
| 换行、空行、`\|` block scalar | 按 §5.2 排版 |
| `**加粗**` | 仅用于纸质版的重点提示（§5.3） |
| `【框名】` | 仅限逐字取自纸质版框名（§5.2） |
| 表格 → Markdown 表格 | 保持行列结构（§5.2） |
| 标点宽度、上下标 | 视为排版，统一写一种（§5.7） |

除此之外，任何对文字的增、删、改都违反本节。

### 0.3 适用范围与例外

- **适用**：除口诀节点外，所有节点的 `label` 和 `summary.full`。
- **例外 1（口诀节点）**：口诀节点的 `summary.short` / `summary.full` 由 AI 按 §六 的规则理解后填写，**不受 §0.1 硬转录限制**；但仍不得凭空添加 ADR / 禁忌（须能在对应药物节点的 full 中找到，见 §6.4）。口诀节点的 `label` 仍须逐字转录。
- **例外 2（规则生成字段）**：`id`、`location`、`tags` 中的结构标签、`edges_out.reason` 由规则生成，不要求出现在纸质版。

### 0.4 疑似印刷错误与待核对清单

- 疑似印刷错误（错字、药名异写、数值前后矛盾、术语不规范等）：**原样写入 full**；节点文件里不加任何标记，也不暂停转录。
- 在交付说明里列「待核对清单」，每条包含：节点 / 纸质版原文 / 疑似问题 / 可能的正确写法。"可能的正确写法"只供用户判断，**不得自行替换**。
- 字迹**无法辨认**不属于"疑似印刷错误"：该处不写入，在 Step 3 向用户确认。

### 0.5 覆盖检查

- 纸质版的每个框、每段文字，都必须能在节点中找到落点。
- 交付时附「转录对照表」：纸质版的框（位置 + 起首几个字）→ 落入的节点 → 字段（label，或 full 的哪一段）。页码、页眉不转录。

## 一、核心硬性约定（违反即不合规）

### 1.1 文件名 = label（中文），id = 英文/拉丁文

- **文件名** = `label`（中文），如 `地西泮.md`
- **`id`** = 英文/拉丁文，用于图的 id 寻址、edges_out 引用
- 两者分工，不可混用

### 1.2 id 命名格式

**`id` = 前缀-节点英文名-书简写-章号-节号**

| 前缀       | fill                 | 节点类型                                     | 示例                            |
| ---------- | -------------------- | -------------------------------------------- | ------------------------------- |
| `ch-`      | `cls-structure`      | 章入口                                       | `ch-cns-y2-01`                  |
| `sec-`     | `cls-structure`      | 节入口                                       | `sec-sedative-y2-01-01`         |
| `cls-`     | `cls-classification` | 药物分类                                     | `cls-benzodiazepine-y2-01-01`   |
| `med-`     | `cls-drug`           | **重点药**（有完整药理卡片，stroke: double） | `med-diazepam-y2-01-01`         |
| `drug-`    | `cls-drug`           | **普通药**（仅提名，stroke 不填）            | `drug-triazolam-y2-01-01`        |
| `disease-` | `cls-disease`        | 疾病/症状                                    | `disease-insomnia-y2-01-01`     |
| `bio-`     | `cls-biomolecule`    | 生物实体（靶点/受体/酶）                     | `bio-gabaa-y2-01-01`            |
| `feat-`    | `cls-feature`        | 作用特点/临床评价                            | `feat-barbiturate-y2-01-01`     |
| `adr-`     | `cls-adverse`        | 不良反应/禁忌/毒性                           | `adr-barbiturate-y2-01-01`      |
| `concept-` | `cls-concept`        | 抽象概念/总论/术语                           | `concept-bioavailability-y1-04` |
| `sum-`     | `cls-summary`        | 总结/表格                                    | `sum-barbiturate-y2-01`         |
| `mem-`     | `cls-mnemonic`       | 口诀                                         | `mem-barbiturate-y2-01-01`      |

**重点药 vs 普通药判定**：纸质版中该药物有独立框且框内有正文内容 → 重点药（`med-`，stroke: double）；仅提名无独立画像 → 普通药（`drug-`，不填 stroke）。**所有药物都必须建独立节点**。

**章节后缀**：`y1`=药一、`y2`=药二、`y3`=药综、`y4`=法规，格式 `{书简写}-{章号}-{节号}`。

**id 格式例外**：章级/跨节内容没有节号，后缀只写 `{书简写}-{章号}`，包括章入口（`ch-cns-y2-01`）、跨节总结（`sum-barbiturate-y2-01`）、不隶属具体节的概念（`concept-bioavailability-y1-04`）。其余节点一律带节号。

**体系根例外**：体系根节点（漫游引擎的体系边界锚点，登记于 `src/core/config.ts` 的 `UNIVERSE_ROOTS`，如 `concept-exam-system`）的 id 不带书/章/节后缀，不适用本节格式。

### 1.3 summary 规则

| 节点类型 | `summary.short` | `summary.full` |
| -------- | --------------- | -------------- |
| 重点药 | **留空** | 纸质版逐字转录（含临床评价各框，按框名分段，见 §4.4） |
| 普通药 | **留空** | **留空**（仅提名，无独立正文框） |
| 分类节点 | **留空** | 纸质版逐字转录（分类框内的描述性文字、代表药框内容；重点分类另含临床评价各框） |
| 节入口 | **留空** | 纸质版总论逐字转录；没有总论则留空 |
| 疾病节点 | **留空** | 纸质版逐字转录（如虚线注释框）；没有则留空 |
| 总结节点 | **留空** | 纸质版逐字转录（表格写成 Markdown 表格） |
| 口诀节点 | 按 §六 填写 | 按 §六 填写（**不受 §零 约束**） |

**纸质版有的逐字写到 full，纸质版没有的不填。**

**反模式（绝对禁止）**：

- ❌ 给分类节点、普通药节点擅自加 short 描述（如"钠通道阻滞剂"）
- ❌ 按药理推断填充 full（即使"药理学上正确"也不行）
- ❌ 用占位符（"待补充""暂无内容"）
- ❌ 改写、润色、同义替换、纠正纸质版文字（见 §零）
- ❌ 把口诀写入**挂载节点**（药物/分类/节入口）的 short（口诀只建独立节点，见 §六；口诀节点自己的 short 按 §六填写）

### 1.4 stroke 规则（重点节点写 double，普通节点不填）

- **不填** = 默认 glow（呼吸光晕），**禁止显式写 `stroke: glow`（默认就是 glow，写出来冗余）**
- **`double`** = 双线边框，只给纸质版"临床用药评价"分支下的节点（重点药/有临床评价的分类）
- 分类与作用机制分支里的分类，即使列出了多个代表药，也不加 double

> **说明**：double 的判定依据是纸质版位置（是否出现在"临床用药评价"分支下），电子版不保留该分支节点；跨节大总结/表格是另一个例外，同样写 `double`（见 RULES §5.1）。

> md 填的 `stroke`（如 `double`）与默认 `glow` 是**并存叠加**（`STROKE_MERGE_MODE=coexist`，默认），不是替换：重点节点 = 默认呼吸光晕 + 双线边框。

| 节点类型                               | stroke   | 判定标准                                   |
| -------------------------------------- | -------- | ------------------------------------------ |
| 重点药（临床用药评价里有独立评价框）   | `double` | 纸质版"临床用药评价"分支下有该药物的独立框 |
| 普通药（仅提名）                       | 不填     | 仅在分类框中提名                           |
| 重点分类（临床用药评价分支下有该分类） | `double` | 临床用药评价分支下直接出现该分类名         |
| 普通分类（仅在分类与作用机制分支出现） | 不填     | 仅在"分类与作用机制"分支出现               |
| 跨节大总结/表格                        | `double` | 跨节汇总对比                               |
| 节内总结                               | 不填     | 仅本节内总结                               |

> **完整判定 + 渲染链路以 [RULES.md §5.1](./RULES.md#51-stroke-组合值) 为准**。本节是面向转录工作流的简化判定清单；如出现分歧，以 RULES.md 为准。

### 1.5 平铺结构（无 data 包装）

所有字段直接平铺，不使用 `data:` 包装。

## 二、命名规范（label / id / 父节点 / 结构框映射）

### 2.1 label 命名总原则

| 节点类型 | label 命名                          | 示例                                       |
| -------- | ----------------------------------- | ------------------------------------------ |
| 药物节点 | 药名本身，不加节名/分类前缀         | `地西泮`、`唑吡坦`、`丙戊酸钠`             |
| 分类节点 | 分类名本身                          | `苯二氮䓬类`、`巴比妥类`、`非苯二氮䓬类`   |
| 节入口   | `第X节 {节名}`                      | `第一节 镇静催眠药`、`第二节 抗癫痫发作药` |
| 章入口   | `第X章 {章名}`                      | `第一章 精神与中枢神经系统用药`            |
| 口诀节点 | 口诀内容本身（超过10字或含标点→用 `\|` block scalar 换行） | `餐后吃丙干，\n长肉出血掉头发`、`巴比索要本二受` |
| 总结节点 | 纸质版原标题                        | `根据癫痫发作类型合理选药`                 |
| 代际分类 | **加节名后缀**，避免跨节冲突        | `第一代抗癫痫发作药`（不是裸`第一代`）     |

**核心规则**：

- 药物/分类节点 label 不加节名前缀（如不写"第一节地西泮"）
- 代际分类（第一代/第二代/第三代）必须加节名后缀，否则多节都有"第一代"会冲突
- 口诀节点 label 直接写口诀内容，**超过10字或含句内标点（；,，。）→ 用 `|` block scalar 换行显示**
- 口诀节点 label 10字以内，不带标点（尽量）
- 口诀节点标签顺序：`口诀` → `节名/分类名` → `具体分类` → `代表药`
- 口诀节点 summary.short = 口诀拆解（加粗对应关键字）
- 口诀节点 summary.full = 完整知识点（加粗谐音关键字）

### 2.2 label 换行规范（`|` block scalar）

**当 label 超过10字，或含有构成独立分句的标点（`；` `，` `,` `。`），须使用 `|` block scalar 换行，使每行语义独立、显示整齐。**

```yaml
# ❌ 错误：单行过长
label: 丁苯酞，构循环，抗血栓，就是怕芹菜

# ✅ 正确：标点断句，用 | 换行
label: |
  丁苯酞，构循环，
  抗血栓，就是怕芹菜
```

| 适用场景         | 判定标准                  | 示例                                        |
| ---------------- | ------------------------- | ------------------------------------------- |
| 口诀类（超10字） | label 超过10字            | `餐后吃饼干，` + `长肉出血掉头发`           |
| 含分句标点       | 含 `；` `，` `,` `。` | `一代是个锥子；二代是个胖子`                |
| 复合语义         | 两层含义并列（即使单字）  | `儿子的朋友叫小红，得了精神病`（谐音+含义） |

**不适用**：短小精炼的 label（如 `巴比索要本二受`、`爸比不焦急`）。

### 2.3 结构框 → 节点名映射表

纸质版思维导图中的结构框，按以下规则转换为节点 label：

| 纸质版结构框             | 处理方式                                          | 节点 label 示例                              |
| ------------------------ | ------------------------------------------------- | -------------------------------------------- |
| 总论                     | 不单独建节点，写入节入口 full                     | —（写入`第一节 镇静催眠药`的 full）          |
| 分类与作用机制           | 不单独建节点，是分区标题                          | —                                            |
| 分类                     | 不单独建节点，分类节点本身就是分类                | —                                            |
| 代表药物                 | 不单独建节点，逐字写入分类节点 full（纸质版有框名才加标签）         | —                                            |
| 临床用药评价             | 不单独建节点，不拆子节点，内容合并写入重点药 full | —                                            |
| 作用特点                 | 不单独建子节点，合并写入重点药 full【作用特点】   | —                                            |
| 典型不良反应             | 不单独建子节点，合并写入重点药 full【典型不良反应】   | —                                            |
| 主要临床应用             | 不单独建子节点，合并写入重点药 full【主要临床应用】   | —                                            |
| 总结                     | 有独立内容的建节点，用纸质版原标题                | `不同种类的镇静与催眠药剂量与药理作用的关系` |
| 第一代/第二代/第三代     | 建节点，**加节名后缀**                            | `第一代抗癫痫发作药`                         |
| 抑制兴奋性/增强抑制性    | 建节点，用纸质版原标题                            | `抑制兴奋性`、`增强GABA抑制性`               |
| 抑制电压门控钠通道       | 建节点，用纸质版原标题                            | `抑制电压门控钠通道`                         |
| 对肝药酶无影响           | 建节点（手写补充特殊内容），用原标题              | `对肝药酶无影响`                             |
| 备孕或妊娠期女性癫痫用药 | 建节点（总结节点），用原标题                      | `备孕或妊娠期女性癫痫用药`                   |
| 根据癫痫发作类型合理选药 | 建节点（总结节点），用原标题                      | `根据癫痫发作类型合理选药`                   |

**判断标准**：结构框内有独立正文内容 → 建节点，用纸质版原标题；结构框只是分区标题或通用连接词 → 不建节点，内容融合到对应节点。

### 2.4 代际分类命名（防冲突）

**第一代/第二代/第三代这种通用代际名，必须加节名后缀，否则跨节会冲突。**

| ✅ 正确              | ❌ 错误  |
| -------------------- | -------- |
| `第一代抗癫痫发作药` | `第一代` |
| `第二代抗癫痫发作药` | `第二代` |
| `第三代抗癫痫发作药` | `第三代` |

**原因**：如果每一节都分为第一代/第二代/第三代，裸名"第一代"会在多个节中重复，id 也会冲突。加节名后缀后，label 和 id 都唯一。

**id 对应**：

- `第一代抗癫痫发作药` → `cls-gen1-epilepsy-y2-01-02`
- `第二代抗癫痫发作药` → `cls-gen2-epilepsy-y2-01-02`
- `第三代抗癫痫发作药` → `cls-gen3-epilepsy-y2-01-02`

### 2.5 id 命名规则

id 格式与前缀表以 **§1.2 为唯一权威**，本节不再重复维护。

**id 唯一性**：所有节点 id 必须唯一，口诀节点 id 不使用 label 首字等易重复方式。

### 2.6 父节点 ID（章/节入口）

| 层级   | id 格式                                 | 示例                    |
| ------ | --------------------------------------- | ----------------------- |
| 章入口 | `ch-{章节英文名}-{书简写}-{章号}`       | `ch-cns-y2-01`          |
| 节入口 | `sec-{节英文名}-{书简写}-{章号}-{节号}` | `sec-sedative-y2-01-01` |

**edges_out 引用**：

- 节入口 → 章入口：`part_of → ch-cns-y2-01`
- 分类/药物/口诀 → 节入口或分类节点：`instance_of` / `part_of`

### 2.7 同名冲突解决

| 冲突场景                       | 解决方式                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 多节都有"第一代/第二代/第三代" | 加节名后缀：`第一代抗癫痫发作药`                                           |
| 多节都有"临床用药评价"         | 不单独建节点，内容合并写入重点药 full                                        |
| 同一药物出现在多个分类下       | 只建一个节点，多条 `instance_of` 边                                          |
| 纸质版同一名称出现在多个分支下 | 合并为一个节点                                                               |
| 口诀内容相同但挂载不同         | 用 id 区分，label 可相同（但尽量避免）                                       |

#### 重名节点：label 加括号 + equivalent_to（跨章节同名）

当同一名称（药物、分类、机制）在**多个章节**各自建了独立节点时，不合并节点——
每个章节保留自己的节点（纸质版各章独立成框），但必须处理 label 重名与语义关系：

| 要素     | 规则                                                                       |
| -------- | -------------------------------------------------------------------------- |
| **文件名** | **不带括号**，用裸名称（如 `苯二氮䓬类.md`）                              |
| **label** | **加括号后缀区分**：`{原名}（{节名}）`（如 `苯二氮䓬类（镇静催眠药）`）   |
| **id**    | 保持各自独立、按 §1.2 规范命名（不因重名而合并）                          |
| **边**    | 组内**每对节点只写单向一条 `equivalent_to`**：按 id 排序，只有靠前写向靠后（N 个节点共 N(N−1)/2 条边，**不写双向重复**） |
| **reason** | `{节名A}中的{原名}与{节名B}中的{原名}为同一药物类别/同一药物`              |

**`equivalent_to` 语义**（frontmatter.md §3.8）：类等价，对称关系 A↔B。
用于"同一实体在知识图谱不同章节的重复表述"——它们指向同一现实对象，
但各自保留所在章节的 `part_of` / `subclass_of` 归属。

**反模式**：

- ❌ 只改 label 不加边（同名节点失去语义关联）
- ❌ 只加边不改 label（图谱上仍显示为多个同名节点，无法区分）
- ❌ 把跨章节同名节点合并为一个（会破坏各章 `part_of` 归属链）
- ❌ **双向都写 `equivalent_to`**（虽然语义对称，但会产生两条平行边；构建层按 source+target+type 去重，A→B 与 B→A 不会被合并）

**单向规则**：组内 N 个同名节点，按 id 字典序排序后，每对节点 `[i] < [j]` 只写一条 `[i] → [j]`。共 N(N−1)/2 条边，全连通无重复，任意两个同名节点间都有直接边，不用靠传递推导。

#### 括号后缀取值的优先级

1. **节名**（首选）：`苯二氮䓬类（镇静催眠药）`、`卡维地洛（抗高血压药）`
2. **机制/用途后缀**（节名无法区分时）：`苯二氮䓬类（GABAA受体）`
3. **item 字段**（同一节内重名时）：从 `location.item` 取区分值

> 同组内所有节点的括号后缀必须能**区分彼此**（同组内后缀唯一）。若 section +
> item + 机制后缀都无法区分，才考虑合并节点（回到本节表格第一行的"只建一个节点"）。

### 2.8 纸质版版式符号约定

| 纸质版版式 | 转录处理 |
| ---------- | -------- |
| 实线框 + 框名（如"作用特点"） | 对应 full 中的一段，以【框名】起头 |
| 与某节点用**虚线**相连的框 | 注释性内容：逐字并入被连节点的 full（如疾病旁的虚线注释框） |
| 用竖线 / 括号把多个框括在一起，再连到同一个目标 | 共同归属：目标节点对括入的每个节点都成立（如口诀 `part_of` 整个分类，而不是其中某个子分类） |
| "见侧图""见表" | 逐字写入 full；侧图 / 表按总结节点处理 |
| 红色细黑字 / 蓝色加粗字 | 重点提示，见 §5.3 |
| 页码、页眉 | 不转录 |

## 三、工作流（两步走：框架版 → 内容版）

### Step 1 — 读规范

读取 `docs/frontmatter.md` 与 `docs/RULES.md` 全文。

### Step 2 — 读照片（放大、多轮细读、旋转校正）

1. 读取全部思维导图照片（多张图时逐张读取）
2. **图片倒置时先旋转校正再读**（用户上传的照片经常是倒置的）
3. 文字过小或过密时放大裁剪再读
4. 记录：分支结构、各节点名称、药物画像正文、**荧光笔高亮/有色字体**、手写补充、口诀文字
5. **同一框内的内容逐字记录**，不遗漏、不概括、不改字（见 §零）；疑似印刷错误原样记录，另记一份清单（§0.4）

### Step 3 — 用户确认模糊点（不猜，附 A/B/C 候选）

识别所有读不清/有歧义的内容，**一次性列出向用户确认**。有自己推断的附上候选答案 A/B/C：

| 模糊点                                             | 候选答案                                  |
| -------------------------------------------------- | ----------------------------------------- |
| OCR 模糊的药名/术语                                | A. 候选名1 B. 候选名2 C. 其他（用户补充） |
| 归属不明的口诀                                     | A. 挂药物X B. 挂分类Y C. 挂作用特点Z      |
| **分类层级完整性**（几层子分类？每层哪些药？）     | A. 已全部识别 B. 有X层未识别 C. 用户补充  |
| **临床用药评价分支判定**（哪些节点在临床评价下？） | A. 已明确 B. 需确认 C. 用户列出           |
| **"本节不重点介绍"的分类下是否有药名**             | A. 有，需建节点 B. 无 C. 用户确认         |
| **共享节点判定**（哪些药物共享作用机制/禁忌？）    | A. 已明确 B. 需确认 C. 用户列出           |
| 荧光笔/有色字体标注的关键词                        | A. 已全部识别 B. 有X处不确定 C. 用户指出  |

> **Step 3 必查**：分类层级完整性是最高频错误点——必须确认有几层子分类、每层列出哪些药名、"本节不重点介绍"的分类下是否也有药名。

**Step 3 补充（铁律）**：

- **疑似印刷错误**：不阻塞，不在此处提问；原样写入 full，列入交付说明的「待核对清单」（§0.4）。
- **字迹无法辨认**：不写入、不猜，在本步骤提问。

### Step 4 — 第一步：建节点框架（不填 full）

**只建节点框架，不填写 `summary.full`。**

- 输出目录：`书名/章名/节名/`
- 文件名 = label（中文）
- frontmatter 含 `id/label/location/shape/fill/stroke/tags/summary/edges_out`
- `summary.full` 留空；`summary.short` 留空（**口诀节点例外**：short 是口诀拆解，框架版即按 §6.4 填写，其 full 留到内容版）
- 按 §四 结构节点原则处理
- 口诀节点独立建 md（见 §六）
- tags 先填结构标签（药品名 + 分类 + 节名）；重点提示词标签内容版再补（见 §5.4）

### Step 5 — 第一步自查（框架版检查清单）

按 §七.1 框架版检查清单逐项检查。

### Step 6 — 第一步交付（框架版 zip + 节点说明总结）

- 打包节级 zip
- 附节点说明总结（层级树、节点数、stroke 分布、double 节点列表）
- **明确告知用户：这是框架版，full 内容尚未填写，请审批节点结构**
- 用户审批通过后进入第二步；用户提出修改则修改后重新交付

### Step 7 — 第二步：填写 full 内容

**用户审批框架通过后，逐节点填写 `summary.full`。**

**⚠️ 最高优先级铁律：不确定的内容留空，问用户，绝对不编。** 即使"药理学上正确"也不行，纸质版没有就是没有。

- 逐节点读取纸质版原文，填写 full
- 重点药的临床评价内容按 §4.4 规则，合并写入 full，用纸质版框名（如 `【作用特点】`、`【典型不良反应】`）分段
- **full 中纸质版的重点提示（红色细黑字 / 蓝色加粗字）必须用 `**加粗**` 标注**，加粗范围以纸质版着色范围为准（见 §5.3）
- **分类节点 full 核对**：分类框内有描述性文字的必须填写（如"碱化尿液药：与促进尿酸排泄药合用，提高降尿酸效果"），没有的留空
- **节入口 full 核对**：纸质版有总论的写入节入口 full，没有的留空
- **共享节点 full 核对**：共享作用机制/禁忌的内容写入共享节点 full，不重复写入每个药物
- 严格遵守 §1.3：纸质版有的写，没有的不擅自添加
- 补全 tags：full 中每个加粗词都列入 tags，并按所在框名加前缀（见 §5.4）

### Step 8 — 第二步自查（内容版检查清单）

按 §七.2 内容版检查清单逐项检查。

### Step 9 — 最终交付（内容版 zip + 节点说明总结）

- 重新打包节级 zip
- 更新节点说明总结（含 full 填写情况、加粗关键词统计、tags 统计）

#### 交付物格式

**交付物 1：节级 zip**

- 命名：`第X节 {节名}.zip`，如 `第一节 镇静催眠药.zip`
- **文件夹命名直接用"第X节 {节名}"，不带章节前缀**（如不写"第一章 第一节 镇静催眠药"）
- 用 `unzip -l` 反查文件数，确认与节点总数一致

**交付物 2：节点说明总结**

| 项目          | 内容                                      |
| ------------- | ----------------------------------------- |
| 节名          | 如「第一节 镇静催眠药」                   |
| 节点总数      | 用 `unzip -l` 反查的实际文件数            |
| 层级结构      | 节入口 → 分类 → 子分类/药物/口诀 的层级树 |
| double 节点   | 列出所有 stroke: double 的节点            |
| full 填写情况 | 哪些节点填了 full、哪些留空               |
| 口诀归属      | 每条口诀 part_of 指向哪个节点             |
| 已知未完成项  | 哪些节点 full 未填、哪些关系待确认        |

**交付物 3：待核对清单**（§0.4）

| 节点 | 纸质版原文 | 疑似问题 | 可能的正确写法（仅供判断） |
| ---- | ---------- | -------- | -------------------------- |

**交付物 4：转录对照表**（§0.5）

| 纸质版框（位置 + 起首几字） | 落入节点 | 字段 |
| --------------------------- | -------- | ---- |

**交付物 5：加粗 / tags 统计**：各节点 full 的加粗词数与 tags 数；**仍超过 20 字的 tag** 单独列出（§5.4.1 已要求 ≤20 字，超出说明精简未完成）。

## 四、结构节点原则（完全以纸质版为准 + 电子版去冗余）

### 4.1 核心原则

1. **完全以纸质版为准**：纸质版有框 → 电子版有对应节点，不随意删减层级
2. **认清纸质版局限性**：纸质版受纸张大小限制，需要"分类与作用机制""临床用药评价"等结构节点分区；电子版不受此限制
3. **通用结构词不单独建空壳节点**：分类、总论、代表药物、临床用药评价、作用机制、典型不良反应、总结——能融合就融合
4. **必须单独建的加前缀/后缀**：纸质版中该框有独立正文内容时，保留为单独节点，但 label 必须加具体药名/分类名
5. **纸质版同名重复框合并**：同一名称出现在多个分支下（如巴比妥类同时在"分类"和"临床用药评价"下），电子版合并为一个节点

### 4.2 通用结构词融合清单

| 通用结构词   | 处理方式                                                                    |
| ------------ | --------------------------------------------------------------------------- |
| 总论         | 写入节入口节点的 `summary.full`                                             |
| 分类         | 不单独建，分类节点本身就是分类                                              |
| 代表药物     | 逐字写入分类节点的 `summary.full`（纸质版有框名才加标签）                                     |
| 临床用药评价 | **不单独建，不拆子节点**，其下内容合并写入对应重点药/分类的 full（见 §4.4） |
| 作用机制     | 写入分类/药物节点的 `summary.full`                                          |
| 总结         | 节内总结可建节点（`cls-summary`），跨节大总结建节点并加 double              |

### 4.3 分类层级完整性（禁止药物直挂节入口）

**纸质版中每一层分类框都必须建对应节点，药物必须挂到所属分类下。**

| 规则       | 说明                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| 逐层建节点 | 有几个子分类就建几个分类节点，即使"本节不重点介绍"也必须建                   |
| 药物挂分类 | 所有药物节点的 `edges_out` 必须 `instance_of` 指向所属分类，禁止直接挂节入口 |
| 不遗漏药名 | 分类框中列出的所有药名都必须建独立节点                                       |
| 口诀挂分类 | 分类级口诀 `part_of` 指向该分类节点                                          |

**正模式：**

```
第八节 中枢肌松药 (节入口)
├── 苯二氮䓬类 (分类，本节不重点介绍，但仍需建节点)
│   ├── 三唑仑 (普通药，instance_of → 苯二氮䓬类)
│   └── 艾司唑仑 (普通药，instance_of → 苯二氮䓬类)
└── 非苯二氮䓬类 (分类)
    ├── 乙哌立松 (重点药，instance_of → 非苯二氮䓬类)
    └── 氯唑沙宗 (普通药，instance_of → 非苯二氮䓬类)
```

### 4.4 临床用药评价：合并写入重点药 full（不拆子节点）

**临床用药评价分支下的内容，不拆分子节点，全部合并写入对应重点药/重点分类的 `summary.full`，各框按纸质版框名分段。**

| 规则 | 说明 |
| ---- | ---- |
| 不拆子节点 | 不建 `{药名}作用特点`、`{药名}典型不良反应` 等子节点 |
| 合并写入 full | 所有临床评价内容写入重点药/重点分类的 `summary.full` |
| 框名原样 | 分段标签逐字取自纸质版框名（如作用特点、典型不良反应、适应证、药物相互作用、临床应用注意），不得改名、不得归并为"标准名" |
| 不重新归类 | 纸质版把内容放在哪个框，就写在哪一段；不按药理意义重新分段 |
| 格式清楚 | 标签分段，段落间空行，编号 (1)(2)(3) **每个编号换行** |

**full 格式示例（叶酸）：**

```yaml
summary:
  full: |
    【适应证】
    (1) 口服0.4mg规格：①预防**胎儿先天性神经管畸形**；②妊娠期、哺乳期妇女预防用药。
    (2) 口服5mg规格：①各种原因引起的叶酸缺乏及叶酸缺乏所致的**巨幼细胞贫血**；……
    (3) 注射剂：用于各种原因引起的叶酸缺乏及叶酸缺乏所致的**巨幼细胞贫血**。

    【药物相互作用】
    (1) 营养性巨幼细胞贫血常合并缺铁，应同时补充铁剂、蛋白质和其他B族维生素。
    (2) 恶性贫血及疑有维生素B12缺乏的患者，**需与维生素B12同服**，不单独使用叶酸，否则增加神经系统症状。
```

**反模式（绝对禁止）**：

- ❌ 把重点药拆成"作用特点""典型不良反应"等子节点
- ❌ 把纸质版的框名改成标准名（"适应证"写成【临床应用】、"药物相互作用"写成【相互作用】）
- ❌ full 里不写标签，内容堆在一起不分段
- ❌ (1)(2)(3) 不换行，挤在一行

### 4.5 药物节点处理（所有药物都建独立节点）

| 类型       | 前缀    | stroke   | summary.full       | 判定标准                   |
| ---------- | ------- | -------- | ------------------ | -------------------------- |
| **重点药** | `med-`  | `double` | 有完整临床评价内容 | 纸质版有独立框且框内有正文 |
| **普通药** | `drug-` | 不填     | 留空               | 仅提名，无独立正文框       |

- 纸质版一个框里列出多个药名（如"长效：苯巴比妥、巴比妥"），每个药各建独立节点，不合并
- 普通药节点 `edges_out` 写 `instance_of → 父分类节点`
- 分类节点的 `summary.full` 仍逐字保留纸质版代表药框的内容，作为该分类下药物的概览清单

### 4.6 多父节点药物（多条 edges_out）

**当一个药物同时出现在多个分类分支下时（如按代分类 + 按作用机制分类），只建一个节点，但 `edges_out` 写多条边。**

```yaml
edges_out:
  - target: cls-gen2-y2-01-02
    type: instance_of
    reason: 第二代抗癫痫发作药的代表药物
  - target: cls-nmda-y2-01-02
    type: instance_of
    reason: 抑制NMDA型谷氨酸受体的代表药物
```

### 4.7 总结节点合并规则

**当纸质版有一个总标题（如"根据癫痫发作类型合理选药"），其下包含多个子类型且每个子类型涉及多个药物时，合并为一个总结节点，不拆分。**

| 规则           | 说明                                                          |
| -------------- | ------------------------------------------------------------- |
| 合并为一个节点 | 总标题作为一个 `cls-summary` 节点，不拆成多个子类型节点       |
| 挂节入口       | `edges_out` 为 `part_of → 节入口`，不连大量指向每个药物的边 |
| 内容写 full    | 各子类型内容写入 `summary.full`，用 `【子类型】` 标签分段     |
| short 留空     | 总结节点的 short 永远不写                                     |

**反模式**：

- ❌ 把"根据癫痫发作类型合理选药"拆成"局灶性癫痫""失神发作"等多个子节点
- ❌ 给总结节点连大量指向每个药物的边（旧写法称 `has_instance`，现已不属于 5 种合法边类型，且会导致图混乱）

### 4.8 共享节点（多药共用作用机制/禁忌）

**当纸质版多个药物放在同一框内、共享作用机制或禁忌时，建独立共享节点，不重复写入每个药物的 full。**

| 规则      | 说明                                                                                         |
| --------- | -------------------------------------------------------------------------------------------- |
| 节点命名  | 必须加分类前缀，如"促进尿酸排泄药作用机制""抑制尿酸生成药禁忌"，**禁止裸用**"作用机制""禁忌" |
| fill      | 共享作用机制 → `cls-concept`；共享禁忌 → `cls-adverse`                                       |
| stroke    | 不填                                                                                         |
| edges_out | `part_of` 同时指向所有共享该内容的药物节点                                                   |
| full      | 填写纸质版共享原文，重点关键词加粗                                                           |

**示例**：苯溴马隆和丙磺舒共享作用机制和禁忌 → 建"促进尿酸排泄药作用机制"和"促进尿酸排泄药禁忌"两个共享节点，各用 `part_of` 同时指向苯溴马隆和丙磺舒。

**反模式**：

- ❌ 把共享内容重复写入每个药物的 full
- ❌ 共享节点裸用"作用机制""禁忌"命名（让人摸不着头脑）
- ❌ 共享节点用 `instance_of` 指向药物（必须用 `part_of`）

### 4.9 其他常见错误

| 错误场景                                                        | 正确做法                                                |
| --------------------------------------------------------------- | ------------------------------------------------------- |
| 机制分类节点只写代表药在 full，没给代表药加边                   | 代表药用 `instance_of` 边指向分类                       |
| 药物级口诀挂到分类节点上                                        | 口诀挂载以纸质版为准，药物级口诀 `part_of` 指向药物节点 |
| 纸质版同一框里的多个内容被拆成多个节点                          | 同一框里的内容合并为一个节点，不拆分                    |
| 机制分类下的子分类（如"激动GABAA受体"下的"苯二氮䓬类"）没建节点 | 纸质版中有明确子分类的，建子分类节点                    |

## 五、字段制作规范

### 5.0 文件格式（必须有 `---`）

**每个节点 `.md` 文件必须是标准 YAML frontmatter 格式，开头和结尾都必须有 `---` 分隔符，缺一不可。**

```markdown
---
id: med-diazepam-y2-01-01
label: 地西泮
fill: cls-drug
stroke: double
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
tags:
  - 地西泮
  - 苯二氮䓬类
summary:
  short:
  full: |
    【作用特点】...
edges_out:
  - target: cls-benzodiazepine-y2-01-01
    type: instance_of
    reason: 属于苯二氮䓬类
---
```

**反模式（绝对禁止）**：

- ❌ 开头没有 `---`（YAML 无法解析）
- ❌ 结尾没有 `---`（frontmatter 不闭合）
- ❌ `---` 前后有多余空行或空格
- ❌ 用 `...` 或其他符号代替 `---`

### 5.1 shape / fill

- **fill**（必填）：药学顶层类 IRI，决定背景色 + 默认形状 + 默认边框。取值见 RULES §二
- **shape**（可选）：OWL2 实体类型，不填或 `auto` 时用 fill 的默认形状

### 5.2 summary.full 格式

> 内容受 **§零 铁律**约束（口诀节点除外）。本节只规定**排版**，不规定内容。

- 必须用 `full: |`（block scalar）。
- **分段**：纸质版中每个有框名的框，对应一段，以 `【框名】` 起头。框名**逐字取自纸质版**，不改名、不合并同义框名、不自拟。例：纸质版写"适应证"，就写【适应证】。
- **无框名的框**（如分类框里直接列药名的框）：不加标签，直接逐字写入。
- **同名的多个框**（如同一药物下出现两个"作用特点"框）：合并为一段，按纸质版顺序连续排列，纸质版自带的编号照抄，不重编。
- **段落之间必须空行**。
- **编号**：纸质版的 (1)(2)(3) 每个编号单独一行；句中的 ①②③ 不换行，原样保留。
- **表格**：写成标准 Markdown 表格，保持原行列结构。纸质版的合并单元格，在被合并的每一行重复内容；**表头不加粗**（渲染自带，且 `**` 在本规范里表示重点提示，见 §5.3）；纸质版没有符号的单元格，原样留空，不补 ✓ / ✗。
- **禁止**：整段不换行、`#` 标题、HTML 标签。

**纸质版常见框名**（仅供对照，以纸质版为准）：总论、作用机制、作用特点、典型不良反应、禁忌、药物相互作用、适应证、主要临床应用、临床应用注意、代表药物。

### 5.3 重点提示：加粗规则

纸质版有两类重点提示（均为 10 号字）：

| 类型 | 纸质版外观 | 含义 | 转录 |
| ---- | ---------- | ---- | ---- |
| 关键词 | 红色、细黑体 | 普通重点提示词 | `**加粗**` |
| 口诀对应关键词 | 蓝色、粗体 | 与某条口诀对应的关键词 | `**加粗**` |

荧光笔、下划线等其他视觉强调：同样加粗，并在交付说明中注明，由用户确认归类。

**规则**：

1. 只加粗纸质版上带有上述提示的文字，不自行判断重点。
2. **加粗范围 = 纸质版着色范围**，不扩大、不缩小。
3. 同一词多次出现，每次都加粗。
4. **加粗的词就是 tags 必须列明的词**（见 §5.4）。
5. 表头不加粗（避免与重点提示混淆）。
6. 口诀节点 `short` 里的加粗是谐音标注，不适用本节（见 §6.4）。
7. 红色与蓝色目前都写成 `**…**`，文本里不记录色别（待定，见变更说明）。

### 5.4 tags 规则

tags 由两部分组成，顺序固定：**结构标签** → **重点提示词标签**。

#### 一、三铁律

1. **加粗即列明（覆盖完整）**：full 中每个加粗词都必须被 tags 覆盖——tag 至少要包含该加粗词的**核心关键词**。tag 可以是加粗词的精简提炼（如整句加粗时只保留「作用机制」核心），不要求逐字复制整段加粗。
2. **不杜撰**：除结构标签外，tags 中每个词都必须来自 full 的加粗范围（精简提炼时不得引入加粗范围外的新词）。**full 里的加粗范围严格以纸质版为准，tags 不得反向要求修改 full 的加粗**。
3. **写法一致**：tag 的文字与 full 里的写法一致（字符规则见 §5.7）；药名、分类名与对应节点的 label 写法一致。

#### 二、结构标签（不要求出现在 full 里）

| 类别 | 内容 | 适用节点 |
| ---- | ---- | -------- |
| 名称 | 节点自身的 label（药品名/分类名） | 药物、分类 |
| 归属分类 | 直接上级分类名 | 药物、子分类 |
| 节名 | 所属节的主题名（如"抗癫痫发作药"） | 药物、分类、疾病 |
| 下级与代表药 | 子分类名、代表药名 | 分类 |
| 口诀 | `口诀` + 药品名/分类名，顺序见 §6.3 | 口诀节点 |

#### 三、重点提示词标签（取自 full 的加粗词）

前缀 = 该加粗词所在的【框名】。**以下前缀为 v1 草案，类别待用户定稿**：

| full 中的框名 | tag 前缀 | 示例 |
| ------------- | -------- | ---- |
| 作用机制 | `药理作用：` | `药理作用：松弛平滑肌` |
| 作用特点 | `特点：` | `特点：起效慢` |
| 适应证、主要临床应用 | `适应症：` | `适应症：巨幼细胞贫血` |
| 典型不良反应 | `ADR：` | `ADR：体位性低血压` |
| 禁忌 | `禁忌：` | `禁忌：铁超负荷` |
| 药物相互作用 | `相互作用：` | `相互作用：需与维生素B12同服` |
| 临床应用注意 | `用药注意：` | `用药注意：应每日补充铁剂` |
| 总论、无框名 | 无前缀 | `自限现象` |

同一词在不同框中出现，按框名分别加前缀（如 `ADR：肝毒性` 与 `禁忌：肝毒性` 可并存）。

#### 四、抽取流程

1. 扫 full，抽出所有 `**…**`。
2. 去掉 `**`，同前缀同词去重。
3. 按所在【框名】加前缀。
4. 与结构标签合并（结构标签在前）。
5. **长度控制**：tag 超过 **20 字**时必须精简——保留「前缀：核心关键词」，去掉解释性从句、剂量数字、括号补充（见 §5.4.1）。

#### 五、tag 长度上限与精简规则（20 字）

**硬约束**：单个 tag **不得超过 20 字**（中文字符 + 标点 + 拉丁字母均按 1 字计）。

**关键原则**：**full 里的加粗范围原版不变，只精简 tags**。

- ❌ 绝对不允许为了迁就短 tag 而修改 full 的加粗范围——加粗以纸质版为准（§0.1 / §5.3）。
- ✅ 应当缩短 tag 本身：从整句提炼核心关键词。

| full 的加粗（不动）                                    | tag（精简到 ≤20 字）         |
| ------------------------------------------------------ | ---------------------------- |
| **竞争性抑制纤维蛋白与纤溶酶的结合，阻断纤维蛋白凝块的溶解** | `药理作用：竞争性抑制纤溶酶结合` |
| **维生素K在绿色蔬菜、植物油中含量丰富，是肝脏合成凝血因子Ⅱ、Ⅶ、Ⅸ、Ⅹ必不可少的辅因子** | `药理作用：凝血因子合成辅因子` |
| **作用于粒系造血祖细胞，促进其增殖、分化，并可增加粒系终末分化细胞功能** | `药理作用：促进粒系造血祖细胞增殖与分化` |
| **口服血小板生成素受体激动剂(TPO-RA)**（21 字）          | `TPO-RA`                     |

**精简方法**：按以下顺序删减，保留到 20 字以内：

1. 删解释性从句（"，主要用于…"、"，产生止血作用"）
2. 删剂量与数字细节（"最大剂量可达600mg/d" → "最大剂量600mg/d"）
3. 删括号补充（"（如 ACEI 或 ARB）"、"（非磺酰胺结构，可作为…）"）
4. 冗长的机制全称 → 通用缩写（如"口服血小板生成素受体激动剂(TPO-RA)" → "TPO-RA"）
5. 前缀 + 核心关键词已足够时，删去所有从句

> 交付说明中的「加粗 / tags 统计」只需列出仍超 20 字的 tag；已精简的不必再上报。

> 本规则**没有数量上限**，也**不要求**每个重点药必有"药理作用"tag：full 里没有加粗的药理作用，就不写。口诀节点的 tags 按 §6.3，不适用本节。

**示例（叶酸）**

```yaml
tags:
  - 叶酸                      # 名称（结构标签）
  - 维生素                    # 归属分类（结构标签）
  - 抗贫血药                  # 节名（结构标签）
  - 适应症：胎儿先天性神经管畸形   # 【适应证】中的加粗词
  - 适应症：巨幼细胞贫血
  - 相互作用：需与维生素B12同服   # 【药物相互作用】中的加粗词
```

### 5.5 edges_out 填写规则

#### 边方向铁律：每个节点自管自己的 edges_out

| 关系                   | 由谁写         | type          |
| ---------------------- | -------------- | ------------- |
| 类-类层级（子类→父类） | 子类写         | `subclass_of` |
| 药物→分类              | 药物写         | `instance_of` |
| 节入口→章入口          | 节入口写       | `part_of`     |
| 口诀→主知识节点        | **口诀节点**写 | `part_of`     |
| 总结节点→节入口        | 总结节点写     | `part_of`     |

**禁止**：

- ❌ 父节点写 edges_out 指向子节点
- ❌ 用 `subclass_of` 表达 `part_of`
- ❌ 双向边正反都写

#### 补充边方向约定（顶层分类 / 疾病 / 章入口）

| 关系 | 由谁写 | type | 状态 |
| ---- | ------ | ---- | ---- |
| 子分类 → 父分类 | 子分类写 | `subclass_of` | 已定 |
| 顶层分类 → 节入口 | 分类写 | `part_of` | 已定 |
| 疾病 → 节入口 | 疾病写 | `part_of` | **暂定**：5 种合法边没有"治疗"关系，疾病与药物的对应关系暂不建边 |
| 章入口 → 书入口 / 体系根 | 章入口写 | `part_of` | 有书入口时指向它；没有则 `edges_out: []` |

#### reason 措辞规范

- **必填**，不可空
- 必须包含具体对象（药名/分类名），不能是"治疗""相关"等空泛词
- 必须能独立成句

**禁止的层位词占位**（按用户样例确立）：

| 禁止 | 改写 | 规则 |
|---|---|---|
| `属于该书籍` / `属于该教材` | `属于 {book}` | 必须用具体书籍名 |
| `属于该章` | `属于 {chapter}` | 必须用具体章节名（去掉"第N章"层级编号） |
| `属于第九章 抗感染药物` / `属于第九章 抗感染药物（...）` | `属于抗感染药物` | 已有 `属于 {X}` 前缀时，`X` 内部不能含"第N章"层位词 |
| `属于第九章抗感染药物`（无空格变体） | `属于抗感染药物` | 无空格分隔同等适用 |
| `XXX属于第N章 X` / `属于第N章 X（修饰）` | `XXX属于X` / `属于X` | 句子中嵌入的"第N章"+末尾括号修饰一起去掉 |
| `第四章消化系统用药的第一节` | `消化系统用药` | 层位词包裹主体：第N章+主体+的第N节 → 主体 |
| `第五节中枢镇痛药 的临床用药评价` | `中枢镇痛药 的临床用药评价` | 第N节+主体+(的+属性) → 主体+(的+属性) |
| `第二节的第一亚类` / `第二节的总结节点` | `第一亚类` / `总结节点` | 第N节+的+抽象属性 → 抽象属性 |
| `属于第N章 X 下的第N节` | `属于X`(Y) | "第N章"和"下的第N节"两个层位词都去掉 |
| `XXX 属于第N节 Y` | `属于Y` | 句中嵌入的"第N节"+前导词一起去掉 |
| `第一章的一部分` / `第一章 精神与中枢神经系统用药的一部分` | `精神与中枢神经系统用药的一部分` | "第N章"层位词去掉 |
| `第一节镇静催眠药的总结` | `镇静催眠药的总结` | "第N节"层位词去掉 |
| 跳过（不算违规） | - | `属于第二代抗精神病药` 中的代次信息保留 |
| 跳过（不算违规） | - | `XX下的YY` 等"非第N下的"自然表述保留 |

> 规则外的"层位描述"（如 `第二节的总结节点`、`第五节X 的临床用药评价`、`第一章心血管系统用药的第二节`）保留为后续 TODO，由 `npm run audit` 单独扫描。

### 5.6 location 字段

```yaml
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
  item: 一、（一）① # 可选
```

- 知识节点的 label 不附目录序号（如药物节点写「地西泮」，不写「第一节 地西泮」）
- 结构节点（节入口）的 label 可包含序号（如「第一节 镇静催眠药」）
- location 只是来源坐标，不决定 fill/shape，也不决定边类型

### 5.7 字符统一规则

**原则**：文字、数字、字母、单位**必须与纸质版一致**；标点宽度和上下标视为**排版**，统一写一种。

| 项目 | 规则 | 示例 |
| ---- | ---- | ---- |
| 汉字 | 与纸质版一致，不换字形 | — |
| 数字、字母、单位 | 与纸质版一致；一律半角 | `0.3g`、`1mg/d`、`PSA`、`CYP3A4` |
| 上下标 | 平排，不用上下标字符 | α₁→`α1`、B₁₂→`B12`、GABA_A→`GABAA` |
| 中文语境标点 | 全角 | `，` `。` `；` `：` `、` `“”` |
| 括号 | 正文括号全角 `（）`；编号括号半角 `(1)` | `(1)`、`（最常见的病因是缺铁）` |
| 范围号 | 统一为 `～` | `3～6个月`、`100～130g/L` |
| 连字符 | 半角 `-`；同一概念与节点 label 写法一致 | `Q-T`、`5α-还原酶抑制剂` |
| 圈号、罗马数字 | 视为文字，原样 | `①②③`、`Ⅰ`、`Ⅱ` |
| 空格 | 中文与数字/字母之间不加空格；编号 `(1)` 后加一个空格 | `(1) 口服4～5日后` |

照片里难以分辨的符号（如 `~` 与 `～`、半角与全角括号），按本表统一写法，不属于"疑似印刷错误"。

## 六、口诀处理（独立节点）

口诀**只建独立节点**（`fill: cls-mnemonic`），不写入挂载节点的 short。

### 6.1 口诀归属：完全以纸质版挂载位置为准

| 纸质版挂载位置  | 电子版 part_of 指向 |
| --------------- | ------------------- |
| 挂在具体药物下  | 该药物节点          |
| 挂在分类下      | 该分类节点          |
| 挂在节/章入口下 | 该节/章节点         |

### 6.2 口诀节点 label

直接写口诀内容本身。**超过10字或含句内标点（`；` `,` `，` `。`）→ 用 `|` block scalar 换行**（见 §2.2）。

同一药品/分类有多个口诀时，拆成多个节点，各用各的 label。

### 6.3 口诀节点 tags

必须包含 `口诀` + 对应的药品名/分类名。标签顺序固定：`口诀` → `节名/分类名` → `具体分类` → `代表药`。

示例（激动GABAA受体口诀）：

```yaml
tags:
  - 口诀
  - 抗癫痫发作药
  - 激动GABAA受体
  - 苯巴比妥
  - 加奈索酮
  - 苯二氮䓬类
```

### 6.4 口诀节点 summary 格式

> **本节不受 §零 铁律约束**：口诀节点的 short / full 由 AI 按本节规则理解后填写。但 ADR / 禁忌仍须按对应药物节点 full 提取，不得凭空添加。

- **short** = 口诀拆解：按口诀原文顺序，谐音关键字加粗，**药名不加粗**，每行与 label 换行对齐
- **full** = 完整知识点：知识类别 + 完整药理/临床内容，谐音关键字加粗，关键临床术语（ADR、禁忌）**按对应药物节点 full 提取**

**short 格式规则**：

- 谐音字对应关键字 → `**加粗**`
- 长药名（3字以上）**不加粗**，直接跟在谐音后面
- 短药名可加粗以示强调
- 换行与 label 保持语义对齐

**full 格式规则**：

- 知识类别（药物分类/药理机制）先行
- 谐音关键字加粗
- ADR/禁忌从对应药物节点 full 提取，不重复造词
- 禁止在 full 中加入 full 里没有的 ADR/禁忌

示例1（`巴比索要本二受`，与已有节点文件一致）：

```yaml
summary:
  short: 苯**巴比**妥 加奈**索**酮 要 **苯二**氮䓬类 激动GABAA**受**体
  full: |
    抗癫痫药，作用机制激动GABAA**受**体：**苯**巴比妥、加奈**索**酮、**苯二**氮䓬类。
```

示例2（`AMPA-吡仑帕奈`）：

```yaml
summary:
  short: |
    **AMPA-吡仑帕奈**
  full: |
    抗癫痫药，抑制AMPA型谷氨酸受体：**吡**仑**帕**奈。
```

示例3（`吗啡是个大坏蛋，不呼吸、不心跳、不让小号，还不让宝宝`）：

```yaml
summary:
  short: |
    **吗啡**是个大坏蛋，
    **不呼吸**、**不心跳**、不让**小号**，还不让**宝宝**
  full: |
    阿片生物碱类镇痛药，**吗啡**典型不良反应与禁忌：抑制**呼吸**、心血管系统扩血管降血压、膀胱括约肌张力升高导致**排尿困难尿潴留**、临产妇及哺乳期妇女禁用（影响**宝宝**）、支气管哮喘、肺源性心脏病者禁用。
```

### 6.5 short 加粗粒度规范

| 类型           | 加粗规则   | 示例                             |
| -------------- | ---------- | -------------------------------- |
| 谐音关键字     | `**加粗**` | `**笨**`=苯、`**本二**`=本二氮卓 |
| 长药名（≥3字） | **不加粗** | 苯巴比妥、加奈索酮               |
| 短药名（≤2字） | 可加粗     | `**地西泮**`                     |
| 括号补充说明   | 不加粗     | `（COX-2）`                      |

**反模式**：

- ❌ 口诀写入挂载节点的 short（short 全部留空）
- ❌ 口诀用 `subclass_of` / `instance_of` 挂到分类下（必须用 `part_of`）
- ❌ 口诀归属错位（如把挂在药物下的口诀 part_of 指向分类）
- ❌ short 中把长药名逐字加粗（如 `**笨****苯**比**妥**`）
- ❌ short 中加入 full 里没有的 ADR/禁忌

## 八、迁移与重写

### 8.1 同名节点重写规则

| 字段                    | 处理                                                           |
| ----------------------- | -------------------------------------------------------------- |
| `id`                    | 保留原值（保持 ID 不变以免破坏边）                             |

| `summary.full`          | 不沿用旧文本，用户未提供的部分必须留空                         |
