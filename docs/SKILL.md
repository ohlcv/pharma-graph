# Pharma Mindmap Transcribe — 纸质思维导图 → 节点 md

把纸质思维导图照片忠实转录为符合规范的独立节点 `.md` 文件。

**开始任何转录前必须读取：**
- `docs/frontmatter.md` — 通用字段定义、OWL2 实体类型、三维度视觉编码（权威）
- `docs/RULES.md` — 药学领域特化参数：fill 取值、外观配置、渲染参数、迁移映射

> 本 SKILL 与 RULES 冲突时，以 RULES.md 为准。

---

## 一、关键硬性约定（违反即不合规）

### 1.1 文件名 = label（中文）

- **文件名** = `label`（中文），如 `地西泮.md`、`苯二氮䓬类.md`
- **`id`** = 英文/拉丁文，用于图的 id 寻址、edges_out 引用
- 两者分工，不可混用

### 1.2 id 命名格式

**`id` = 前缀-节点英文名-书简写-章号-节号**

> **前缀基于 fill 分类设计**，每个前缀对应一个 fill 值，语义一致。

| 前缀 | fill | 节点类型 | 示例 |
|---|---|---|---|
| `sec-` | `cls-structure` | 组织结构（书/篇/章/节入口） | `sec-sedative-y2-01-01` |
| `cls-` | `cls-classification` | 药物分类 | `cls-benzodiazepine-y2-01-01` |
| `med-` | `cls-drug` | **重点药**（有完整药理卡片，stroke: glow） | `med-diazepam-y2-01-01`、`med-zolpidem-y2-01-01` |
| `drug-` | `cls-drug` | **普通药**（仅提名，stroke: auto） | `drug-trizolam-y2-01-01` |
| `disease-` | `cls-disease` | 疾病/症状 | `disease-insomnia-y2-01-01` |
| `bio-` | `cls-biomolecule` | 生物实体（靶点/受体/酶） | `bio-gabaa-y2-01-01`、`bio-cyp3a4-y2-01` |
| `feat-` | `cls-feature` | 作用特点/临床评价/选药原则 | `feat-barbiturate-y2-01-01` |
| `adr-` | `cls-adverse` | 不良反应/禁忌/毒性 | `adr-barbiturate-y2-01-01` |
| `concept-` | `cls-concept` | 抽象概念/总论/术语 | `concept-bioavailability-y1-04` |
| `sum-` | `cls-summary` | 总结/表格 | `sum-barbiturate-y2-01` |
| `mem-` | `cls-mnemonic` | 口诀 | `mem-barbiturate-y2-01-01` |

> **重点药 vs 普通药判定**：纸质版中该药物有独立框且框内有正文内容 → 重点药（`med-`，stroke: glow）；仅提名无独立画像 → 普通药（`drug-`，不填 stroke）。**所有药物都必须建独立节点**（详见 §4.5），普通药同样建节点，区别仅在于前缀和内容完整度。

**章节后缀**：`y1`=药一、`y2`=药二、`y3`=药综、`y4`=法规，格式 `{书简写}-{章号}-{节号}`。

### 1.3 summary 字段禁止 AI 擅自填充（short 和 full 都适用）

- **`full`**：仅当用户主动提供文本时写入；缺用户资料时 `full` 完全不写（YAML 解析为 null，UI 隐藏展开按钮）
- **`short`**：同样禁止"按药理推断"填充。纸质版上有荧光笔标注/关键词的，重组为 short；纸质版上没有的，**short 留空**，不编造、不推断
- 禁止"按药理推断"填充、禁止占位符（"待补充"）、禁止模板套用
- **核心原则**：纸质版上有的内容写到 full 里，纸质版上没有的内容一律不填，short 空着

> **常见错误**：给分类节点（如"抑制GABA氨基转移酶"）、普通药节点（如"苯妥英钠"）擅自加 short 描述（如"钠通道阻滞剂"），这些都是纸质版上没有的内容，必须留空。

### 1.4 视觉优先级

- **shape / stroke 不填时由 fill 决定**，显式填写时覆盖 fill 默认值（最高优先级）
- 多数节点不填 shape/stroke，由 fill 默认配置即可；只有需要"显式几何形状"或"流光/光晕边框"时才填
- shape 是 OWL2 实体类型（6 种 + auto），每个对应一个固定几何形状，详见 RULES §二

### 1.5 平铺结构（无 data 包装）

所有字段直接平铺，不使用 `data:` 包装：

```yaml
---
id: med-diazepam-y2-01-01
label: 地西泮
shape: auto
fill: cls-drug
stroke: glow
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
tags:
  - 地西泮
  - 苯二氮䓬类
summary:
  short: "**苯二氮䓬类长效代表药**；抗焦虑、镇静催眠、抗癫痫。"
  full: |
    【药理作用】...
edges_out:
  - target: cls-benzodiazepine-y2-01-01
    type: instance_of
    reason: 属于苯二氮䓬类
---
```

## 二、工作流（按序执行）

### Step 1 — 读规范

读取 `docs/frontmatter.md` 与 `docs/RULES.md` 全文。字段定义、shape 取值（OWL2 实体类型 → 固定几何形状）、fill 取值、stroke 渲染参数，全部以这两份文档为准。

### Step 2 — 读照片（放大、多轮细读）

1. 下载/读取全部思维导图照片（多张图时逐张读取）
2. 文字过小或过密时放大裁剪再读，必要时按区域细读
3. 记录：分支结构、各节点名称、药物画像正文、荧光笔高亮、手写补充、口诀文字

### Step 3 — 用户确认模糊点（不猜）

识别所有读不清/有歧义的内容，**一次性列出向用户确认**。如果对某个模糊点有自己的推断（不是完全不知道，而是不确定），**附上候选答案 A/B/C 供用户选择**，不要只抛问题：

| 模糊点 | 候选答案 |
|---|---|
| OCR 模糊的药名/术语 | A. 候选名1  B. 候选名2  C. 其他（用户补充） |
| 归属不明的口诀 | A. 挂药物X  B. 挂分类Y  C. 挂作用特点Z |
| 手写补充的含义与位置 | A. 写入short  B. 写入full  C. 独立建节点 |
| 命名分歧（如「枸橼酸托法替布 vs 托法替布」） | A. 全称  B. 简称  C. 用户指定 |
| **分类层级完整性**（分类框中有几层子分类？每层列出哪些药？） | A. 已全部识别  B. 有X层未识别  C. 用户补充完整层级 |
| **临床用药评价分支判定**（哪些节点在临床用药评价分支下？） | A. 已明确  B. 需用户确认  C. 用户列出 |
| **"本节不重点介绍"的分类下是否有药名** | A. 有，需建节点  B. 无  C. 用户确认 |

**原则**：能推断的给选项，完全无法判断的才直接问。用户确认后再进入 Step 4。

> **Step 3 必查**：分类层级完整性是最高频错误点——必须确认纸质版分类框中有几层子分类、每一层列出了哪些药名、"本节不重点介绍"的分类下是否也有药名。遗漏分类层级或药名会导致药物直接挂节入口的结构性错误。

### Step 4 — 第一步：建节点框架（不填具体内容）

**先只建节点框架，不填写 `summary.full` 的具体内容。** 框架包括：

- **输出目录**：按 `书名/章名/节名/` 建目录
- **文件名**：严格等于 `label`（中文）
- 每个节点一个文件，frontmatter 含 `id/label/location/shape/fill/stroke/tags/summary/edges_out`
- `summary.full` **留空**（不写），`summary.short` 按 §1.3 规则（纸质版有则写，没有则留空）
- 按「结构节点原则」（见 §四）处理通用结构词、分类层级、多父节点、总结节点合并等
- 口诀节点独立建 md，同时按双轨制写入主知识节点 summary
- **重点药的临床评价内容暂不写入 full**（留到第二步）

### Step 5 — 第一步自查（框架）

按 §九质量检查清单中与框架相关的项检查：
- id 唯一、文件名=label、fill 合法、edges_out 引用存在
- 分类层级完整、药物不直挂节入口、所有药物建独立节点
- 总结节点已合并、临床评价未拆子节点
- stroke 只写 glow、无显式 auto

### Step 6 — 第一步交付（框架版 zip + 节点说明总结）

**框架版交付，等用户审批结构。**

- 打包节级 zip（见下方交付物格式）
- 附节点说明总结（层级树、节点数、stroke 分布）
- **明确告知用户：这是框架版，full 内容尚未填写，请审批节点结构是否正确**
- 用户审批通过后，进入第二步；用户提出修改则修改框架后重新交付

### Step 7 — 第二步：填写 full 内容

**用户审批框架通过后，认真填写 `summary.full`。**

- 逐节点读取纸质版原文，填写 `summary.full`
- 重点药的临床评价内容按 §4.11 规则，合并写入 full，用 `【作用特点】`、`【临床应用】`、`【不良反应】` 标签分段
- 总结节点的内容写入 full，short 留空
- 严格遵守 §1.3：纸质版有的写，没有的不擅自添加
- 口诀按双轨制写入挂载节点 summary.short 末尾

### Step 8 — 第二步自查（内容）

按 §九质量检查清单全部项检查，重点：
- full 内容来自纸质版，无 AI 擅自填充
- 重点药 full 有完整临床评价，普通药 full 留空
- full 格式正确（标签分段、段落空行、编号清晰）
- short 无擅自添加内容

### Step 9 — 最终交付（内容版 zip + 节点说明总结）

**内容版最终交付。**

- 重新打包节级 zip
- 更新节点说明总结（含 full 填写情况）
- 交付给用户

#### 交付物 1：以节为单位的压缩文件

- 将该节的全部节点 `.md` 文件打包为一个 zip，与节目录同级
- 命名：`{节名}.zip`，如 `第一节 镇静催眠药.zip`
- 打包命令：
  ```bash
  zip -r "第一节 镇静催眠药.zip" "第一节 镇静催眠药/"
  ```
- 用 `unzip -l` 反查 zip 内文件数，确认与节点总数一致

#### 交付物 2：节点说明总结

随 zip 一并交付一份节点说明总结，包含：

| 项目 | 内容 |
|---|---|
| 节名 | 如「第一节 镇静催眠药」 |
| 节点总数 | 用 `unzip -l` 反查的实际文件数 |
| 层级结构 | 节入口 → 分类 → 子分类/药物/作用特点/不良反应/口诀 的层级树 |
| short/full 来源 | 哪些是用户提供的、哪些留空、哪些是手写/高亮/印刷来源 |
| 口诀归属 | 每条口诀 part_of 指向哪个节点 |
| 命名处理 | 通用结构词融合情况、前缀/后缀添加情况 |
| 已知未完成项 | 哪些节点 full 未填、哪些关系待用户确认 |

#### 注意

- **不要在全部节点完成前打包**——中途反复打包浪费磁盘；只在用户说"全部好了/打包/交付"时触发
- 每节独立交付一个 zip；多节完成时也可按用户要求合并
- 交付前按 §九质量检查清单逐项自查，确认无误后再打包

## 三、照片转录规则（提取→分析→拆解→重组）

### 3.1 内容映射

| 照片里的内容 | 写入哪 |
|---|---|
| 图中**本来就有**的具体药物节点的正文内容 | 该药物节点的 `summary.full` |
| 荧光笔划住的关键词/短语 | **重组**为该节点的 `summary.short`（关键词用 `**…**` 加粗） |
| 用户**手写补充**的文字（不在原图里） | 写入对应节点的 `summary.short`（手写补充是判断考点/重点的依据） |

### 3.2 来源优先级（从高到低）

1. **手写补充 > 图中原有**：用户手写的一定是新信息（强调/补充/订正），优先按手写内容写
2. **荧光笔划住 > 普通印刷**：荧光笔划住的内容是核心考点，**重组成 short**，而非照搬原句
3. **图中普通印刷**（非荧光笔）→ 该节点的 `full` 素材来源；非核心描述可酌情忽略
4. **同药物在多张照片出现** → 以"最新一张"为准；之前照片的差异向用户确认是否并入

### 3.3 重组规则（short 字段）

- 把荧光笔划住的关键词**重新组织**成一句话，不是直接复制粘贴
- 关键词用 `**…**` 加粗
- 结构：核心特点 + 核心用途，一句话
- 不重复 full 已有的【适应症】段标签

**正模式**：
- 原图高亮"组胺类、改善微循环血供" → 重组为 `组胺类药物，改善微循环血供，用于脑血管疾病和**内耳眩晕症**`
- 原图高亮"吡拉西坦是酰胺类中枢兴奋药" → 重组为 `酰胺类中枢兴奋药，促进脑内**Ach↑**，激活、保护神经细胞`

**反模式**：
- ❌ 把荧光笔划住的字直接复制粘贴进 short，没有重组
- ❌ 把图中所有文字无差别全部复制到 full
- ❌ 在没有照片提供的节点上"按图谱惯例"自动推断 short

### 3.4 full 字段转录

- 保留原图的【药理作用】【适应症】【禁忌】等段落标签
- 按 §五.2 格式规范写
- 必须用 `full: |`（block scalar）让 YAML 保留换行

## 四、结构节点原则（完全以纸质版为准 + 电子版去冗余）

### 4.1 核心原则

1. **完全以纸质版为准**：转录时重点关注纸质版的每一个框及其结构，纸质版有框 → 电子版有对应节点，不随意删减层级
2. **认清纸质版局限性**：纸质版受纸张大小限制，需要"分类与作用机制""临床用药评价"等结构节点分区；电子版不受此限制
3. **通用结构词不单独建空壳节点**：分类、总论、代表药物、临床用药评价、作用机制、典型不良反应、总结——这些词本身无独立语义，能融合就融合
4. **必须单独建的加前缀/后缀**：纸质版中该框有独立正文内容时，保留为单独节点，但 label 必须加具体药名/分类名作为前缀或后缀
5. **纸质版同名重复框合并**：纸质版中同一名称出现在多个分支下（如巴比妥类同时在"分类"和"临床用药评价"下各有一个框），电子版合并为一个节点

### 4.2 通用结构词融合清单

以下 7 个通用结构连接词**不单独建空壳节点**：

| 通用结构词 | 处理方式 | 示例 |
|---|---|---|
| 总论 | 写入节入口节点的 `summary` | 镇静催眠药总论 → 写入「镇静催眠药」summary |
| 分类 | 不单独建，分类节点本身就是分类 | 「巴比妥类」直接挂节入口 |
| 代表药物 | 写入分类节点的 `summary.full【代表药】` | 长效代表药 → 写入「巴比妥类」full |
| 临床用药评价 | 不单独建，其下有内容的子项（作用特点/典型不良反应）加前缀后单独建 | 巴比妥类临床用药评价 → 「巴比妥类作用特点」+「巴比妥类典型不良反应」 |
| 作用机制 | 写入分类/药物节点的 `summary` | 非特异性抑制中枢 → 写入「巴比妥类」summary |
| 作用特点 | 纸质版有独立正文 → 加分类名前缀单独建 | 「巴比妥类作用特点」 |
| 典型不良反应 | 纸质版有独立正文 → 加分类名前缀单独建 | 「巴比妥类典型不良反应」 |
| 总结 | 节内总结可建节点，跨节大总结建节点 | 「不同种类镇静催眠药剂量与药理作用关系」 |

### 4.3 融合 vs 单独建节点决策

| 情况 | 处理 |
|---|---|
| 总论内容简短（1-2 句） | 写入节入口 `summary.short` |
| 总论内容较长（多段） | 写入节入口 `summary.full` |
| 作用机制是分类的核心定义 | 写入分类节点 `summary` |
| 作用特点有独立正文（多段） | 单独建「XX作用特点」节点（`fill: cls-feature`） |
| 典型不良反应有独立正文 | 单独建「XX典型不良反应」节点（`fill: cls-adverse`） |
| 口诀挂在作用特点下 | 口诀独立建节点，`part_of` 指向作用特点（完全以纸质版挂载位置为准） |
| 普通药仅提名无画像 | 不单独建，写入分类 `full【代表药】` |
| 重点药有完整药理卡片 | 单独建药物节点（`fill: cls-drug`） |

### 4.4 前缀/后缀命名规范

必须单独建节点时，**必须加具体药名/分类名作为前缀或后缀**，禁止使用裸通用词：

| ✅ 正确 | ❌ 错误 |
|---|---|
| 巴比妥类作用特点 | 作用特点 |
| 地西泮临床应用注意 | 临床应用注意 |
| 丙戊酸钠典型不良反应 | 典型不良反应 |
| 苯二氮䓬类药物相互作用 | 药物相互作用 |

### 4.5 药物节点处理（所有药物都建独立节点）

**所有在纸质版中出现的药物，无论重点药还是普通药，都必须建立独立节点**，挂到父分类节点下。区别仅在于前缀和内容完整度：

| 类型 | 前缀 | stroke | summary.full | 判定标准 |
|---|---|---|---|---|
| **重点药** | `med-` | `glow` | 有完整药理卡片 | 纸质版有独立框且框内有正文内容 |
| **普通药** | `drug-` | 不填（默认auto） | 留空（不写） | 仅提名，无独立正文框 |

- 普通药节点的 `summary.short` 可基于分类信息简短描述（如"巴比妥类长效药"），也可留空
- 普通药节点 `edges_out` 写 `instance_of → 父分类节点`
- 分类节点的 `summary.full【代表药】` 仍保留，作为该分类下药物的概览清单
- 纸质版一个框里列出多个药名（如"长效：苯巴比妥、巴比妥"），每个药各建一个独立节点，**不合并、不省略**

### 4.6 分类层级完整性（禁止药物直挂节入口）

**纸质版中每一层分类框都必须建对应节点，药物必须挂到其所属分类下，禁止直接挂节入口。**

| 规则 | 说明 |
|---|---|
| 逐层建节点 | 纸质版分类框中有几个子分类，就建几个分类节点；即使某子分类"本节不重点介绍"，也必须建节点 |
| 药物挂分类 | 所有药物节点（重点药+普通药）的 `edges_out` 必须 `instance_of` 指向其所属分类节点，不能直接 `instance_of` 或 `part_of` 指向节入口 |
| 不遗漏药名 | 分类框中列出的所有药名都必须建独立节点，包括"本节不重点介绍"的分类下的药名 |
| 口诀挂分类 | 分类级口诀 `part_of` 指向该分类节点，不指向节入口 |

**反模式（绝对禁止）：**
- ❌ 药物节点直接 `instance_of → 节入口`（跳过分类层级）
- ❌ 纸质版有"苯二氮䓬类/非苯二氮䓬类"两个子分类框，只建一个分类或不建分类
- ❌ "本节不重点介绍"的分类下的药名被省略不建节点
- ❌ 分类级口诀直接 `part_of → 节入口`

**正模式：**
```
第八节 中枢肌松药 (节入口)
├── 苯二氮䓬类 (分类，本节不重点介绍，但仍需建节点)
│   ├── 药A (普通药，instance_of → 苯二氮䓬类)
│   └── 药B (普通药，instance_of → 苯二氮䓬类)
└── 非苯二氮䓬类 (分类)
    ├── 重点药X (重点药，instance_of → 非苯二氮䓬类)
    └── 普通药Y (普通药，instance_of → 非苯二氮䓬类)
```

> **Step 3 必查项**：确认模糊点时，必须检查"纸质版分类框中有几层子分类？每一层列出了哪些药名？本节不重点介绍的分类是否也有药名？"，遗漏分类层级是最常见的错误。

### 4.7 纸质版同名重复框合并

纸质版中同一名称出现在多个分支下时，电子版合并为一个节点：

| 纸质版结构 | 电子版处理 |
|---|---|
| 分类 → 巴比妥类（含机制、代表药） | 合并为一个「巴比妥类」节点，summary 含机制，full 含代表药 |
| 临床用药评价 → 巴比妥类（含作用特点、典型不良反应） | 作用特点、典型不良反应作为「巴比妥类」的子节点（part_of） |

合并后，原两个分支下的子节点统一挂到合并后的节点下，避免重复建同名节点。

### 4.8 子分类节点保留

纸质版中分类下的子分组（如"长效""超短效"）如果有独立框且框内有内容，**保留为单独子分类节点**（`fill: cls-classification`），不扁平化掉：

```
巴比妥类（cls-classification）
├─ 长效巴比妥类（cls-classification，full【代表药】含苯巴比妥、巴比妥）
└─ 超短效巴比妥类（cls-classification）
    └─ 硫喷妥钠（cls-drug，instance_of）
```

如果子分组框内只有药名列表、无独立正文，则药名直接写入父分类的 `full【代表药】`，不单独建子分类节点。

### 4.9 纸质版结构 → 电子版结构转换示例

**纸质版**：
```
镇静催眠药
├─ 分类与作用机制
│   └─ 分类
│       └─ 巴比妥类（非特异性抑制中枢）
│           ├─ 长效：苯巴比妥、巴比妥  ← 一个框，多药
│           └─ 超短效：硫喷妥钠
│   └─ 总论
├─ 临床用药评价
    └─ 巴比妥类
        ├─ 作用特点 → xxx → 口诀：爸比不焦急
        └─ 典型不良反应 → xxx
```

**电子版（去冗余后）**：
```
镇静催眠药（节入口 cls-structure，summary 含总论）
└─ 巴比妥类（cls-classification，summary 含"非特异性抑制中枢"，full 含长效代表药）
    ├─ 巴比妥类作用特点（cls-feature，part_of）
    │   └─ 爸比不焦急（cls-mnemonic，part_of 指向作用特点）
    ├─ 巴比妥类典型不良反应（cls-adverse，part_of）
    └─ 超短效巴比妥类（cls-classification）
        └─ 硫喷妥钠（cls-drug，instance_of）
```

> 注意：纸质版有两个巴比妥类框 → 合并为一个；"超短效"有独立框 → 保留子分类节点；"长效"框内只有药名无正文 → 药名写入巴比妥类 full【代表药】，不单独建子分类。

### 4.10 多父节点药物（多条 edges_out）

**当一个药物同时出现在纸质版的多个分类分支下时（如按代分类 + 按作用机制分类），只建一个药物节点，但 `edges_out` 写多条边，分别指向不同父分类。**

| 规则 | 说明 |
|---|---|
| 节点唯一 | 同一药物只建一个节点（id 唯一），不重复建 |
| 多条边 | `edges_out` 是数组，可写多条 `instance_of`，每条指向一个父分类 |
| 主分类优先 | 第一条边指向主要分类（如代分类），后续边指向次要分类（如机制分类） |
| reason 区分 | 每条边的 reason 写明所属分类，如"第二代抗癫痫药"、"抑制NMDA型谷氨酸受体的代表药物" |

**示例（托吡酯）：**
```yaml
edges_out:
  - target: cls-gen2-y2-01-02
    type: instance_of
    reason: 第二代抗癫痫发作药的代表药物
  - target: cls-nmda-y2-01-02
    type: instance_of
    reason: 抑制NMDA型谷氨酸受体的代表药物
```

**反模式：**
- ❌ 同一药物在不同分类下各建一个节点（id 重复）
- ❌ 药物只挂一个分类，遗漏纸质版中出现的其他分类
- ❌ 多条边的 reason 都写"属于该分类"（不具体）

### 4.11 临床用药评价内容合并写入重点药 full（不拆子节点）

**临床用药评价分支下的重点药，不拆分"作用特点""临床应用""不良反应"子节点，全部内容合并写入该重点药的 `summary.full`，用标签分段标注。**

| 规则 | 说明 |
|---|---|
| 不拆子节点 | 不建 `{药名}作用特点`、`{药名}主要临床应用`、`{药名}典型不良反应` 等子节点 |
| 合并写入 full | 所有临床评价内容写入重点药的 `summary.full`，用 `【作用特点】`、`【临床应用】`、`【不良反应】` 等标签分段 |
| 需读原文分类 | 纸质版可能把所有内容写到一个框里，需要读原文分清楚哪段是作用特点、哪段是临床应用、哪段是不良反应，在 full 里标注清楚 |
| 格式清楚 | 标签分段，段落间空行，编号用 (1)(2)(3) 或 ①②③，注意换行 |
| 重点药 vs 普通药 | 重点药 full 有完整临床评价内容，普通药 full 留空——这是两者的核心区别 |

**full 格式示例：**
```yaml
summary:
  full: |
    【作用特点】
    (1) 肝药酶抑制剂，用于各种类型癫痫。
    (2) 有肝毒性，3岁以下儿童风险较大。

    【临床应用】
    (1) 各种类型癫痫，包括全身性强直-阵挛发作及部分性发作。
    (2) 双相情感障碍相关躁狂发作。

    【不良反应】
    (1) 肝毒性，肝功能损害。
    (2) 避免与肝毒性药物合用。
```

**反模式（绝对禁止）：**
- ❌ 把重点药拆成"作用特点""临床应用""不良反应"3个子节点（导致重点药 full 为空，和普通药无区别，还增加节点数）
- ❌ 纸质版内容混在一个框里，不分类就直接原样写入 full（需要读原文分清楚类别并标注）
- ❌ full 里不写标签，内容堆在一起不分段

### 4.12 手写补充特殊节点处理

**纸质版中手写补充的特殊内容（非药物、非分类、非口诀），如"对肝药酶无影响"、"备孕与妊娠用药影响"等，按以下规则处理：**

| 情况 | 处理方式 |
|---|---|
| 有独立框或明确标注的手写补充 | 单独建节点（`fill: cls-feature`），`edges_out` 为 `part_of → 节入口` |
| 写在某个分类/药物框内的补充 | 写入该节点的 `summary.full`，不单独建节点 |
| 补充内容包含代表药列表 | 节点 `full` 中用 `【代表药】` 标签列出 |
| 补充内容有口诀 | 口诀单独建节点（`fill: cls-mnemonic`），`part_of` 指向该补充节点 |

**示例：**
```
对肝药酶无影响 (cls-feature, part_of → 节入口)
└── 丁桂嘉左 (cls-mnemonic, part_of → 对肝药酶无影响)
```

### 4.13 其他常见错误与规范

| 错误场景 | 正确做法 |
|---|---|
| 机制分类节点（如"抑制GABA氨基转移酶"）只写了代表药在 full，没给代表药加边 | 分类节点用 `has_instance` 边指向代表药节点，或代表药用 `instance_of` 边指向分类 |
| 药物级口诀挂到了分类节点上 | 口诀挂载以纸质版为准：药物级口诀 `part_of` 指向药物节点，不挂分类 |
| 选药节点/总结节点拆成多个子节点、连大量药线 | 有总标题的选药/总结内容合并为一个 `cls-summary` 节点挂节入口，内容写 full，不拆分子节点、不连大量 has_instance 边（详见 §4.14） |
| 纸质版同一框里的多个内容被拆成多个节点 | 纸质版同一框里的内容合并为一个节点，不拆分（如"肌阵挛性发作和全面性强直-阵挛性发作"在同一框，合并为一个节点） |
| 给分类节点/普通药节点擅自加 short 描述 | 纸质版上没有的内容一律不填，short 留空（详见 §1.3） |
| 机制分类下的子分类（如"激动GABAA受体"下的"苯二氮䓬类"）没建节点 | 纸质版中有明确子分类的，建子分类节点，药物挂到子分类下 |

### 4.14 总结节点合并规则

**当纸质版有一个总标题（如"根据癫痫发作类型合理选药"、"备孕或妊娠期女性癫痫用药"），其下包含多个子类型且每个子类型涉及多个药物时，合并为一个总结节点，不拆分。**

| 规则 | 说明 |
|---|---|
| 合并为一个节点 | 总标题作为一个 `cls-summary` 节点，不拆成多个子类型节点 |
| 挂节入口 | `edges_out` 为 `part_of → 节入口`，不连大量 `has_instance` 边指向具体药物 |
| 内容写 full | 各子类型的选药/注意事项写入 `summary.full`，用 `【子类型】` 标签分段 |
| short 留空 | 总结节点的 `short` 永远不写，有内容写 full |
| label 用纸质版总标题 | 如"根据癫痫发作类型合理选药"、"备孕或妊娠期女性癫痫用药" |

**反模式（绝对禁止）：**
- ❌ 把"根据癫痫发作类型合理选药"拆成"局灶性癫痫""失神发作""肌阵挛性发作"等多个子节点
- ❌ 给总结节点连大量 `has_instance` 边指向每个药物（导致图混乱）
- ❌ 给总结节点写 `short`（有内容写 full，没内容留空）
- ❌ 丢失纸质版原有的总标题框

**正模式：**
```
第二节 抗癫痫发作药 (节入口)
├── 根据癫痫发作类型合理选药 (cls-summary, part_of → 节入口)
│   └── full: 【局灶性癫痫】... 【失神发作】... 【肌阵挛性发作】...
├── 备孕或妊娠期女性癫痫用药 (cls-summary, part_of → 节入口)
│   └── full: 【避免使用】... 【首选】...
└── 对肝药酶无影响 (cls-summary, part_of → 节入口)
    └── full: 【代表药】... 【口诀】...
```

## 五、字段制作规范

### 5.1 shape / fill / stroke

- **fill**（必填）：药学顶层类 IRI，决定背景色 + 默认形状 + 默认边框。取值见 RULES §三
- **shape**（可选）：OWL2 实体类型，每个类型对应**一个固定几何形状**（映射见 RULES §二）。合法值：`auto` / `class` / `named_individual` / `object_property` / `data_property` / `annotation_property`
  - **不填或 `auto`**：用 fill 的默认形状（可访问 FILL_CONFIG 中的扩展形状如 vee / tag / barrel）
  - **显式填写**：用映射表的固定形状，**覆盖** fill 的默认形状
- **stroke**（可选）：**不填时由 fill 决定（默认 auto，无特效）**；只有需要强调时才显式填写。合法值：`glow`（呼吸光晕，重点节点/重点分类）。**`auto` 不需要单独写**，不填就是 auto

**覆盖示例**：

```yaml
# 例 1：默认情况 —— 让 fill 的扩展形状生效
fill: cls-mnemonic
# 不填 shape → 节点是 V 形（vee，扩展形状）

# 例 2：覆盖 fill —— 让口诀用椭圆
fill: cls-mnemonic
shape: named_individual  # → 椭圆（覆盖 V 形）

# 例 3：关系实体化 —— "治疗" 边转成节点
fill: cls-feature
shape: object_property   # → 六边形
```

**stroke 填写规则（只写 glow，不写 auto）**：

| 节点类型 | stroke | 判定标准 |
|---|---|---|
| 重点药（临床用药评价里有独立评价框） | `glow` | 纸质版"临床用药评价"分支下有该药物的作用特点/临床应用/不良反应独立框 |
| 普通药（仅提名，无独立评价框） | 不填（默认 auto） | 仅在分类框中提名，"临床用药评价"分支下无独立评价框 |
| 重点分类（临床用药评价分支下有该分类） | `glow` | 纸质版"临床用药评价"分支下直接出现该分类名，且其下有作用特点/不良反应 |
| 普通分类（仅在分类与作用机制分支出现） | 不填（默认 auto） | 仅在"分类与作用机制"分支出现，"临床用药评价"分支下无该分类 |
| 跨节大总结/表格 | `glow` | 跨节汇总对比 |
| 节内总结 | 不填（默认 auto） | 仅本节内总结 |
| 其他节点（作用特点/不良反应/口诀/节入口） | 不填（默认 auto） | — |

> **关键区分**：glow 的判定依据是"该节点是否出现在纸质版'临床用药评价'分支下"，不是"该分类下有没有药"或"该分类有没有代表药"。分类与作用机制分支里的分类，即使列出了多个代表药，也不加 glow。
>
> **示例**：中枢肌松药的"非苯二氮䓬类"只出现在分类分支，临床用药评价分支下直接是乙哌立松/巴氯芬/氯唑沙宗三个药 → 非苯二氮䓬类不加 glow，三个药加 glow。

### 5.2 summary 填写原则与格式规范

#### 填写原则（先判断"能不能写"，再判断"怎么写"）

**`summary.full` 必须由用户主动提供，禁止 AI 自动填充。** 这是创建节点时最容易越权的点，必须严格区分两个字段：

| 字段 | 创建时可自动初始化？ | 何时可填充/替换 |
|---|---|---|
| `summary.short` | ✅ 可以（建议留空或简短占位） | 用户主动提供或确认后**替换** |
| `summary.full` | ❌ 禁止 | **仅当用户主动提供文本时**才可写入；任何"智能补充""自动总结""按药理推断"都被禁止 |

**反模式（绝对禁止）：**
1. ❌ 创建新节点时由 AI 撰写 `full`，即使"药理学上正确"
2. ❌ 用占位字符串填充 `full`（如"待补充""暂无内容"）
3. ❌ 用户改 `short` 时顺手重写 `full`，除非用户明确指示
4. ❌ 把临床内容拆成独立边的同时又往 `full` 里塞文字（两选一，见 §七）
5. ❌ 用同章节同分类节点的 `full` 文本"模板套用"，除非用户明确要求参照

**正模式：**
1. ✅ 用户未提供 `full` → 该字段完全不写（YAML 解析为 null，UI 自然隐藏展开按钮）
2. ✅ 用户手写/口述并明确说"写入 full" → 原样写入，不二次润色
3. ✅ 用户只提供 `short` → 仅写 `short`，`full` 保持不写入、不留占位
4. ✅ 用户提供多个药理点（"作用：…用途：…禁忌：…"）→ 按用户给的标题分段写入 `full`，段落间空行分隔

**汇报约定：** 创建/重构节点时，最终汇报必须明示 `short`/`full` 各自来源——哪个是用户提供的、哪个沿用旧的、哪个留空。若用户未提供 `full`，汇报必须出现"未写 full / full 留空 / 待用户提供"字样。

**判断锚点：** "如果我不在场，用户能否接受我写进 `full` 的每一个字？" 不能 → 留空；能 → 写。默认答案：**不能**。

#### full 中重点关键词加粗规则

**纸质版上被荧光笔标注、有色字体（蓝色/红色等）、或视觉上强调的重点关键词，在写入 `full` 时必须用 `**加粗**` 标注。** 这关系到后续写 `short` 和抽取 `tags`。

| 加粗对象 | 示例 |
|---|---|
| 药物成分/结构名 | **咪唑并吡啶**、**环吡咯酮**、**三氯乙醇** |
| 关键酶/代谢途径 | **肝药酶诱导剂**、**CYP3A4**、**凝血酶原时间** |
| 关键受体/通道 | **GABAB**、**MT1**、**MT2**、**觉醒通路** |
| 特殊不良反应 | **Stevens-Johnson综合征**、**宿醉**、**戒断综合征**、**呼吸抑制** |
| 关键参数/数值 | **生物利用度约为80%**、**Q-T间期** |
| 特殊人群/禁忌 | **胎盘屏障**、**肝功能不全**、**癫痫持续状态** |
| 代表药名 | **地西泮**、**瑞马唑仑**、**雷美替胺** |

**规则：**
- 只加粗纸质版上**视觉强调**的关键词（荧光笔/有色字体），不自行判断加粗
- 加粗用 Markdown `**关键词**` 格式
- 同一关键词在 full 中多次出现时，每次都加粗
- 加粗不改变原文措辞，只添加格式标记

#### short 格式

- 关键词用 `**…**` 加粗
- 结构：核心特点 + 核心用途，一句话
- 以 `**` 开头时必须加双引号（YAML 会把 `**` 解析为 alias）

```yaml
short: "**苯二氮䓬类长效代表药**；适应证包括**抗焦虑、镇静催眠、抗癫痫抗惊厥**；**妊娠妇女和新生儿禁用**。"
```

#### full 格式（【标签】+ 段落）

- 多段结构，每段以 `【标签】` 起头
- 常用标签：`【药理作用】` `【适应症】` `【禁忌】` `【不良反应】` `【相互作用】` `【药代动力学】` `【临床应用注意】` `【代表药】` `【口诀】`
- **段落之间必须空行**（否则 marked 不会拆出多个 `<p>`）
- 关键医学术语 `**加粗**`，多项用 `- ` markdown 列表
- 必须用 `full: |`（block scalar）

```yaml
full: |
  【药理作用】抑制合成嘧啶的**二氢乳清酸脱氢酶**，使活化 B 细胞的生长受抑制。

  【适应症】
  - 适用于**成人类风湿关节炎**（有改善病情作用）、**狼疮性肾炎**。
  - **半衰期长**，间隔 24h 给药一次。

  【禁忌】妊娠期、哺乳期、严重肝、肾损伤者禁用。
```

**禁止**：`(1)(2)(3)` 半角括号编号、整段不换行、`#` 标题、HTML 标签。

#### 关键词加粗判定

满足任一条即可加粗：药理学机制名词、适应症（疾病名）、禁忌关键人群/关键药名、用户手写补充强调的词、荧光笔划住的关键词、不良反应/严重警告。

**不加粗**：整段一句话加粗、"用于""是""的""和"等连接词。

### 5.3 tags 抽取规则

#### 三铁律

1. **复用优先**：summary 里已有合适关键词直接复用，不另造同/近义词
2. **去重优先**：不写语义重复的标签（`口诀` 与 `记忆口诀`、`禁忌` 与 `禁用`、`适应症` 与 `适用症` 不并存；先出现则保留先出现的）
3. **不杜撰**：严禁把 summary 里没出现的概念放进 tags（否则图谱搜索出现"空标签命中"）

**附加约束：**
- 不把 fill 枚举值（`cls-drug`/`cls-classification` 等）重复写入 tags
- 不把"药物/疾病/概念"等节点本质词写成标签
- 不把整个句子放进 tags

#### 节点类型专属规则（按 fill 区分）

| 节点类型 | tags 必须包含 | 可选包含 | 说明 |
|---|---|---|---|
| **重点药**（`cls-drug` + `stroke: glow`） | 药品名 + 至少一个分类 tag + 至少一个作用 tag | 代际分类、化学分类、作用机制、ADR（最多3个） | 作用 tag 必填，如 `解热镇痛`、`降压`；ADR 必须标注为 `ADR：XXX` 格式，最多保留 3 个 |
| **普通药**（`cls-drug`，无 glow） | 药品名 + 分类 tag | — | 可简化，不需要作用 tag 和 ADR |
| **分类节点**（`cls-classification`） | 自身 label | 子分类名、机制/分类依据、重点代表药 | 有子分类时列子分类名；无子分类时列机制（如 `激动β₂受体`）；普通药不标记 |
| **口诀节点**（`cls-mnemonic`） | `口诀` + 对应的药品名/分类名 | — | label 改为口诀内容本身（见 §六） |
| **模块节点**（`cls-structure`） | — | — | 一般不单独建 tags，有需求按具体内容抽取 |
| **作用特点/评价**（`cls-feature`） | 所属分类名/药名 | 核心特点关键词 | 如 `巴比妥类作用特点` 的 tags 含 `巴比妥类` |
| **不良反应/禁忌**（`cls-adverse`） | 所属分类名/药名 | 具体 ADR 关键词 | 如 `巴比妥类典型不良反应` 的 tags 含 `巴比妥类, 宿醉现象` |
| **其他节点**（`cls-concept`/`cls-biomolecule`/`cls-disease`/`cls-summary`） | 核心关键词 | 相关分类/作用 | 视节点内容决定 |

**药物节点示例：**
```yaml
# ✅ 正模式
tags:
  - 氨溴索            # 药品名
  - 黏痰溶解剂         # 分类
  - 祛痰              # 作用
  - ADR：胃肠道反应    # ADR（标注格式，最多3个）
```

**分类节点细分（有子分类 vs 无子分类）：**

有子分类的分类节点（如 `M胆碱受体拮抗剂` 下有 SAMA/LAMA）：
```yaml
tags:
  - M胆碱受体拮抗剂     # 自身 label
  - SAMA              # 子分类名
  - LAMA              # 子分类名
  - 异丙托溴铵          # 重点代表药
  - 噻托溴铵           # 重点代表药
```

无子分类的细分类节点（如 `短效M胆碱受体拮抗剂（SAMA）`）：
```yaml
tags:
  - 短效M胆碱受体拮抗剂（SAMA）  # 自身 label（已含 SAMA，不再单独列 SAMA）
  - 拮抗M胆碱受体                # 机制/分类依据
  - 异丙托溴铵                   # 重点代表药
```

> **冗余检查**：若子分类缩写（如 SAMA）已包含在 label 中，只列机制如 `拮抗M胆碱受体`，不必再列 `SAMA`。

#### 药理作用 tag vs 适应症 tag（必须区分）

**重点药的 tags 中必须区分药理作用和适应症，两者不可混用：**

| 类型 | 定义 | 示例 | 标注方式 |
|---|---|---|---|
| **药理作用 tag** | 药物在体内产生的药理效应 | `镇静催眠`、`抗惊厥`、`肌松`、`降压`、`抗焦虑` | 加前缀 `药理作用：`，如 `药理作用：镇静催眠` |
| **适应症 tag** | 药物临床用于治疗的疾病/症状 | `失眠`、`入睡困难`、`癫痫`、`高血压`、`焦虑` | 加前缀 `适应症：`，如 `适应症：失眠` |
| **禁忌 tag** | 药物禁用的人群/情况 | `妊娠期禁用`、`新生儿禁用`、`肝功能不全`、`呼吸功能不全` | 加前缀 `禁忌：`，如 `禁忌：妊娠期禁用` |
| **ADR tag** | 药物的不良反应 | `宿醉`、`戒断综合征`、`呼吸抑制` | 加前缀 `ADR：`，如 `ADR：宿醉` |

**规则：**
- 重点药必须至少有一个**药理作用 tag**（必填）
- 适应症、禁忌、ADR tag 均可选，有则加对应前缀
- 普通药可简化，不需要严格区分
- 禁止把适应症当药理作用写（如把 `失眠` 写成 `镇静催眠` 的替代）
- 禁止把药理作用当适应症写（如把 `镇静催眠` 写成 `适应症：镇静催眠`）
- 禁忌 tag 只写禁用情况，不写慎用（慎用属于注意事项，不单独建 tag）

**示例：**
```yaml
# ✅ 正确区分
tags:
  - 唑吡坦              # 药品名
  - 非苯二氮䓬类         # 分类
  - 镇静催眠            # 药理作用（必填）
  - 适应症：入睡困难      # 适应症（可选，加前缀）
  - CYP3A4             # 代谢途径

# ❌ 错误：把适应症当药理作用
tags:
  - 唑吡坦
  - 非苯二氮䓬类
  - 失眠               # 这是适应症，不是药理作用
```

#### 抽取流程

1. **扫 summary**：抽出所有 `**加粗**` 短语 / 专有名词 / 药理分类词
2. **按三铁律 + 节点类型专属规则过滤**候选词
3. **语义去重**：同/近义词只保留先出现的
4. **硬约束再过滤**：不重复 fill 枚举值、不写本质词、不写整句
5. **兜底自取**（仅当前 4 步拿不到目标数量时）：基于 summary 上下文自取，**必须向用户汇报"自取了哪些"**

#### UI 显示过滤规则（代码自动处理，MD 内保持完整）

为节省界面空间，UI 渲染时自动隐藏以下重复标签：
- **规则 1**：tag 与 label 相同 → 隐藏（如药品节点 `氨溴索` 的 tags 里有 `氨溴索`，显示时自动隐藏）
- **规则 2**：口诀节点（`fill: cls-mnemonic`）的 `口诀` tag → 隐藏

> MD 文档内 tags 保持完整，只是显示时隐藏重复部分。通过 API/数据导出的 tags 仍是完整的。

#### 兜底自取汇报措辞

| 抽取来源 | 汇报措辞 |
|---|---|
| summary 文字 `**加粗**` 标记 | "来自 `**加粗**` 标记：`H1受体激动剂`、`内耳眩晕`" |
| summary 上下文（无标记但有该词） | "来自 summary 上下文：`微循环改善`" |
| AI 兜底自取 | "**AI 兜底自取**：`XXX`（基于 summary 上下文，未在原资料中显式标注）" |

### 5.4 edges_out 填写规则

#### 边方向铁律：每个节点自管自己的 edges_out

所有 `edges_out` 都表示"这个节点向外辐射的引用关系"，发起方在自己的 md 文件里写。

| 关系 | 由谁写 |
|---|---|
| 类-类层级（子类→父类） | 子类写 `subclass_of → 父类` |
| 局部-整体（局部→整体） | 局部写 `part_of → 整体` |
| 个体-类（实例→类别） | 实例写 `instance_of → 类别` |
| 辅助学习（口诀→主知识） | **辅助节点**写 `part_of → 主知识节点` |
| 等价/互斥/同一（双向） | **任一侧**写，存一条即可 |

**禁止**：
- ❌ 父节点写一堆 edges_out 指向子节点
- ❌ 双向边正反都写
- ❌ 用 `subclass_of` 表达 `part_of`

#### 6 种边类型

| type | 语义 | 方向 |
|---|---|---|
| `subclass_of` | 类-类，A 是 B 的一种 | 子类→父类 |
| `instance_of` | 个体-类，A 是 B 的实例 | 实例→类别 |
| `part_of` | 局部-整体，A 是 B 的构件 | 局部→整体 |
| `disjoint_with` | 互斥（对称） | 任一侧 |
| `equivalent_to` | 类等价（对称） | 任一侧 |
| `same_individual` | 个体同一/别名（对称） | 任一侧 |

#### reason 措辞规范

- **必填**，不可空
- 必须包含具体对象（药名/分类名/疾病名/机制名），不能是"治疗""相关""适用"等空泛词
- 必须能独立成句——读者看到 reason 即可理解这条边的语义

#### reason 措辞模板（按 type）

| type | 建议模板 | 示例 |
|---|---|---|
| `subclass_of` | `属于{上级类名}` / `一种{上级类名}` | `一种苯二氮䓬类` |
| `instance_of` | `{动作}{对象}` | `治疗癫痫持续状态`、`激动GABA_A受体`、`导致粒细胞缺乏` |
| `part_of` | `{主知识名}{角色}` | `吡拉西坦记忆口诀`、`镇静催眠药的一项`、`某节总结` |
| `disjoint_with` | `与{对方}互斥` | `与吡拉西坦互斥（同为酰胺类但不可同用）` |
| `equivalent_to` | `与{对方}等价` | `与苯二氮䓬等价（译名一致）` |
| `same_individual` | `与{对方}同物异名` | `与乙酰水杨酸同物异名（阿司匹林）` |

#### 边类型选择决策表

| 关系场景 | 用什么 type | 写在谁的文件里 | reason 措辞 |
|---|---|---|---|
| 分类 X 是分类 Y 的子类 | `subclass_of` | 分类 X 写 | `一种{分类Y}` |
| 药物 A 属于分类 X | `instance_of` | 药物 A 写 | `属于{分类X}` |
| 节入口 是 章入口的一部分 | `part_of` | 节入口写 | `{章名}的一部分` |
| 作用特点/不良反应 是 药物/分类的一部分 | `part_of` | 特点/不良反应节点写 | `{药物名}的作用特点` |
| 口诀节点 ↔ 药物/分类 | `part_of` | **口诀节点**写 | `{主知识名}记忆口诀` |
| 注意/提示节点 ↔ 药物 | `part_of` | **注意节点**写 | `{药物名}注意事项` |
| 对比表节点 ↔ 分类/节 | `part_of` | **对比表节点**写 | `{分类/节名}药物对比` |
| 药物 A 与药物 B 药理相反/不可同用 | `disjoint_with` | **任一侧**写 | `与{药名}互斥` |
| 分类 A 与分类 B 等价（别名） | `equivalent_to` | **任一侧**写 | `与{分类名}等价` |
| 药物 A 与药物 B 是同一物质的不同名称 | `same_individual` | **任一侧**写 | `与{药名}同物异名` |

#### 占位边禁止

- ❌ 不得为"看起来完整"就建占位边（如 `subclass_of → unknown` 占位未知分类）
- ❌ 不得为尚未确认的关系预先建边（如用户只说"可能与 X 相互作用"就建 `instance_of → X`）
- 遇到不确定的关系，明确告知用户"该关系需要确认，是否建边"

#### 边方向易错点（4 个经典反例）

**❌ 反例 1：父节点反向持有层级边**
```yaml
# 错误：父节点不该写指向子节点的层级边
# 镇静催眠药.md
edges_out:
  - target: 唑吡坦
    type: subclass_of
    reason: 下属药物
```
应改为由子节点声明：
```yaml
# 正确：唑吡坦.md
edges_out:
  - target: 镇静催眠药
    type: instance_of
    reason: 属于该分类
```

**❌ 反例 2：用 `subclass_of` 表达辅助关系**
```yaml
# 错误：口诀不是分类，挂在分类下会被画成子节点
# 某口诀.md
edges_out:
  - target: 酰胺类中枢兴奋药
    type: subclass_of
    reason: 帮助记忆酰胺类
```
口诀是辅助节点，必须用 `part_of`：
```yaml
# 正确
edges_out:
  - target: 酰胺类中枢兴奋药
    type: part_of
    reason: 酰胺类记忆口诀
```

**❌ 反例 3：主知识节点反向持有辅助边指向口诀**
```yaml
# 错误：药物节点主动连向口诀，会把口诀画成下级
# 丁苯酞.md
edges_out:
  - target: 丁苯酞口诀
    type: part_of
    reason: 记忆口诀
```
应由口诀节点持有 `part_of` 边指向主知识：
```yaml
# 正确：丁苯酞口诀.md
edges_out:
  - target: 丁苯酞
    type: part_of
    reason: 帮助记忆丁苯酞
```

**❌ 反例 4：同方向重复边**
```yaml
# 错误：同一对节点同时写 subclass_of 和 part_of
edges_out:
  - target: 镇静催眠药
    type: subclass_of
    reason: 属于上级
  - target: 镇静催眠药
    type: part_of
    reason: 属于上级
```
选一种即可：类-类用 `subclass_of`，局部-整体用 `part_of`，不要并存。

#### 判断锚点（self-check）

| 问自己 | 答案 |
|---|---|
| 这条边写完后，**新增一个新子节点/辅助节点时**，是否需要回到这条边的发起方文件里改 edges_out？ | **不需要** → 写法正确；需要 → 方向反了或位置写错 |
| 这条边的 edges_out 写在**子类/局部/业务提供方**那一侧的 md 文件里吗？ | 是 → 正确；否 → 改为子类/局部那一侧 |
| 我要用 `subclass_of` 还是 `part_of`？ | `subclass_of` = 种类归属（A 是一种 B）；`part_of` = 局部-整体（A 是 B 的一部分/辅助） |
| reason 是否包含具体对象？ | 是 → 正确；否 → 补具体名词 |
| 这条关系是否已确认？ | 未确认 → 不建边，先问用户 |

### 5.5 location 字段

```yaml
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
  item: 一、（一）①   # 可选，节内排序/子项
```

#### 字段填写

- 书/章/节名称与教材目录一致
- 节入口节点的 location 就是自身
- 子节点的 location 继承所属节
- `item`（可选）：节内排序或子项编号，用于同名多节点的区分（如"第一节 一、（一）① vs 一、（一）②"）；模块节点（篇/章/节入口）可省略 `item`，其余节点须提供

#### 保留规则

1. **知识节点的 label 不附目录序号**（如药物节点 label 写「地西泮」，不写「第一节 地西泮」）；**结构节点（节入口）的 label 可包含序号**（如「第一节 镇静催眠药」），与纸质图/教材目录一致。
2. `section == chapter` 时可删除重复的 `section`（如某些章直接分知识点、无节级划分）。
3. `item` 用于同一节内多个节点的排序 tiebreaker（如同节多个药物按教材出现顺序编号）。
4. **location 不决定 fill/shape，也不直接决定边类型。** 节点的视觉身份由 fill/shape/stroke 决定，关系由 edges_out 显式声明——location 只是来源坐标。
5. **思维导图结构 ≠ 教材目录结构。** 例如某节点在教材里属于「镇静催眠药」，但在纸质思维导图中可能作为另一个大分支下的三级节点。两者可以同时成立，互不冲突。
6. 不为了让 location 与纸图层级一致而修改教材真实位置——location 记录的是"教材里在哪"，不是"图里画在哪"。
7. 节点详情面板可以完整展示 location，但主思维导图默认不把它展开为额外视觉编码。

## 六、口诀双轨制

口诀必须**双轨呈现**，缺一不可：

1. **独立口诀节点**（`fill: cls-mnemonic`）：由口诀节点自身的 `edges_out` 写 `part_of → 纸质版中挂载的节点`
2. **同时写入挂载节点的 summary**：口诀写入它在纸质版中所挂载的那个节点的 `summary.short` 末尾，用 `；` 与前半段分隔

### 口诀归属：完全以纸质版挂载位置为准

口诀在纸质版中挂在哪个节点下，电子版就 `part_of` 指向哪个节点，同时写入该节点的 summary：

| 纸质版挂载位置 | 电子版 part_of 指向 | 同时写入 | 示例 |
|---|---|---|---|
| 挂在具体药物下 | 该药物节点 | 该药物 `summary.short` 末尾 | 丁苯酞口诀 → 丁苯酞 |
| 挂在分类下 | 该分类节点 | 该分类 `summary.short` 末尾或 full【口诀】 | 酰胺类口诀 → 酰胺类中枢兴奋药 |
| 挂在作用特点下 | 该作用特点节点 | 该作用特点 `summary.short` 末尾 | 爸比不焦急 → 巴比妥类作用特点 |
| 挂在典型不良反应下 | 该不良反应节点 | 该不良反应 `summary.short` 末尾 | — |
| 挂在节/章入口下 | 该节/章节点 | 该节/章 `summary.short` 末尾 | 章节级口诀 → 节入口 |

**判断标准**：口诀内容记住的是哪个节点的知识，就指向哪个节点。纸质版中画在谁的子分支下，就指向谁。

### 口诀节点 label

直接写口诀内容本身（如 `爸比不焦急。`），不用"XX口诀"式命名。

### 反模式

- ❌ 只有独立口诀节点，没在挂载节点同步内嵌
- ❌ 只在挂载节点 summary 里写口诀，没建独立口诀节点
- ❌ 口诀归属错位（如把挂在作用特点下的口诀 part_of 指向药物节点）
- ❌ 口诀节点用 `subclass_of` / `instance_of` 挂到分类下（口诀是辅助节点，必须用 `part_of`）

## 七、临床内容下沉模式

药物节点的临床内容（药理作用、适应症、禁忌、相互作用）**写入 `summary.full`**，不拆成独立边。

| 场景 | 做法 |
|---|---|
| 药物→疾病的对应关系需要图谱导航 | `instance_of` 边 + 独立疾病节点 |
| 药物的药理/适应症/禁忌/相互作用是知识文本 | `summary.full` 内嵌 |
| 单纯的文字描述考点 | `summary.full` 内嵌 |

**分类节点内容归属**：
- 分类的定义、范围、作用机制 → 分类节点自身 summary
- 分类下普通药名单 → 分类节点 `full【代表药】`
- 分类下重点药的药理/适应症/禁忌 → ❌ 不允许写入分类节点，必须单独建药物节点

## 八、YAML 规范

### 8.1 多行字符串必须用 block scalar

所有可能跨行的字符串字段，必须用 `|` 标记：

```yaml
# ✅ 正确
full: |
  【药理作用】...

  【适应症】...

# ❌ 错误（换行被折叠成空格）
full:
  【药理作用】...

  【适应症】...
```

适用：`summary.full`（最常用）、`summary.short`（较长时）、`reason`。

### 8.2 `**` 开头的值必须加引号

```yaml
# ✅ 正确
short: "**苯二氮䓬类**长效代表药。"

# ❌ 错误（YAML 把 ** 解析为 alias，报错）
short: **苯二氮䓬类**长效代表药。
```

### 8.3 block scalar 关键细节

- `|` = literal（保留所有换行，推荐）；`>` = folded（折成单行，少用）
- body 缩进必须严格大于 key 的缩进至少 1 格
- 单行字符串无需加 `|`，仅当实际跨行时才必须加
- `id`/`label`/`shape`/`fill`/`stroke` 等结构字段永远单行，不加 `|`

## 十、同名节点重写规则

### 10.1 frontmatter 字段（严格重写）

| 字段 | 处理 |
|---|---|
| `id` | **保留原值**（保持 ID 不变以免破坏边） |
| `label` | **保留原值**（除非用户明确要求改名） |
| `location` | 可参考（仅作为目录位置依据） |
| `shape`/`fill`/`stroke` | **不沿用**，按新资料重新判定 |
| `tags` | **不沿用**，按规则重新抽取 |
| `edges_out` | **重建**（按新资料，不保留旧边除非用户指示） |
| `summary.short` | **不沿用旧文本**，按用户新资料重写 |
| `summary.full` | **不沿用旧文本**，用户未提供的部分必须留空 |

### 10.2 正文（宽松保留）

| 场景 | 处理 |
|---|---|
| 已有同名节点，正文已有内容，未要求重写 | **保留旧正文** |
| 用户明确要求"重写正文" | 按用户提供的新正文替换 |
| 新增节点，用户未提供正文 | **正文留空**，不写占位符 |

批量迁移旧节点时按此表转换。**迁移后 shape 统一填 `auto`**，让 fill 的默认形状生效——除非原节点有明确的"用某种形状表达"的语义意图（罕见）。

|---|---|---|---|
| module | cls-structure | auto | auto |

| strict-class | cls-classification | auto | 有临床评价 → glow |
