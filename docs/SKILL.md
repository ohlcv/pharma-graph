# Pharma Mindmap Transcribe — 纸质思维导图 → 节点 md

把纸质思维导图照片忠实转录为符合规范的独立节点 `.md` 文件。

**开始任何转录前必须读取：**
- `docs/frontmatter.md` — 通用字段定义、OWL2 实体类型、三维度视觉编码（权威）
- `docs/RULES.md` — 药学领域特化参数：fill 取值、外观配置、渲染参数、迁移映射

> 本 SKILL 与 RULES 冲突时，以 RULES.md 为准。

---

## 一、关键硬性约定（违反即不合规）

### 1.1 文件名 = label（中文）

- **文件名** = `label`（中文），如 `地西泮.md`、`苯二氮䓬类.md`
- **`id`** = 英文/拉丁文，用于图的 id 寻址、edges_out 引用
- 两者分工，不可混用

### 1.2 id 命名格式

**`id` = 前缀-节点英文名-书简写-章号-节号**

| 前缀 | 节点类型 | fill | 示例 |
|---|---|---|---|
| `bk-` | 书/篇级入口 | cls-structure | `bk-y2` |
| `ch-` | 章入口 | cls-structure | `ch-cns-y2-01` |
| `sec-` | 节入口 | cls-structure | `sec-sedative-y2-01-01` |
| `cls-` | 分类节点 | cls-classification | `cls-benzodiazepine-y2-01-01` |
| `med-` | 重点药 | cls-drug | `med-diazepam-y2-01-01` |
| `drug-` | 普通药 | cls-drug | `drug-trizolam-y2-01-01` |
| `ill-` | 疾病 | cls-disease | `ill-insomnia-y2-01-01` |
| `bio-` | 生物实体 | cls-biomolecule | `bio-cyp3a4-y2-01` |
| `feat-` | 作用特点/评价 | cls-feature | `feat-barbiturate-feature-y2-01-01` |
| `adr-` | 不良反应/禁忌 | cls-adverse | `adr-barbiturate-y2-01-01` |
| `cpt-` | 抽象概念/总论 | cls-concept | `cpt-liver-enzyme-y2-01` |
| `meta-` | 总结 | cls-summary | `meta-cyp1a2-summary-y2-01` |
| `mem-` | 口诀 | cls-mnemonic | `mem-barbiturate-y2-01-01` |

章节后缀：`y1`=药一、`y2`=药二、`y3`=药综、`y4`=法规，格式 `{书简写}-{章号}-{节号}`。

### 1.3 summary.full 禁止 AI 自动填充

- `full` 仅当用户主动提供文本时写入
- 缺用户资料时 `full` 完全不写（YAML 解析为 null，UI 隐藏展开按钮）
- 禁止"按药理推断"填充、禁止占位符（"待补充"）、禁止模板套用

### 1.4 视觉优先级

- **shape / stroke 不填时由 fill 决定**，显式填写时覆盖 fill 默认值（最高优先级）
- 多数节点不填 shape/stroke，由 fill 默认配置即可；只有需要"显式几何形状"或"流光/光晕边框"时才填
- shape 是 OWL2 实体类型（6 种 + auto），每个对应一个固定几何形状，详见 RULES §二

### 1.5 平铺结构（无 data 包装）

所有字段直接平铺，不使用 `data:` 包装：

```yaml
---
id: med-diazepam-y2-01-01
label: 地西泮
shape: auto
fill: cls-drug
stroke: flow
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
tags:
  - 地西泮
  - 苯二氮䓬类
summary:
  short: "**苯二氮䓬类长效代表药**；抗焦虑、镇静催眠、抗癫痫。"
  full: |
    【药理作用】...
edges_out:
  - target: cls-benzodiazepine-y2-01-01
    type: instance_of
    reason: 属于苯二氮䓬类
---
```

## 二、工作流（按序执行）

### Step 1 — 读规范

读取 `docs/frontmatter.md` 与 `docs/RULES.md` 全文。字段定义、shape 取值（OWL2 实体类型 → 固定几何形状）、fill 取值、stroke 渲染参数，全部以这两份文档为准。

### Step 2 — 读照片（放大、多轮细读）

1. 下载/读取全部思维导图照片（多张图时逐张读取）
2. 文字过小或过密时放大裁剪再读，必要时按区域细读
3. 记录：分支结构、各节点名称、药物画像正文、荧光笔高亮、手写补充、口诀文字

### Step 3 — 用户确认模糊点（不猜）

识别所有读不清/有歧义的内容，**带着自己的判断和答案**一次性列出向用户确认：
- OCR 模糊的药名/术语
- 归属不明的口诀（哪条口诀挂哪个药/分类）
- 手写补充的含义与位置
- 命名分歧（如「枸橼酸托法替布 vs 托法替布」）

### Step 4 — 建节点（每个节点单独一个 md）

- **输出目录**：按 `书名/章名/节名/` 建目录
- **文件名**：严格等于 `label`（中文）
- 每个节点一个文件，frontmatter 含 `id/label/location/shape/fill/stroke/tags/summary/edges_out`
- 按「结构节点原则」（见 §四）处理通用结构词
- 按「照片转录规则」（见 §三）提取内容
- 口诀节点独立建 md，同时按双轨制写入主知识节点 summary

### Step 5 — 自查（每个节点）

按 §九质量检查清单逐项检查。

### Step 6 — 分批交付

一次可处理多个节点，交付时分批呈现（如按分支分组），最终汇总总数与层级结构。汇报中明示：
- 哪些 short/full 是用户提供的、哪些留空
- 哪些是手写/高亮/印刷来源
- 口诀归属
- 命名处理

## 三、照片转录规则（提取→分析→拆解→重组）

### 3.1 内容映射

| 照片里的内容 | 写入哪 |
|---|---|
| 图中**本来就有**的具体药物节点的正文内容 | 该药物节点的 `summary.full` |
| 荧光笔划住的关键词/短语 | **重组**为该节点的 `summary.short`（关键词用 `**…**` 加粗） |
| 用户**手写补充**的文字（不在原图里） | 写入对应节点的 `summary.short`（手写补充是判断考点/重点的依据） |

### 3.2 来源优先级（从高到低）

1. **手写补充 > 图中原有**：用户手写的一定是新信息（强调/补充/订正），优先按手写内容写
2. **荧光笔划住 > 普通印刷**：荧光笔划住的内容是核心考点，**重组成 short**，而非照搬原句
3. **图中普通印刷**（非荧光笔）→ 该节点的 `full` 素材来源；非核心描述可酌情忽略
4. **同药物在多张照片出现** → 以"最新一张"为准；之前照片的差异向用户确认是否并入

### 3.3 重组规则（short 字段）

- 把荧光笔划住的关键词**重新组织**成一句话，不是直接复制粘贴
- 关键词用 `**…**` 加粗
- 结构：核心特点 + 核心用途，一句话
- 不重复 full 已有的【适应症】段标签

**正模式**：
- 原图高亮"组胺类、改善微循环血供" → 重组为 `组胺类药物，改善微循环血供，用于脑血管疾病和**内耳眩晕症**`
- 原图高亮"吡拉西坦是酰胺类中枢兴奋药" → 重组为 `酰胺类中枢兴奋药，促进脑内**Ach↑**，激活、保护神经细胞`

**反模式**：
- ❌ 把荧光笔划住的字直接复制粘贴进 short，没有重组
- ❌ 把图中所有文字无差别全部复制到 full
- ❌ 在没有照片提供的节点上"按图谱惯例"自动推断 short

### 3.4 full 字段转录

- 保留原图的【药理作用】【适应症】【禁忌】等段落标签
- 按 §五.2 格式规范写
- 必须用 `full: |`（block scalar）让 YAML 保留换行

## 四、结构节点原则（以原版纸质图为准 + 电子版扁平化）

### 4.1 核心原则

1. **以原版纸质思维导图为准**：转录时重点关注纸质版的每一个框及其结构
2. **认清原版局限性**：原版受纸张大小限制，需要结构节点分区；电子版不受此限制
3. **通用结构词不单独建空壳节点**：能融合就融合，必须单独建的加前缀/后缀
4. **电子版可适当扁平化**：原版的多层结构分区可以压缩

### 4.2 通用结构词融合清单

| 通用结构词 | 处理方式 | 示例 |
|---|---|---|
| 总论 | 写入节入口节点的 `summary` | 镇静催眠药总论 → 写入「镇静催眠药」summary |
| 分类 | 不单独建，分类节点本身就是分类 | 「巴比妥类」直接挂节入口 |
| 代表药物 | 写入分类节点的 `summary.full【代表药】` | 长效代表药 → 写入「巴比妥类」full |
| 临床用药评价 | 不单独建，下沉为「XX作用特点」「XX典型不良反应」 | 巴比妥类临床用药评价 → 「巴比妥类作用特点」+「巴比妥类典型不良反应」 |
| 作用机制 | 写入分类/药物节点的 `summary` | 非特异性抑制中枢 → 写入「巴比妥类」summary |
| 作用特点 | 必须单独建时加分类名前缀 | 「巴比妥类作用特点」 |
| 典型不良反应 | 必须单独建时加分类名前缀 | 「巴比妥类典型不良反应」 |
| 总结 | 节内总结可建节点，跨节大总结建节点 | 「不同种类镇静催眠药剂量与药理作用关系」 |

### 4.3 融合 vs 单独建节点决策

| 情况 | 处理 |
|---|---|
| 总论内容简短（1-2 句） | 写入节入口 `summary.short` |
| 总论内容较长（多段） | 写入节入口 `summary.full` |
| 作用机制是分类的核心定义 | 写入分类节点 `summary` |
| 作用特点有独立正文（多段） | 单独建「XX作用特点」节点 |
| 典型不良反应有独立正文 | 单独建「XX典型不良反应」节点 |
| 口诀挂在作用特点下 | 口诀独立建节点，`part_of` 指向作用特点 |
| 普通药仅提名无画像 | 不单独建，写入分类 `full【代表药】` |
| 重点药有完整药理卡片 | 单独建药物节点 |

### 4.4 前缀/后缀命名规范

必须单独建节点时，**必须加具体药名/分类名作为前缀或后缀**，禁止使用裸通用词：

| ✅ 正确 | ❌ 错误 |
|---|---|
| 巴比妥类作用特点 | 作用特点 |
| 地西泮临床应用注意 | 临床应用注意 |
| 丙戊酸钠典型不良反应 | 典型不良反应 |
| 苯二氮䓬类药物相互作用 | 药物相互作用 |

### 4.5 普通药处理

- 普通药不单独建节点，放在分类节点的 `summary.full【代表药】` 里
- 原版中"长效：苯巴比妥、巴比妥"这种一个框多药的情况，普通药写入分类节点 full
- 如果某个普通药后续有了详细画像，再升级为独立药物节点

### 4.6 原版结构 → 电子版结构转换示例

**原版**：
```
镇静催眠药
├─ 分类与作用机制
│   └─ 分类
│       └─ 巴比妥类（非特异性抑制中枢）
│           ├─ 长效：苯巴比妥、巴比妥
│           └─ 超短效：硫喷妥钠
│   └─ 总论
├─ 临床用药评价
    └─ 巴比妥类
        ├─ 作用特点 → xxx → 口诀：爸比不焦急
        └─ 典型不良反应 → xxx
```

**电子版（扁平化后）**：
```
镇静催眠药（节入口，summary 含总论）
├─ 巴比妥类（分类，summary 含"非特异性抑制中枢"，full 含代表药）
│   ├─ 巴比妥类作用特点（part_of）
│   │   └─ 巴比妥类口诀（part_of 作用特点）
│   ├─ 巴比妥类典型不良反应（part_of）
│   └─ 硫喷妥钠（instance_of，重点药单独建）
```

## 五、字段制作规范

### 5.1 shape / fill / stroke

- **fill**（必填）：药学顶层类 IRI，决定背景色 + 默认形状 + 默认边框。取值见 RULES §三
- **shape**（可选）：OWL2 实体类型，每个类型对应**一个固定几何形状**（映射见 RULES §二）。合法值：`auto` / `class` / `named_individual` / `object_property` / `data_property` / `annotation_property`
  - **不填或 `auto`**：用 fill 的默认形状（可访问 FILL_CONFIG 中的扩展形状如 vee / tag / barrel）
  - **显式填写**：用映射表的固定形状，**覆盖** fill 的默认形状
- **stroke**（可选）：不填或 `auto` 时由 fill 决定；显式填写时覆盖 fill 默认边框。合法值：`auto` / `flow` / `glow`

**覆盖示例**：

```yaml
# 例 1：默认情况 —— 让 fill 的扩展形状生效
fill: cls-mnemonic
# 不填 shape → 节点是 V 形（vee，扩展形状）

# 例 2：覆盖 fill —— 让口诀用椭圆
fill: cls-mnemonic
shape: named_individual  # → 椭圆（覆盖 V 形）

# 例 3：关系实体化 —— "治疗" 边转成节点
fill: cls-feature
shape: object_property   # → 六边形
```

**重点药 vs 普通药**：
- 重点药（教材有完整药理卡片）：`fill: cls-drug, stroke: flow`
- 普通药（仅提名）：`fill: cls-drug, stroke: auto`

**重点分类 vs 普通分类**：
- 重点分类（有临床用药评价详细讲解）：`fill: cls-classification, stroke: flow`
- 普通分类：`fill: cls-classification, stroke: auto`

### 5.2 summary 格式规范

#### short 格式

- 关键词用 `**…**` 加粗
- 结构：核心特点 + 核心用途，一句话
- 以 `**` 开头时必须加双引号（YAML 会把 `**` 解析为 alias）

```yaml
short: "**苯二氮䓬类长效代表药**；适应证包括**抗焦虑、镇静催眠、抗癫痫抗惊厥**；**妊娠妇女和新生儿禁用**。"
```

#### full 格式（【标签】+ 段落）

- 多段结构，每段以 `【标签】` 起头
- 常用标签：`【药理作用】` `【适应症】` `【禁忌】` `【不良反应】` `【相互作用】` `【药代动力学】` `【临床应用注意】` `【代表药】` `【口诀】`
- **段落之间必须空行**（否则 marked 不会拆出多个 `<p>`）
- 关键医学术语 `**加粗**`，多项用 `- ` markdown 列表
- 必须用 `full: |`（block scalar）

```yaml
full: |
  【药理作用】抑制合成嘧啶的**二氢乳清酸脱氢酶**，使活化 B 细胞的生长受抑制。

  【适应症】
  - 适用于**成人类风湿关节炎**（有改善病情作用）、**狼疮性肾炎**。
  - **半衰期长**，间隔 24h 给药一次。

  【禁忌】妊娠期、哺乳期、严重肝、肾损伤者禁用。
```

**禁止**：`(1)(2)(3)` 半角括号编号、整段不换行、`#` 标题、HTML 标签。

#### 关键词加粗判定

满足任一条即可加粗：药理学机制名词、适应症（疾病名）、禁忌关键人群/关键药名、用户手写补充强调的词、荧光笔划住的关键词、不良反应/严重警告。

**不加粗**：整段一句话加粗、"用于""是""的""和"等连接词。

### 5.3 tags 抽取规则

#### 三铁律

1. **复用优先**：summary 里已有合适关键词直接复用，不另造同/近义词
2. **去重优先**：不写语义重复的标签（`口诀` 与 `记忆口诀`、`禁忌` 与 `禁用` 不并存）
3. **不杜撰**：严禁把 summary 里没出现的概念放进 tags

#### 节点类型专属规则

| 节点类型 | tags 必须包含 |
|---|---|
| 药物节点（cls-drug） | 药品名 + 至少一个分类 tag + 至少一个作用 tag |
| 分类节点（cls-classification） | 自身 label + 子分类名（如有）+ 重点代表药（普通药不标记） |
| 口诀节点（cls-mnemonic） | 对应的药品名/分类名（label 改为口诀内容本身） |
| 模块节点（cls-structure） | 一般不建 tags，有需求按具体内容抽取 |

#### 抽取流程

1. 扫 summary：抽出所有 `**加粗**` 短语/专有名词/药理分类词
2. 按三铁律 + 节点类型专属规则过滤
3. 语义去重
4. 兜底自取（仅当前几步拿不到目标数量时）：基于 summary 上下文自取，**必须向用户汇报"自取了哪些"**

### 5.4 edges_out 填写规则

#### 边方向铁律：每个节点自管自己的 edges_out

所有 `edges_out` 都表示"这个节点向外辐射的引用关系"，发起方在自己的 md 文件里写。

| 关系 | 由谁写 |
|---|---|
| 类-类层级（子类→父类） | 子类写 `subclass_of → 父类` |
| 局部-整体（局部→整体） | 局部写 `part_of → 整体` |
| 个体-类（实例→类别） | 实例写 `instance_of → 类别` |
| 辅助学习（口诀→主知识） | **辅助节点**写 `part_of → 主知识节点` |
| 等价/互斥/同一（双向） | **任一侧**写，存一条即可 |

**禁止**：
- ❌ 父节点写一堆 edges_out 指向子节点
- ❌ 双向边正反都写
- ❌ 用 `subclass_of` 表达 `part_of`

#### 6 种边类型

| type | 语义 | 方向 |
|---|---|---|
| `subclass_of` | 类-类，A 是 B 的一种 | 子类→父类 |
| `instance_of` | 个体-类，A 是 B 的实例 | 实例→类别 |
| `part_of` | 局部-整体，A 是 B 的构件 | 局部→整体 |
| `disjoint_with` | 互斥（对称） | 任一侧 |
| `equivalent_to` | 类等价（对称） | 任一侧 |
| `same_individual` | 个体同一/别名（对称） | 任一侧 |

#### reason 措辞规范

- **必填**，不可空
- 必须包含具体对象（药名/分类名/疾病名），不能是"治疗""相关"等空泛词
- 必须能独立成句

### 5.5 location 字段

```yaml
location:
  book: 药学专业知识二
  chapter: 第一章 精神与中枢神经系统用药
  section: 第一节 镇静催眠药
  item: 一、（一）①   # 可选，节内排序/子项
```

- 书/章/节名称与目录一致
- 节入口节点的 location 就是自身
- 子节点的 location 继承所属节
- `item`（可选）：节内排序或子项编号，用于同名多节点的区分（如"第一节 一、（一）① vs 一、（一）②"）

## 六、口诀双轨制

口诀必须**双轨呈现**，缺一不可：

1. **独立口诀节点**（`fill: cls-mnemonic`）：由口诀节点自身的 `edges_out` 写 `part_of → 主知识节点`
2. **同时写入主知识节点的 summary**：药物口诀写入该药物 `summary.short` 末尾，用 `；` 与前半段分隔

| 口诀类型 | 独立节点 | 同时写入 |
|---|---|---|
| 药物口诀 | ✅ | 该药物节点的 `summary.short` 末尾 |
| 分类口诀 | ✅ | 该分类节点的 `summary.short` 末尾或 full 的【口诀】段 |
| 章节级口诀 | ✅ | 该节/章节点的 `summary.short` 末尾 |

**口诀节点 label**：直接写口诀内容本身（如 `爸比不焦急。`），不用"XX口诀"式命名。

**反模式**：
- ❌ 只有独立口诀节点，没在主知识节点同步内嵌
- ❌ 只在主知识节点 summary 里写口诀，没建独立口诀节点
- ❌ 把药物口诀写到分类节点的 summary 里（归属错位）

---

## 七、临床内容下沉模式

药物节点的临床内容（药理作用、适应症、禁忌、相互作用）**写入 `summary.full`**，不拆成独立边。

| 场景 | 做法 |
|---|---|
| 药物→疾病的对应关系需要图谱导航 | `instance_of` 边 + 独立疾病节点 |
| 药物的药理/适应症/禁忌/相互作用是知识文本 | `summary.full` 内嵌 |
| 单纯的文字描述考点 | `summary.full` 内嵌 |

**分类节点内容归属**：
- 分类的定义、范围、作用机制 → 分类节点自身 summary
- 分类下普通药名单 → 分类节点 `full【代表药】`
- 分类下重点药的药理/适应症/禁忌 → ❌ 不允许写入分类节点，必须单独建药物节点

## 八、YAML 规范

### 8.1 多行字符串必须用 block scalar

所有可能跨行的字符串字段，必须用 `|` 标记：

```yaml
# ✅ 正确
full: |
  【药理作用】...

  【适应症】...

# ❌ 错误（换行被折叠成空格）
full:
  【药理作用】...

  【适应症】...
```

适用：`summary.full`（最常用）、`summary.short`（较长时）、`reason`。

### 8.2 `**` 开头的值必须加引号

```yaml
# ✅ 正确
short: "**苯二氮䓬类**长效代表药。"

# ❌ 错误（YAML 把 ** 解析为 alias，报错）
short: **苯二氮䓬类**长效代表药。
```

### 8.3 block scalar 关键细节

- `|` = literal（保留所有换行，推荐）；`>` = folded（折成单行，少用）
- body 缩进必须严格大于 key 的缩进至少 1 格
- 单行字符串无需加 `|`，仅当实际跨行时才必须加
- `id`/`label`/`shape`/`fill`/`stroke` 等结构字段永远单行，不加 `|`

## 十、同名节点重写规则

### 10.1 frontmatter 字段（严格重写）

| 字段 | 处理 |
|---|---|
| `id` | **保留原值**（保持 ID 不变以免破坏边） |
| `label` | **保留原值**（除非用户明确要求改名） |
| `location` | 可参考（仅作为目录位置依据） |
| `shape`/`fill`/`stroke` | **不沿用**，按新资料重新判定 |
| `tags` | **不沿用**，按规则重新抽取 |
| `edges_out` | **重建**（按新资料，不保留旧边除非用户指示） |
| `summary.short` | **不沿用旧文本**，按用户新资料重写 |
| `summary.full` | **不沿用旧文本**，用户未提供的部分必须留空 |

### 10.2 正文（宽松保留）

| 场景 | 处理 |
|---|---|
| 已有同名节点，正文已有内容，未要求重写 | **保留旧正文** |
| 用户明确要求"重写正文" | 按用户提供的新正文替换 |
| 新增节点，用户未提供正文 | **正文留空**，不写占位符 |
