# 思维导图节点拆分规则

> 适用范围：把每张手绘思维导图转写为项目知识图谱的可浏览节点。
> 原则：忠实转录、不补充未在图中出现的内容；合理设计目录、避免过细拆分；严格沿用现有 Frontmatter 字段约定，新节点兼容现有系统。
>
> **与** **[REFACTOR-RULES.md](./REFACTOR-RULES.md)** **的关系**：本文档描述**新建节点**（拆分）；REFACTOR-RULES.md 描述**已有图谱的合并与骨架补齐**。两本手册方向相反但共用同一套 frontmatter 字段与 schema 规则。

> ⚠️ **口诀节点禁止独立成文件**：记忆口诀（包括代表药口诀、药理口诀、不良反应口诀、分类口诀、方案口诀等）一律写入对应主节点正文的 `## 记忆口诀是什么？` 段，**不得创建独立的** **`*口诀.md`** **节点文件**。详见 [REFACTOR-RULES.md](./REFACTOR-RULES.md) § 零。

***

## 一、核心原则

1. **现有节节点不修改**：每张思维导图对应的"节"已经存在节点（例如 `第二节 抗癫痫发作药物.md`），它就是这张图的根节点 / 容器节点，不替换也不改动。
2. **新节点只增不改**：新节点仅在现有节节点下新建同名的子目录中创建（例如 `第二节 抗癫痫发作药物/xxx.md`），不覆盖、不修改现有节节点的 frontmatter。
3. **沿用现有 Frontmatter 字段**：仅使用现有约定的字段（`id`、`label`、`essence`、`field`、`tier`、`location`、`tags`、`summary`、`edges_out`），不引入新字段、不新增枚举值。
4. **忠实转录**：只收录思维导图出现的内容，不补充学科常识、不补充图中未涉及的适应证、不补充额外机制。
5. **合理粒度**：拆分到"独立可学的知识实体"为止；过细的内容（如每一个不良反应、每一个剂量数字）不独立成节点，写入其所属药物/监护节点的正文。

***

## 二、节点类型映射（essence）

思维导图中的内容按其本质映射到现有 9 种 essence：

| 思维导图内容                               | essence       | 形状              | tier        |
| ------------------------------------ | ------------- | --------------- | ----------- |
| 药物类别（巴比妥类、苯二氮䓬类…）                    | `module`      | round-rectangle | management  |
| 具体药物（苯妥英钠、卡马西平…）                     | `medication`  | ellipse         | drug        |
| 作用机制（钠通道阻滞、GABA 增强…）                 | `process`     | star            | mechanism   |
| 监护主题、临床评价、口诀、理论术语（用药监护、起效延迟…）        | `notion`      | octagon         | management  |
| **具体疾病、症状综合征、病理状态**（高血压、青光眼、阿尔茨海默病…） | **`illness`** | **diamond**     | **disease** |
| 章节入口（节级节点，已经存在）                      | `section`     | tag             | management  |

> 字段 / tier 选择参考 [frontmatter.md 中字段约定](./frontmatter.md)。**旧版本中的** **`concept`** **essence 已废弃**（参见 frontmatter.md § 1.2），全仓 47 个 `concept-*` 前缀节点将在后续重构中批量改为 `notion`，过渡期间不阻断构建。

### § 二.5 疾病节点拆分原则（illness 节点必建，不是 tag）

**核心原则**：具体的疾病、症状综合征、病理状态在图谱中是一等公民，**必须**拥有独立 `.md` 节点（`essence: illness`、`tier: disease`、形状 `diamond`）。这与"具体药物必须独立成 medication 节点"是同等重要的设计。

**为什么不能只作 tag：**

1. `medication` 节点的 `treats` / `contraindicates` 边需要指向**独立疾病节点**（`target` 必须是真实节点 id，不能指向不存在的 tag）
2. `diamond` 形状是图谱中视觉识别"这是一个独立疾病"的关键信号；如果只是 tag，读者看不到菱形节点
3. `tier: disease` 与 `essence: illness` 是 1:1 对应关系，避免再出现"既有 tier:disease 又有 section 节点"的混乱

**判定该建独立 disease 节点的阈值：**

满足以下任一条件，应建立独立 `.md` 节点：

- 全仓 `tag` 引用 ≥ 2 次（即该疾病名作为适应证 tag 出现在 ≥ 2 个 medication / module 节点中）

- 是 `medication` 节点的 `treats` 边的目标（不管数量）

- 是 `medication` 节点的 `contraindicates` 边的目标（不管数量）

**判定为不应建独立节点（仍可作 tag 出现）：**

- 一次性出现的临床症状（发热、疼痛、便秘）—— 这些是症状 `tag`，不是疾病

- 教材无独立章节、药师不会单独检索的极小概念

- 仅为章节命名服务、且正文不带具体诊疗内容的章节标题

**疾病节点 id 命名约定：**

- `<disease-name>-management` 或 `<disease-name>-disease` 二选一

- 与现有节节点命名保持一致：疾病治疗/管理类用 `-management`（如 `hypertension-management`），单纯病理/疾病实体用 `-disease`

**illness 节点位置**：

- 默认与所治疗的药物放在同一目录（如"抗高血压药"目录下的 `hypertension-management`）

- 若疾病跨多个节，建立在最常用药物目录；正文 `## 它在知识体系里的位置` 段交代跨节位置

**illness 节点的最低边要求**（参见 frontmatter.md § 一 各类节点最低边数）：

- 1 条 `isa` 边指向疾病分类父节点（如"高血压 → 心血管系统疾病"）

- ≥1 条上游治疗药 `treats` 边指向本节点（即由 medication 节点写 `treats → hypertension-management`）

## 三、目录与文件布局

```
药学专业知识二/
└── 第一章 精神与中枢神经系统用药/
    ├── 第二节 抗癫痫发作药物.md             # 已有节节点（不动）
    └── 第二节 抗癫痫发作药物/                 # 新建同名子目录
        ├── 巴比妥类.md                       # module
        ├── 苯二氮䓬类.md                     # module
        ├── …
        ├── 苯妥英钠.md                       # medication
        ├── 卡马西平.md                       # medication
        ├── …
        ├── 钠通道阻滞.md                     # process
        ├── GABA 增强.md                      # process
        ├── …
        └── 抗癫痫药用药监护.md               # concept
```

布局规则：

- 子目录名与节节点文件名一致（沿用 `第一节 口服固体制剂/美托洛尔.md` 的现有模式）。

- 所有子节点平铺在该子目录下，不在其下再开二级子目录。

- 文件命名：中文 label 直接作文件名（特殊符号按 URL 安全方式处理，如 `γ-氨基丁酸类似物.md`）。

## 四、edges\_out 写法

| 关系类型              | 方向          | 用途                              |
| ----------------- | ----------- | ------------------------------- |
| `isa`             | 子 → 父       | 类别归属（药物 → 类别 → 节）；机制 → 节；监护 → 节 |
| `mechanism`       | 药物 → 机制     | 药物使用该机制                         |
| `causes`          | 药物 → 不良反应节点 | 暂不新建独立不良反应节点，正文表达               |
| `interacts`       | 药物 ↔ 药物     | 暂不新建，正文表达                       |
| `contraindicates` | 药物 → 状态     | 暂不新建，正文表达                       |
| `prerequisite`    | 先修概念 → 后修概念 | 节节点 → 监护 / 机制（理解用药要懂机制）         |

写入要求：

- 至少 1 条 `isa`（除 book 根节点外，规则来源：[frontmatter.md § 层级关系](./frontmatter.md)）。

- 父节点不需要反向写出"我包含哪些子节点"（与现有 § 一致）。

- 边的 `target` 必须指向仓库已有节点 ID（不存在的需先创建）。

- 不重复同一对层级关系成双向。

## 五、tag / summary / 正文规范

### tags

- 3–8 个；不与 `field`、`tier` 重复。

- 维度优先选：机制类型、临床特点、患者人群、临床场景、药物分类属性、监护重点。

### summary

- `short` ≤ 40 字，纯陈述句，不含"本节/本章"。

- `full` ≤ 100 字，是 `short` 的扩展，交代背景或临床价值。

### 正文

沿用节节点的"五问体"结构，但可根据节点类型调整：

- `medication`：`它是什么？为什么要学？它和什么有关？它在什么阶段出现？它在知识体系里放哪里？`

- `module`：`它属于什么分类？分类依据是什么？下面有哪些代表药物？它和节的关系是什么？`

- `process`：`机制是什么？它作用于什么靶点？哪些药物使用此机制？它对临床选药有什么意义？`

- `concept`（监护）：`监护在讲什么？为什么要监护？监护哪些维度？特殊人群要注意什么？它在节里处于什么位置？`

正文信息**全部来自思维导图**，不补充未出现的内容。

## 六、拆分粒度白名单 / 黑名单

### 白名单（应独立成节点）

- 化学结构分类（巴比妥类、苯二氮䓬类、乙内酰脲类、二苯并氮䓬类、γ-氨基丁酸类似物、脂肪酸类、磺胺类）

- 思维导图中明确列出的具体药物

- 思维导图中明确列出的作用机制

- 思维导图中作为独立分支的监护主题

### 黑名单（不独立成节点，写入正文）

- 单个不良反应名称（眩晕、嗜睡、共济失调…）

- 单个禁忌项（房室传导阻滞、皮肤损伤…）

- 特殊人群（妊娠期、哺乳期、儿童、老年人、驾驶员）

- **泛指的"适应证类型"词**（抗惊厥、抗癫痫、抗炎、抗菌）——这些是功能描述，不是具体疾病，按"临床应用"或"代表药核心考点"段写入对应伞形正文，**不**独立成节点。注意与"具体疾病名（如高血压、阿尔茨海默病）"区分（见下文 § 二.5 疾病节点拆分原则）

- 给药方法、剂量数字、给药细节

- 注意事项、用药交代的具体要点

- **概念性 concept 节点**（如"首过效应""足量足疗程原则""止泻"等）—— 此类概念在思维导图中作为独立分支出现时，**应按其语义归属并入伞形 module 或节节点正文的对应段**（`## 机制` / `## 用药注意` / `## 临床应用` 等），不独立建节点。理由：这些概念本质是"主题的解释"而非"独立可学的知识实体"，单独成节点会导致 `in_deg = 0` 零散积累，详见 [REFACTOR-RULES.md § 二](./REFACTOR-RULES.md)。

## 七、同分子跨节复用（避免重复建节点）

**触发场景**：同一化学分子在多个节中被重复提及（如地西泮、苯巴比妥同时出现在"第一节 镇静催眠药、中枢肌松药"与"第二节 抗癫痫发作药物"）。

**判定原则（看场景）**：

| 场景                                   | 做法                                            |
| ------------------------------------ | --------------------------------------------- |
| 该分子的多节内容**差异大**（不同机制、不同 ADR、不同监护要点）  | 唯一文件 + 多归属（**首选方案**，见下文）                      |
| 各节内容**高度重叠**，只是同一主题在不同节中重复讲解         | 唯一文件 + 通过 `tags` 表达多归属，正文只保留一份详细解释            |
| 跨节归属**完全相同**（如同一节既是一般分类的成员又是特殊场景的代表） | 唯一文件 + `isa` 边指向分类伞形 + `prerequisite` 边指向相关机制 |

**首选方案：唯一文件 + 多归属**：

- ✅ 该分子在哪一节**首次**被思维导图覆盖，就只在那一节建一个 `.md` 文件

- ✅ 该文件存放该分子的**完整多节归属信息**（`location.section` 取首次归属节为目录定位）

- ✅ 通过 `tags` 表达多归属（加"跨节复用" tag + 各归属节的特征 tag）

- ✅ 通过 `edges_out` 表达跨节关系：

  - 各归属节下的分类节点（`isa`）、机制节点（`mechanism`）、特征节点（`prerequisite`）都需要从该文件反向指回去

  - 跨节归属节点的边在 `reason` 中标注所属节，例如 `地西泮在化学结构上属于苯二氮䓬类（第一节归属）`

- ✅ `summary.short` / `summary.full` 中说明跨节使用情况

- ✅ 文件正文（body）"它和节的关系？"部分列出全部归属节

- ✅ 其它节中的分类 / 机制节点引用该分子时，`target` 直接指向**唯一**的 id（如 `diazepam`、`phenobarbital`），不指向任何后缀变体

**绝对禁止**：

- ❌ 给同一分子在不同节下分别建立新 `.md` 文件（哪怕文件名加后缀如"地西泮（镇静催眠用途）.md"）

- ❌ 用后缀 id（如 `diazepam-sedative-myorelaxant`、`phenobarbital-sh`）做"伪区分"

- ❌ 重复文件中的内容（节归属、机制、标签等）造成数据冗余

**例外（允许 hybrid）**：

当一节点内容**确实不可拆分**（如地西泮在第一节"镇静催眠/中枢肌松药"用作中枢肌松药，在第二节"抗癫痫"用作抗癫痫药，两节用途的 ADR 谱与监护要点差异巨大），可：

- ✅ 唯一文件，正文按节分 `## 第一节归属 / ## 第二节归属` 标题

- ✅ `edges_out` 双向指向各归属伞形

- ✅ 节归属信息放 `tags` 与正文 `## 它和节的关系？` 段

- ❌ **不能**为了"清晰"而拆分为多个 md（违反全局唯一 id 原则）

**示例**：地西泮跨第一节与第二节使用

| 节点                                    | 归属节 | 说明                                                                                                                                            |
| ------------------------------------- | --- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `diazepam.md`（唯一文件，位于 `第二节 抗癫痫发作药物/`） | 第二节 | `location.section = 第二节 抗癫痫发作药物`；`tags` 含 `镇静催眠药`、`中枢肌松药`、`跨节复用`；`edges_out` 含 `benzodiazepines-sh`（第一节）与 `benzodiazepines-aed`（第二节）；正文列出两节归属 |
| `中枢肌松药分类.md`（第一节）                     | 第一节 | `edges_out` 中 `target: diazepam`（直接引用唯一 id，不加后缀）                                                                                              |

**为什么这样设计**：

1. **id 全局唯一**：图谱渲染、跨图引用、邻接查询都基于 id 字符串；后缀变体等于破坏图谱连通性
2. **目录归属清晰**：每节点只在一个目录下，避免文件分裂
3. **信息完整**：所有节中关于该分子的信息聚合在一处，查看时不会因为目录跳跃而漏掉内容
4. **边方向统一**：跨节 `isa`、`mechanism`、`prerequisite` 边都从该文件反向发出，方向规则与 ADR-0001 一致

## 八、ID 命名约定

- 英文 + 连字符；语义清晰；全局唯一。

- 类别：`<class>-aed`（例：`barbiturates-aed`、`benzodiazepines-aed`）。

- 药物：英文通用名（例：`phenytoin`、`carbamazepine`、`valproate`）。

- 机制：`<mechanism>-aed`（例：`sodium-channel-blockade-aed`、`t-type-calcium-blockade`、`gaba-enhancement`、`glutamate-inhibition`）。

- 监护：`<topic>-monitoring`（例：`antiepileptic-drug-monitoring`）。

## 十、产出物清单

每次完成一张思维导图，产出：

1. `第二节 xxx/隔离目录` 下的所有新节点 `.md` 文件
2. 至少 1 条 `isa` 边 + 必要的 `mechanism` 边
3. 对照思维导图的全分支清单验证（确保无遗漏、无额外补充）
