# frontmatter.md

> 本规范用于将**纸质思维导图完整、稳定地迁移为电子节点图**。
>
> 核心原则：**不追求把所有药学关系都拆成独立类型，而优先忠实还原纸质资料中的“节点—层级—分支—关系—学习辅助”结构。**
>
> 当前图谱仅使用四个可视化语义维度：
>
> 1. `essence` → 节点形状
> 2. `level` → 节点边框色
> 3. `tier` → 节点填充色
> 4. `edges_out.type` → 边的颜色、虚实与方向样式
>
> **禁止用字体、字号、字重、阴影、透明度、渐变、节点大小等额外视觉变量承载新的语义。**

***

## 一、Frontmatter 标准结构

```yaml
data:
  id: 唯一标识
  label: 显示名称
  essence: 节点本质
  level: 节点层级
  tier: 知识层级

  location:
    book: 根文件名
    part: 篇
    chapter: 章
    section: 节
    subsection: 子节
    item: 具体知识点

  tags:
    - XXX

  summary:
    short: 一句话定义
    full: 详细解释

  edges_out:
    - target: 对方节点 id
      type: 关系类型
      reason: 关系具体含义
```

### 字段总览

| 字段          | 类型            |        必填 | 可视化作用       | 核心含义             |
| ----------- | ------------- | --------: | ----------- | ---------------- |
| `id`        | `string`      |         ✅ | 无           | 节点唯一标识           |
| `label`     | `string`      |         ✅ | 节点文字        | 节点显示名称           |
| `essence`   | `enum`        |         ✅ | **形状**      | 节点本质/对象类型        |
| `level`     | `integer 1–6` |         ✅ | **边框色**     | 纸质思维导图中的一级至六级结构  |
| `tier`      | `enum`        |         ✅ | **填充色**     | 知识在药学体系中的自然层级    |
| `location`  | `object`      |         ✅ | **不参与图形编码** | 教材目录定位，仅用于节点详情展示 |
| `tags`      | `string[]`    |        可选 | 无           | 检索关键词及补充属性       |
| `summary`   | `object`      |        推荐 | 无           | 节点详情中的定义和解释      |
| `edges_out` | `object[]`    | ✅（根节点可为空） | **边样式**     | 与其他节点的显式关系       |

# 二、四个视觉语义维度

## 2.1 essence — 节点本质（决定形状）

`essence` 只回答一个问题：

> **“这个方框在知识体系里到底是什么？”**

形状必须具有稳定语义。同一种本质永远使用同一种形状，不允许因为内容重要程度、章节位置或个人喜好随意换形状。

### 当前标准本质类型

| `essence`        | 中文含义        | 建议形状              | 使用范围                     |
| ---------------- | ----------- | ----------------- | ------------------------ |
| `module`         | 结构模块/入口     | `round-rectangle` | 篇、章、节、主题入口等结构节点          |
| `classification` | 分类/分组标准     | `hexagon`         | 药物分类、亚类、分类依据、分组节点        |
| `concept`        | 概念/术语       | `octagon`         | 教材定义明确、具有边界的知识概念         |
| `medication`     | 具体药物/制剂     | `ellipse`         | 通用名、具体制剂、代表药物            |
| `illness`        | 疾病/病理状态/综合征 | `diamond`         | 可被治疗、禁忌、导致或独立讨论的疾病/状态    |
| `process`        | 机制/过程       | `star`            | 作用机制、体内过程、病理过程、流程        |
| `notion`         | 学习性认知单元     | `tag`             | 经验性认识、临床提示、易混概念、经验归纳     |
| `mnemonic`       | 记忆口诀        | `vee`             | 口诀、首字母记忆、顺口溜、分类速记        |
| `summary`        | 总结/归纳       | `pentagon`        | 对多个节点进行收束、压缩、归纳的总结节点     |
| `table`          | 表格/对照表      | `rectangle`       | 原纸图中需要作为独立知识载体展示的表格或对照结构 |
| `note`           | 注意/提示/笔记    | `round-tag`       | 【注意】、【提示】、易错提醒、补充说明      |

### 形状使用原则

1. **形状表达本质，不表达重要程度。**
2. **形状表达本质，不表达教材章节级别。**
3. `module` 统一承载篇、章、节等结构模块；具体层级交给 `level`。
4. `classification` 统一承载“分类/亚类/分组”概念，不再为每一种分类形式设计不同形状。
5. `mnemonic`、`summary`、`table`、`note` 均允许成为独立节点，以完整还原纸质资料中的独立视觉对象。
6. 原有 `route`、`substance` 等本质不再作为当前纸图迁移规范中的固定视觉类型；若未来纸质原稿反复出现具有独立视觉身份、且现有类型无法无歧义承载的对象，再单独增加本质类型。
7. 不为了“凑满 Cytoscape 形状”而创建本质类型。**形状数量以纸质资料实际需要为准。**

## 2.2 level — 思维导图结构级别（决定边框色）

`level` 与教材目录 `location` **完全独立**。

它回答：

> **“在这张纸质思维导图里，这个节点处在第几级？”**

### 类型

```yaml
level: 1
```

取值严格限制为：

```text
1 = 一级节点
2 = 二级节点
3 = 三级节点
4 = 四级节点
5 = 五级节点
6 = 六级节点
```

### 语义

| level | 含义    | 典型节点               |
| ----: | ----- | ------------------ |
|   `1` | 一级主节点 | 总主题、核心主题、一级大分支     |
|   `2` | 二级节点  | 一级主题下的主要分类/模块      |
|   `3` | 三级节点  | 二级节点展开出的知识分支       |
|   `4` | 四级节点  | 具体知识点、代表药物         |
|   `5` | 五级节点  | 考点维度、属性展开          |
|   `6` | 六级节点  | 最末级辅助：口诀、总结、注意、表格等 |

### 边框色规则

边框色只由 `level` 决定：

| level | 边框颜色语义 | 建议视觉   |
| ----: | ------ | ------ |
|   `1` | 一级色    | 最深的结构色 |
|   `2` | 二级色    | 深结构色   |
|   `3` | 三级色    | 中结构色   |
|   `4` | 四级色    | 中浅结构色  |
|   `5` | 五级色    | 浅结构色   |
|   `6` | 六级色    | 最浅结构色  |

> **说明：** 六级之间不再使用粗细、字体、阴影等方式区分。六级就是六级，视觉上保持同一层级稳定一致。

### 关键规则

- `level` 只表示**纸质思维导图的结构级别**。

- `level` 不表示疾病层、药物层、基础层等知识语义。

- `level` 不从 `location.chapter/section/...` 自动推导。

- 同一个教材章节中的两个节点，可以因为纸图中的组织方式不同而拥有不同 `level`。

- `location` 改变不会自动改变 `level`。

- 口诀、总结、表格、注意节点可以使用与其在纸图中实际所在位置相对应的 `level`，通常为 `4`、`5` 或 `6`。

### `level` 与父子关系（边方向判定）

> **`level` 是父 / 子判定的唯一依据。** `parent` 边永远由 `level` 数字大的子节点指向 `level` 数字小的父节点，**与 `essence`、`location` 无关**。

| 节点 A | 节点 B | 谁是父？ |
| --- | --- | --- |
| `level: 3` 分类 | `level: 4` 药物 | 分类（level 小） |
| `level: 4` 药物 | `level: 4` 口诀 | **平级**（同 level，无父子） |
| `level: 5` 考点 | `level: 4` 药物 | 药物（level 小） |

**平级关系**：同 `level` 的节点之间**不写 `parent` 边**，用 `contrast`（横向比较）或 `relate`（一般关联），或干脆不建边。

**辅助关系**：口诀（mnemonic）→ 药物（medication）这类"主知识 ↔ 辅助节点"关系**不按 level 判定父子**——它是同 level 的辅助关系，由**辅助节点自身**的 `edges_out` 写 `support →` 主知识节点（参见 §7.5 与 §9.4）。

***

## 2.3 tier — 知识层级（决定填充色）

`tier` 沿用原知识图谱的“自然层级”思想，不再表示思维导图的一级/二级/三级/四级。

它回答：

> **“这个节点在药学知识世界里属于哪一个自然层？”**

### 当前类型

| `tier`       | 中文  | 典型内容              | 填充色语义   |
| ------------ | --- | ----------------- | ------- |
| `basic`      | 基础层 | 生理、病理、基础药理机制、基础概念 | 基础色     |
| `drug`       | 药物层 | 具体药物、制剂、药物类别      | **淡蓝色** |
| `disease`    | 疾病层 | 疾病、诊断、症状综合征、病理状态  | **粉红色** |
| `management` | 管理层 | 用药管理、合理用药、监护与决策   | 管理色     |
| `service`    | 服务层 | 药学服务流程、服务模块       | 服务色     |
| `legal`      | 法律层 | 法规、政策、伦理          | 法律色     |

### 设计原则

1. `tier` 继续使用现有知识层级色彩体系。
2. **药物层使用淡蓝色，疾病层使用粉红色**，保持一眼可识别的语义差异。
3. 其他 `tier` 使用各自独立的固定色，不通过渐变表达层级。
4. `tier` 不表达思维导图结构级别。
5. 同一 `tier` 无论处在一级还是四级，填充色都保持一致。
6. 填充色不得承担“重点/难点/掌握状态”等其他含义。

> `level` 和 `tier` 必须正交：
>
> - `level` = 纸图结构位置
>
> - `tier` = 药学知识自然层级
>
> 因此可以出现：
>
> `level: 3 + tier: drug`
>
> 也可以出现：
>
> `level: 4 + tier: disease`

***

## 2.4 四维组合的完整含义

一个节点最终由以下四个属性共同决定其视觉身份：

```text
                  节点
                   │
       ┌───────────┼───────────┐
       ↓           ↓           ↓
    essence      level       tier
       │           │           │
      形状        边框色      填充色
       └───────────┬───────────┘
                   │
             edges_out.type
                   │
              边的视觉类型
```

例如：

```yaml
essence: medication
level: 4
tier: drug
```

表示：

> 这是一个**具体药物**节点；它在纸图中属于**四级节点**；它属于药学知识中的**药物层**。

视觉上即：

> **椭圆 + 四级边框色 + 淡蓝色填充**

而不是让一个颜色同时承担三个含义。

# 三、location — 教材位置

`location` **保留原字段结构，不参与四个视觉维度的计算。**

它只回答：

> **“这个节点在原教材/资料中来自哪里？”**

### 标准结构

```yaml
location:
  book: 药学专业知识二
  part: 某篇
  chapter: 某章
  section: 某节
  subsection: 某子节
  item: 某具体知识点
```

### 字段规则

| 字段           | 类型       | 是否必填 | 含义       |
| ------------ | -------- | ---: | -------- |
| `book`       | `string` |    ✅ | 根文件名/教材名 |
| `part`       | `string` |   可选 | 篇        |
| `chapter`    | `string` |    ✅ | 章        |
| `section`    | `string` |   可选 | 节        |
| `subsection` | `string` |   可选 | 子节       |
| `item`       | `string` |   可选 | 具体知识点    |

### 保留规则

1. `location` 原则上维持教材真实目录结构。
2. `label` 不附带“第几章/第几节”等目录序号。
3. 目录序号只出现在 `location` 对应值或节点详情中。
4. `section == chapter` 时可删除重复的 `section`。
5. `subsection == section` 时可删除重复的 `subsection`。
6. 不为了让 `location` 与纸图层级一致而修改教材位置。
7. **`location`** **不决定** **`essence`、`level`、`tier`，也不直接决定边类型。**
8. 节点详情面板可以完整展示 `location`，但主思维导图默认不把它展开为额外视觉编码。

### 最重要的结构原则

> **思维导图结构 ≠ 教材目录结构。**

例如：

```yaml
label: 首选药物
level: 3
location:
  book: 药学专业知识二
  chapter: 精神与中枢神经系统疾病用药
  section: 镇静催眠药
```

这个节点在教材里属于“镇静催眠药”，但在纸质思维导图中可能作为另一个大分支下的三级节点。两者可以同时成立，互不冲突。

***

# 四、tags — 标签

`tags` 用于补充节点检索信息，不承担四个视觉维度的语义。

```yaml
tags:
  - 口服
  - 老年人
  - 肝损伤
  - 药物监测
```

### 类型

```text
string[]
```

### 规则

1. 标签必须是有检索价值的关键词。
2. **优先复用 `summary.short` / `summary.full` 里已有的关键词**——不要自作主张另造同义/近义词（参见 §四 与 RULES §5.11.4）。
3. **不写语义重复的标签**：同一节点下不允许同时存在 `口诀` 与 `记忆口诀`、`禁忌` 与 `禁用`、`适应症` 与 `适用症` 等同/近义形式。先出现则保留先出现的。
4. 不把 `essence`、`level`、`tier` 的枚举值重复写入 `tags`。
5. 不把“药物/疾病/概念”等节点本质重复写成标签。
6. 不把整个句子放进 `tags`。
7. 建议每个普通知识节点 2–8 个；不是硬性要求，纸图迁移时以原资料信息完整性优先。
8. 疾病如果已经建立独立 `illness` 节点，仍允许在相关药物节点保留疾病名标签，作为检索索引。

### Tags 应包含的内容（按节点类型）

> 关键词抽取来源：summary.short / summary.full 中加粗的词。药物节点须同时包含分类和作用，分类可不止一个。

| 节点类型 | 必须包含 | 说明 |
|---|---|---|
| **药物节点** | 分类 tag + 作用 tag（≥各1） | 分类如 `H1受体激动剂`、`他汀类`；作用如 `扩张血管`、`降压`；可另加 ADR/禁忌/注意事项 tag |
| **分类节点** | 分类名 + 本质 tag（可选） + 重点子代表药 + 功能作用机制 | 如 `酰胺类`（分类）+ `γ-氨基丁酸衍生物`（本质）+ `吡拉西坦`（重点代表药）+ `脑代谢改善`（功能） |
| **其他节点** | 视节点内容决定，通常为分类/作用/适应症等核心关键词 | — |

### 抽取流程

从 `summary.short` / `summary.full` 中抽取标注了 `**关键词**` 的内容作为 tag 候选词。其余流程与约束见 RULES §5.11.4。

# 五、summary — 节点详情摘要

```yaml
summary:
  short: 一句话定义
  full: 详细解释
```

## `short`

- 类型：`string`

- 推荐长度：≤ 40 字

- 用于悬停/快速查看

- 必须是完整陈述句

- 不写“本章/本节/本文”等元话语

## `full`

- 类型：`string`

- 推荐长度：≤ 100–150 字

- 用于节点详情弹窗

- 可补充背景、意义、临床价值及关键关系

- 不要求与正文完全重复

> `summary` 是**节点详情内容**，不参与形状、边框色、填充色或边类型计算。

***

# 六、edges\_out — 思维导图关系边

当前正式使用 **6 种边类型**。

原则：

> **边类型少而稳定；具体语义放进** **`reason`。**
>
> **边方向由发起方决定**：每个节点的 `edges_out` 表达的是"我向外辐射的引用"。`parent` 由子节点（level 大）写、`support` 由辅助节点（mnemonic/note/table）写、`link` 由业务主动方写。详见 §7、§9.2、§9.4。

不再把 `treats`、`causes`、`activates`、`inhibits`、`interacts`、`contraindicates` 等全部作为独立 `type`。

示例：

```yaml
edges_out:
  - target: 癫痫持续状态
    type: link
    reason: 治疗
```

而不是：

```yaml
- target: 癫痫持续状态
  type: treats
```

这样既能保留“治疗”这个具体语义，又能显著减少边类型数量。

***

## 6.1 六种边总览

| `type`     | 中文   | 核心语义                     | 是否方向敏感   | 线型      | 建议颜色 |
| ---------- | ---- | ------------------------ | -------- | ------- | ---- |
| `parent`   | 层级归属 | A 是 B 的下级结构节点            | ✅ 数据上有方向 | **实线**  | 中性灰  |
| `branch`   | 分支展开 | A 展开出 B / A 与 B 属于纸图分支结构 | 结构方向     | **实线**  | 蓝色   |
| `link`     | 明确关系 | 存在明确知识关系，由 `reason` 说明   | ✅ 通常有方向  | **实线**  | 绿色   |
| `relate`   | 一般关联 | 两节点需要放在一起理解，但没有更强关系      | ❌        | **点线**  | 灰紫   |
| `support`  | 学习辅助 | 主知识与口诀/总结/表格/注意等辅助对象的关系  | ✅        | **虚线**  | 橙色   |
| `contrast` | 对比区分 | 两节点用于比较、辨析、排除混淆          | ❌ / 双向   | **点划线** | 紫色   |

> **所有边不使用粗细表达语义差异。**
>
> **所有边不使用渐变色。**
>
> 同一种边始终保持同一种颜色和线型。

***

# 七、六种边的详细规范

## 7.1 `parent` — 层级归属

表达：

> A 在纸质思维导图结构上属于 B 的下一级。

例如：

```text
一级主题
  └── 二级主题
       └── 三级主题
            └── 四级知识点
```

数据方向统一：

```text
子节点 → 父节点
```

例如：

```yaml
- target: 镇静催眠药
  type: parent
  reason: 属于该分类
```

### 视觉

- 颜色：中性灰

- 线型：**实线**

- 箭头：默认**不显示箭头**，以树枝/层级连线视觉呈现

- 关系标签：通常不显示；需要解释时可显示 `reason`

### 注意

`parent` 只表示**纸图结构层级**，不表达：

- 药物属于药物类别的药理学归类

- 药物治疗疾病

- 机制导致效应

这些均应使用其他边。

***

## 7.2 `branch` — 分支展开

表达：

> 一个节点在纸质图中向多个下位概念展开，或多个节点构成某个明显的分类分支。

例如：

```text
镇静催眠药
├── 入睡困难
├── 焦虑型失眠
└── 维持睡眠
```

### 视觉

- 颜色：蓝色

- 线型：**实线**

- 箭头：默认**无箭头**

- `reason`：可写“分为”“展开为”“包括”等

### `parent` 与 `branch` 的区别

- `parent` = **严格的层级归属**

- `branch` = **纸图中的展开/分支关系**

一个节点可以在数据上 `parent` 某个父节点，同时通过 `branch` 与纸图中其他分支发生组织联系。

***

## 7.3 `link` — 明确知识关系

这是药学知识关系的主承载边。

不再继续细分成十几种边，而通过 `reason` 表达具体关系。

### 常用 `reason`

```text
治疗
导致
作用于
激动
抑制
代谢
相互作用
禁忌
前测
特点
适用于
代表
```

例如：

```yaml
- target: 癫痫持续状态
  type: link
  reason: 治疗

- target: 嗜睡
  type: link
  reason: 导致

- target: GABA_A受体
  type: link
  reason: 作用于

- target: HLA-B*1502
  type: link
  reason: 前测
```

### 视觉

- 颜色：绿色

- 线型：**实线**

- 箭头：默认显示方向箭头

- `reason`：作为边标签，在 hover / 点击时显示

### 为什么不用 `treats / causes / activates ...`

这些具体词仍然保留在 `reason`，但不再把每个具体动词都升级成新的可视边类型。

这样：

> **type 负责“关系家族”；reason 负责“具体关系”。**

***

## 7.4 `relate` — 一般关联

表达：

> A 与 B 有明确学习/知识联系，但没有足够理由归入更具体关系。

典型情况：

```text
两个需要联想记忆的知识点
跨章节但需要一起复习的内容
同一个临床问题下的弱关联节点
```

### 视觉

- 颜色：灰紫色

- 线型：**点线**

- 箭头：无

- `reason`：可以写“相关”“联想”“跨章节关联”等

### 使用限制

`relate` 是**兜底关系**，但不能成为“懒得判断具体关系时什么都用”的万能边。

凡是可以明确表达为 `parent / branch / link / support / contrast` 的，应优先使用具体关系。

***

## 7.5 `support` — 学习辅助

表达：

> 一个知识节点和一个“帮助理解/记忆/总结”的辅助节点之间的关系。

典型目标包括：

```text
mnemonic   口诀
summary    总结
 table     表格
note       注意/提示
```

例如：

```yaml
- target: 入扎焦氟双佐唑
  type: support
  reason: 记忆口诀
```

```yaml
- target: 镇静催眠药总结
  type: support
  reason: 总结
```

### 视觉

- 颜色：橙色

- 线型：**虚线**

- 箭头：**由辅助节点（mnemonic / note / table / summary）自身**的 `edges_out` 写 `support →` 主知识节点，而不是反过来。理由：新增一个口诀 / 总结 / 表格 / 注意节点时只需新建该辅助节点的 md，不必回去修改主知识节点的 `edges_out`。详见 §9.4 反例 3 与 RULES §5.15。

- `reason`：显示具体辅助类型

### 注意

- `support` 不表示药学事实。

  例如：

  > “卡马西平 → 口诀” = `support`（由**口诀节点**发起）

  而：

  > “卡马西平 → 三叉神经痛” = `link + reason: 治疗`（由**药物节点**发起）

  两者必须区分。

***

## 7.6 `contrast` — 对比区分

表达：

> 两个节点需要通过比较来理解其差异或共同点。

典型情况：

```text
PPI ↔ P-CAB
短效 ↔ 长效
苯二氮䓬类 ↔ 非苯二氮䓬类
药物A ↔ 药物B
```

### 视觉

- 颜色：紫色

- 线型：**点划线**

- 箭头：默认双向箭头

- `reason`：显示“对比”“易混淆”“区别”等

### 使用限制

“同级”不自动使用 `contrast`。

如果只是同级并列而没有比较意图，应使用 `branch` 或不建立额外边。

只有确实存在：

> **“把 A 和 B 放在一起比较”**

的学习意图时才使用 `contrast`。

***

# 八、边的视觉规范汇总

```text
parent    ─────────────  灰色实线       层级树
branch    ─────────────  蓝色实线       分支展开
link      ─────────────  绿色实线 →     明确知识关系
relate    · · · · · ·    灰紫点线       一般关联
support   - - - - - -    橙色虚线 →     学习辅助
contrast  ─ · ─ · ─ ·    紫色点划线 ↔   对比区分
```

### 强制限制

- ❌ 不用线宽区分重要程度

- ❌ 不用线宽区分关系强弱

- ❌ 不使用渐变色

- ❌ 不使用透明度区分关系

- ❌ 不使用发光/阴影区分关系

- ❌ 不再为每个具体药学动词建立一个新的 `edge.type`

### `reason` 的职责

> **`type`** **决定边是什么“家族”；`reason`** **决定用户看到的具体中文关系。**

例如：

```yaml
- target: 三叉神经痛
  type: link
  reason: 治疗
```

前端显示：

```text
[绿色实线箭头]
        治疗
```

而：

```yaml
- target: 入扎焦氟双佐唑
  type: support
  reason: 记忆口诀
```

前端显示：

```text
[橙色虚线箭头]
        记忆口诀
```

***

# 九、层级与边的使用规则

## 9.1 纸图层级优先使用 `parent`

对于真正的：

```text
一级 → 二级 → 三级 → 四级 → 五级 → 六级
```

统一使用：

```text
子 → 父
```

例如：

```yaml
# “镇静催眠药”节点
level: 2
edges_out:
  - target: 精神与中枢神经系统疾病用药
    type: parent
    reason: 属于上级主题
```

> `parent` 是唯一用于表达严格纸图层级归属的边。

***

## 9.2 不要求父节点反向枚举所有子节点

不要写：

```yaml
# 错误
# 父节点
edges_out:
  - target: 子节点A
    type: parent
  - target: 子节点B
    type: parent
```

而应由子节点声明：

```yaml
# 正确
# 子节点
edges_out:
  - target: 父节点
    type: parent
    reason: 属于上级主题
```

这样可以避免重复边和双向层级污染。

> **铁律：边的方向是"子 → 父"，永远是子节点持有指向父节点的 `parent` 边，父节点永远不反向持有指向子节点的层级边。**
>
> 如果你发现某个节点的 `edges_out` 里写了 `type: parent`，那它必须是该边所指向目标的**下级**。

### 推广到所有边：每个节点自管自己的 `edges_out`

> **通用规则**：所有 `edges_out` 都表示"这个节点向外辐射的引用关系"，**每个节点自己决定自己往外指哪些边**。
>
> 新增任何节点时，**只需要修改该节点自己的 md 文件**——不必回去修改任何其他节点（包括父节点、辅助对象、对比对象）的 `edges_out`。

| 关系类型 | `edges_out` 写在 |
| --- | --- |
| 父子层级（`parent`） | 子节点文件里（level 大） |
| 辅助学习（`support`） | **辅助节点**文件里（口诀 / 注意 / 对比表） |
| 药学关系（`link`） | **业务主动方**文件里（提供方 / 描述方） |
| 横向对比（`contrast`） | **任一侧**（单边写即可，渲染端补双向视觉） |
| 一般关联（`relate`） | **任一侧**（推荐 level 较大 / 信息提供方） |

详见 RULES §5.15 与本节 §9.4。

***

## 9.3 `location` 不参与层级边生成

即使：

```yaml
location:
  chapter: 精神与中枢神经系统疾病用药
  section: 镇静催眠药
```

也不意味着程序应该自动根据 `location` 生成 `parent`。

因为：

> **教材目录只是来源坐标，纸图结构才是真正的思维导图结构。**

如果纸图中确实存在“镇静催眠药 → 第一章”的结构关系，应由节点显式写 `parent`。

***

## 9.4 边方向易错点汇总

迁移纸图时最常见的错误是**边方向颠倒**——子节点持有指向父节点的边、辅助节点持有指向主知识的边。下面 4 个反例必须避免。

### ❌ 反例 1：父节点反向持有 `parent` 边

```yaml
# 错误：父节点不该写指向子节点的 parent 边
# 镇静催眠药.md
edges_out:
  - target: 唑吡坦
    type: parent
    reason: 下属药物
```

应改为由子节点声明：

```yaml
# 正确：唑吡坦.md
edges_out:
  - target: 镇静催眠药
    type: parent
    reason: 属于该主题
```

### ❌ 反例 2：分类/药物节点把 `type: child` 当作 "child → parent"

```yaml
# 错误：child 不是合法方向标签，"我是 child" 是没意义的
edges_out:
  - target: 镇静催眠药
    type: child
    reason: 属于该主题
```

层级归属永远是子节点持有 `type: parent` 指向父节点，**不存在 `type: child`**。

### ❌ 反例 3：药物/分类节点反向持有 `support` 边指向口诀

```yaml
# 错误：主知识不该主动连向口诀，这会把口诀画成下级
# 丁苯酞.md
edges_out:
  - target: 丁苯酞口诀
    type: support
    reason: 记忆口诀
```

应由口诀节点持有 `support` 边指向主知识：

```yaml
# 正确：丁苯酞口诀.md
edges_out:
  - target: 丁苯酞
    type: support
    reason: 丁苯酞口诀
```

### ❌ 反例 4：口诀节点持有 `parent` 边 "挂在" 某个分类下

```yaml
# 错误：口诀不是层级的下级，挂错地方会被画成药物的子节点
edges_out:
  - target: 酰胺类中枢兴奋药
    type: parent
    reason: 帮助记忆酰胺类
```

口诀是**辅助节点**，与主知识是**辅助关系**而非**层级关系**，必须用 `support`，不能用 `parent`。

### ✅ 一句话判断法

> **写一条 `edges_out` 之前，先问自己两个问题：**
>
> 1. **我是谁的"下级/被记忆对象/被帮助者"吗？**
>    - 是 → 类型是 `parent`（仅限我是下级、对方是上级时）
>    - 不是 → 不是 `parent`
>
> 2. **如果我是一个口诀/总结/表格/注意节点，我应当指向谁？**
>    - 单药口诀 → 该药物
>    - 分类口诀 → 该分类
>    - 总结/表格/注意 → 所属主知识
>    - 全部使用 `type: support`

***

# 十、口诀、总结、表格、注意节点

这些节点现在允许作为独立 `.md` 节点。

## 10.1 口诀

```yaml
essence: mnemonic
```

例如：

```yaml
label: 入扎焦氟双佐唑
essence: mnemonic
level: 4
tier: drug
```

其与知识节点的关系：

```yaml
edges_out:
  - target: 镇静催眠药
    type: support
    reason: 记忆口诀
```

### 规则

- 口诀是独立节点，允许被多处引用。

- 口诀节点不是药物，不使用 `medication`。

- 口诀节点不是普通概念，不使用 `concept`。

- 口诀节点不得成为 `parent` 层级中的教材知识父节点。

### 口诀边的方向：口诀 → 主知识

口诀是**辅助节点**，必须由**口诀节点自己**声明指向它所辅助的**主知识节点**：

```yaml
# 正确：口诀节点持有 support 边，指向被记忆的主知识
edges_out:
  - target: 丁苯酞
    type: support
    reason: 丁苯酞口诀
```

而**不是**：

```yaml
# 错误：药物节点反向持有 support 边指向口诀
# 这会让口诀被画成药物的下级节点，扭曲层级结构
edges_out:
  - target: 丁苯酞口诀
    type: support
    reason: 记忆口诀
```

### 口诀指向谁：单药口诀 vs 分类口诀

| 口诀类型     | 示例                          | 应指向                          |
| -------- | --------------------------- | ---------------------------- |
| **单药口诀** | "丁苯酞，枸循环，抗血栓，就是怕芹菜" | **该药物本身**（如 `med-butyphthalide`） |
| **分类口诀** | "多加点利是吧，胆子真大"（记 4 个代表药） | **该分类本身**（如 `class-achei`）     |

判断标准：

> **口诀内容记住的是哪个层级的知识，就指向哪个层级。**
>
> - "怕芹菜"是丁苯酞的禁忌 → 指向丁苯酞药物节点
> - "多加点利是吧"是把 4 个代表药编成一句 → 指向分类节点

***

## 10.2 总结

```yaml
essence: summary
```

例如：

```yaml
label: 镇静催眠药选择总结
essence: summary
level: 4
tier: drug
```

可以由多个知识节点 `support` 到总结节点，表示：

> 多个零散知识 → 一个压缩总结。

如果纸图明确表现为“多个节点共同汇聚到总结”，应保留这种多入边结构。

***

## 10.3 表格

```yaml
essence: table
```

表格只有在原纸质资料中确实作为独立视觉知识块存在时建立节点。

例如：

```yaml
label: 苯二氮䓬类作用时长比较表
essence: table
level: 4
tier: drug
```

不要因为某段正文“可以整理成表格”就凭空生成 `table` 节点。

***

## 10.4 注意/提示

```yaml
essence: note
```

例如：

```yaml
label: 老年人更敏感
essence: note
level: 4
tier: drug
```

与主知识节点使用：

```yaml
- target: 苯二氮䓬类
  type: support
  reason: 注意
```

***

# 十一、`notion` 的使用边界

`notion` 保留，但要和 `note`、`mnemonic` 区分。

### `concept`

> 教材中有明确边界、可以定义和解释的知识单元。

例如：

```text
首过效应
5-HT 综合征
体位性低血压
```

### `notion`

> 对知识进行学习性压缩后的经验认识，但它不是单纯的“注意提醒”，也不是一句口诀。

例如：

```text
“起效延迟 4～6 周”
“轻症患者在某场景下优先考虑……”
```

### `note`

> 原纸图明确标记为【注意】【提示】【易错】等警示信息。

### `mnemonic`

> 明确用于记忆的口诀。

这四者不要混用。

***

# 十二、疾病节点规则

`illness` 是独立知识节点，不再仅作为 tag。

```yaml
essence: illness
tier: disease
```

### 应独立成节点的情况

满足以下任一条件即可建立：

1. 是 `link + reason: 治疗` 的目标；
2. 是 `link + reason: 禁忌` 的目标；
3. 是多个节点共同关联的重要疾病；
4. 原纸图已经把该疾病单独画成一个方框；
5. 该疾病是后续多个关系的汇聚节点。

### 可只作 tag 的情况

- 一次性出现的小症状；

- 没有独立知识价值、仅用于正文检索的词；

- 纸图中没有独立节点表达。

核心原则：

> **纸图独立画成节点的疾病，电子版原则上也应该是独立节点。**

***

# 十三、一个完整节点示例

```yaml
data:
  id: zuopitan
  label: 唑吡坦
  essence: medication
  level: 4
  tier: drug

  location:
    book: 药学专业知识二
    chapter: 精神与中枢神经系统疾病用药
    section: 镇静催眠药
    item: 唑吡坦

  tags:
    - 非苯二氮䓬类
    - 失眠
    - 入睡困难

  summary:
    short: 唑吡坦是用于失眠治疗的非苯二氮䓬类镇静催眠药。
    full: 唑吡坦主要用于失眠，尤其用于改善入睡困难；其药理作用和临床应用应结合非苯二氮䓬类镇静催眠药整体理解。

  edges_out:
    - target: 镇静催眠药
      type: parent
      reason: 属于该主题下的具体药物

    - target: 失眠
      type: link
      reason: 治疗

    - target: 镇静催眠药选择总结
      type: support
      reason: 纳入总结

    - target: 佐匹克隆
      type: contrast
      reason: 同类药物比较
```

视觉含义：

```text
唑吡坦
│
├─ 形状：ellipse          → 具体药物
├─ 边框：level 4          → 四级节点
├─ 填充：tier drug        → 淡蓝色药物层
│
├─ parent  灰色实线       → 所属上级主题
├─ link    绿色实线箭头   → 明确知识关系
├─ support 橙色虚线箭头   → 学习辅助
└─ contrast 紫色点划线    → 对比关系
```

# 十四、纸质思维导图的最低迁移原则

为了最大程度还原纸质资料，电子化时遵循：

## 1. 纸上独立成框的对象，优先成为独立节点

不要因为某个东西“理论上可以写进正文”就把纸上的方框删除。

尤其是：

```text
口诀
总结
表格
注意
分类
代表药物
```

这些本身就是纸图的结构信息。

## 2. 纸上有分支，就尽量保留分支

不要为了追求“知识图谱很规范”而把所有节点压平成一条关系网络。

纸质图的：

```text
A
├── B
├── C
└── D
```

本身就是重要信息。

## 3. 纸上有总结汇聚，就保留汇聚

```text
A ─┐
B ─┼→ 总结
C ─┘
```

不要把它仅转换成 A/B/C 各自正文中的一句话。

## 4. 纸上有口诀，就保留口诀节点

不要为了减少节点数量而把口诀重新塞回正文。

## 5. 纸图结构优先，教材目录次之

教材目录通过 `location` 保存；

思维导图结构通过 `level + parent/branch` 保存。

两者同时存在，但互不替代。

***

# 十五、完成标准

一个标准节点应满足：

```text
[身份]
 id + label

[本质]
 essence

[节点层级]
 level

[知识层级]
 tier

[教材来源]
 location

[内容]
 summary / tags

[关系]
 edges_out
```

### 校验要求

1. `id` 唯一；
2. `label` 非空；
3. `essence` 必须属于当前允许枚举；
4. `level` 必须为 `1 / 2 / 3 / 4 / 5 / 6`；
5. `tier` 必须属于当前允许枚举；
6. `location.book` 必须存在；
7. `edges_out.target` 必须指向仓库中真实存在的节点；
8. `edges_out.type` 只能使用 6 种正式边类型；
9. 所有具体关系词写在 `reason`，不自行创造新的 `type`；
10. `parent` 不允许父节点反向枚举子节点；
11. 不允许同一结构关系双向重复声明；
12. `location` 不参与视觉样式计算；
13. 不允许使用字体、粗细、阴影、渐变、透明度、节点大小等额外变量表达语义；
14. 纸图独立节点原则上不得被合并成正文文本而丢失其结构身份。

***

# 十六、最终设计原则

```text
                    纸质思维导图电子化
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
       节点本质            纸图层级            知识层级
          │                   │                   │
      essence              level                 tier
          │                   │                   │
        形状               边框色               填充色
          │                   │                   │
          └───────────────────┼───────────────────┘
                              │
                         边类型 type
                              │
           ┌─────────┬────────┼────────┬─────────┐
           ↓         ↓        ↓        ↓         ↓
        parent    branch    link    relate    support    contrast
           │         │        │        │         │           │
         层级       分支     明确关系   关联      学习辅助      对比
                              │
                           reason
                              │
                    具体中文关系语义

        location = 教材来源坐标，不参与上述视觉编码
```

> **一句话总原则：**
>
> **形状回答“它是什么”；边框色回答“它在纸图第几级”；填充色回答“它属于哪个知识层”；边类型回答“它和谁怎么连”；`reason`** **回答“具体为什么连”；`location`** **只负责告诉我们“它在教材哪里”。**
