## 8. 跨布局共同问题

### 8.1 `animationDuration` 语义不一致

| 布局                                      | `animate` 实际值                   | `animationDuration` 含义                                 |
| ----------------------------------------- | ---------------------------------- | -------------------------------------------------------- |
| COSE                                      | `true`（core 接管，非 `'during'`） | cytoscape core `layoutPositions` 一次性 from→to 插值时长 |
| Concentric / Circle / Grid / Breadthfirst | `true`                             | 同上                                                     |
| Dagre                                     | `'end'`                            | cytoscape core `layoutPositions` 一次性 from→to 插值时长 |
| Euler                                     | `true`（连续模式）                 | **被忽略**                                               |

**给用户的统一 slider label 是"动画时长"，但底层语义每个布局都不同**——尤其是 Euler 改了无效。建议：

- 在 `LayoutParam` 加 `description` 字段，hover tooltip 解释每个布局的语义差异。
- 或者把 COSE 的 `animate` 改成 `'end'`，让所有布局的"动画时长"语义统一（cytoscape core 都接管）。

### 8.2 切布局时滑块状态丢失

`layout-manager.ts:85` 的 `container.innerHTML = ...` 每次 `renderLayoutParams` 都重建 DOM 节点，**用户在 layout A 调好的 slider 值在切到 layout B 再切回 layout A 后会丢失**。`LAYOUTS` 状态对象没有按 layout key 缓存用户 override。

可能是 by design（"切布局就是切预设"），但用户体感是"我刚才调好的怎么没了"。如需持久化，用 `localStorage[layoutName]` 缓存每布局最后一次的 slider 集合即可。

### 8.3 `params` 表无 `description` 字段

`LayoutParam` 接口（`config.ts:197-206`）只有 `label`，没有 `description` / `tooltip`——**COSE 的 `nodeRepulsion: 35000` 跟官方默认 4500 差 7.8 倍、Euler `gravity` 是负斥力、COSE `numIter` 在 `quality: 'default'` 下不生效**——这些"用户调参时最需要知道的事实"在 UI 上**一个字都没有显示**。

建议加 `description?: string` 字段，`.param-row` 渲染时附带 `<span title="...">` 或 hover popover。

### 8.4 `LayoutParam` 类型缺 `type: 'select' | 'bool'`

`config.ts:197-206`：

```ts
export interface LayoutParam {
  key: string;
  label: string;
```

### 12.1 COSE / Euler 节点重叠 ✅ 已修

#### 根因（不仅是参数问题，还有死字段 + 公式读法误判）

1. **`minNodeSpacing` / `avoidOverlap` 是 cytoscape 内置字段，cose-bilkent 根本不读**——`cytoscape-cose-bilkent/src/index.js:84-122` 的 `getUserOptions` 完全不出现这两个 key；cytoscape core 的 `layoutPositions` 后处理**只对内置布局（cose/concentric/grid/circle）调用**，对扩展布局（cose-bilkent / dagre / euler）不跑。原清单 §1.2 把这俩标 ✅ "cytoscape core 通用字段"——是错的。
2. **`edgeElasticity` 公式读反**：原清单 §1.2 写"cose-bilkent 用作除数而非系数，实际有效"。**错的**——`layout-base/src/fd/FDLayout.js:223` 是 `springForce = this.springConstant * (length - idealLength)`，是**正向系数**。项目原 `edgeElasticity: 60` 实际上是非常强弹簧（60 倍胡克刚度），与 `idealEdgeLength: 400` 强耦合后，节点被强力推到 400 距离、斥力又把距离压回——平衡点不稳，导致中心区域重叠。
3. **`quality: 'default'` 模式下 numIter 不生效**：cose-base 在 default quality 下走自适应冷却（`MAX_ITERATIONS` 仅作硬上限），224 节点下经常过早收敛。

#### 修复（src/core/config.ts）

### 12.5 默认布局锁定 + Euler 滑块扩域（2026-07）

§12.4 改完 DEFAULT_LAYOUT='euler' 后用户仍报告"默认还是 COSE"。根因不在 config.ts,而在 **3 个 bootstrap 入口仍写死 'cose'**:Renderer constructor 被 main.ts 显式传入 'cose' 覆盖;index.html 两处 `.active` class 仍在 COSE 按钮上;action-handlers `reset-all` 重置回 'cose'。

#### 1. bug 修复

| 文件                            | 位置                             | 改动                                                                                      |
| ------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------- |

#### 2. 加 1 个 e2e guard (`config-layouts.test.ts`)

```ts
it('index.html default-active layout button matches DEFAULT_LAYOUT', ...)
```

- 扫描 `index.html` 所有 `<button class="...active..." data-(name|arg)="...">`

#### 3. Euler 滑块扩域 (用户反馈"参数范围放大一点")

| 字段              | §12.4                    | §12.5                 | 理由                                                     |
| ----------------- | ------------------------ | --------------------- | -------------------------------------------------------- |
| springCoeff       | 0.0001~0.01, step 0.0001 | **0.00005~0.05**      | 加探索极端值:小→无弹簧,大→强黏着                         |

| pull              | 0~0.01, step 0.0005      | **-0.005~0.05**       | 加负 pull (centrifugal 中心斥力) + 较大正 pull           |
| refresh           | 1~100                    | **1~200**             | 慢速动画长链场景                                         |
| maxIterations     | 100~10000                | **100~30000**         | 超长迭代调试                                             |
| maxSimulationTime | 500~40000                | **500~120000**        | 10000+ 迭代需 ~2min                                      |

#### 1. 三处字面 COSE 残留

| 位置             | 字段                       | 原字面               | §12.6                     |
| ---------------- | -------------------------- | -------------------- | ------------------------- |
| `index.html:81`  | `#layout-switcher-current` | `COSE`               | `Euler`                   |

| `index.html:353` | `#layout-desc`             | `COSE — 力学弹簧...` | `Euler — 基于图论力学...` |

之前只有 #stat-layout 在 graph-stats.ts:88 的 `updateStats(cy)` 里被 setStat 覆盖;另外两个**没有同步逻辑**,纯靠 HTML 字面展示。

#### 2. 抽 `syncLayoutDisplay` 复用 UI 同步逻辑

`src/ui/layout-manager.ts` 把原 `runLayout` 内的 5 步 DOM 同步抽成独立 export:

```ts
export function syncLayoutDisplay(name: string): void {
  // 1. 清 .layout-btn 全 active + 设选中
  // 2. 设 #btn-{name} active (desktop toolbar segments)
  // 3. 设 #bs-btn-{name} active (mobile sheet)
  // 4. 设 #layout-desc 描述文字 (从 LAYOUTS[name].description)
  // 5. 设 #layout-switcher-current label (从 LAYOUT_LABELS)
  // 6. 设 popover 每个 layout-switcher__item 的 aria-selected
}
```

`runLayout` 改为一行 `syncLayoutDisplay(name); renderLayoutParams(name);`——保持代码路径等价。

#### 3. bootstrap 同步

`src/ui/main.ts` Renderer 创建后立即:

```ts
syncLayoutDisplay(DEFAULT_LAYOUT);
setCurrentLayout(DEFAULT_LAYOUT);
```

这样首次 paint 之前虽然 HTML 字面已是 "Euler" (§12.6 同改),运行时 sync 会再覆盖一次——双保险,且模型 = 一切 DOM surface 必须同步 DEFAULT_LAYOUT 的单一真相变得可推。

#### 4. e2e guard 增 1

```ts
it('index.html #layout-switcher-current initial label matches DEFAULT_LAYOUT', ...)
```

扫描 index.html 字面值 `#layout-switcher-current` 内容,跟 `LAYOUT_LABELS[DEFAULT_LAYOUT]` 比对。临时还原字面 'COSE' 验证 guard 触发后撤回。

**反思**:任何"配置 → 启动后立即显示"的耦合都要有静态字面 + runtime sync 双保险。prettier 不能 fmt index.html (pre-existing parse error),但 e2e guard 能锁定关键文案。
