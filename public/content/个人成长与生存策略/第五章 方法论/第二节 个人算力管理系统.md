# 第二节 个人算力管理系统

## 一、系统定位：为什么把认知与精力管理建模为“算力系统”？

第三章第一节已经阐明：个体的先天高敏感底色难以被物理卸载，日常的情绪调节、理性分析与冲动抑制高度依赖自上而下的执行控制；而第四章第一节又指出，人脑的工作记忆与每日高阶专注带宽是严格受限的。

在本节中，我们借用计算机工程中的**“算力（Compute）、电量、配额与熔断（Circuit Breaking）”**作为认知资源管理模型（注：此为工程管理隐喻，用于直观刻画认知带宽的消耗与保护，不直接等同于生理学指标测量）。
本系统的核心目标是：**防止有限的高阶认知资源在内心冲突、情绪反刍与多任务空转中被烧穿，确保核心主线拥有稳定的资源供给，并在过载发生时第一时间安全停机。**

## 二、六步闭环架构（2.1 → 2.6）

本节严格按照“识漏记账 → 常态节流 → 日常充电 → 负载预警 → 应急熔断 → 事后调优”的工程闭环组织为六个子模块：

| 子模块 | 核心节点与工具卡 | 触发条件与停止条件 |
| :--- | :--- | :--- |
| **2.1 算力账本：认知资源与消耗来源** | 《第一节 算力账本》《意志力：前额叶有限算力》《意志力消耗大头》 | **日常前置认知**：识别“持续内心冲突”为头号漏电黑洞；凡属先天常数项立即停止硬顶 |
| **2.2 常态管控闭环** | 《第二节 常态管控闭环》★《管控闭环总览》《第一步·觉察打标签》《警报响，不等于着火》《第二步·强制冷却规则》《第三步·标准化思考框架》《第四步·环境减触发》《管控机制六大坑》 | **触发**：出现情绪波动或冲动念头；<br>**停止**：完成标签命名、进入冷却期并回归主线动作 |
| **2.3 算力维护与恢复型资源** | 《第三节 算力维护》《恢复型资源认知》《算力维护五法》 | **日常基线维护**：每日保障 7–8h 睡眠地基、每 90min 停机留白；每次仅迭代 1 个新习惯 |
| **2.4 负载监测、预警与配额** | 《第四节 负载监测与配额》《三级预警信号监测》《L1 一级预警（早期）》《L2 二级过载（中度）》《L3 三级临界熔断》《反扑信号识别》《消耗配额管理》《配额规则》《消耗日志》 | **触发**：每周高消耗事件达上限（2–3 件）或出现 L1–L3 躯体/认知/心智反扑信号 |
| **2.5 熔断、恢复与误区拦截** | 《第五节 熔断与恢复》《熔断触发流程》★《应急熔断五步》《分级恢复协议》《认知误区拦截》《应急常见误区》 | **触发**：命中 L2/L3 预警或反扑信号；<br>**停止**：完成分级静默恢复（30min / 半天 / 1–3 天），核心信号归零 |
| **2.6 复盘与迭代** | 《第六节 复盘迭代》《复盘四问》 | **触发**：仅在状态完全恢复至 L0 后启动（严禁过载期复盘）；15 分钟内产出 1 条护栏微调规则即结束 |
