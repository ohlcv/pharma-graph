# PDCA 循环（戴明环）

## 一、来源与核心逻辑

PDCA（Plan-Do-Check-Act）由美国质量管理先驱爱德华兹·戴明推广，故又称戴明环（Deming Cycle）。它针对的是一个常见错觉——**把“执行完”当成“完成”**：任何工作或管理活动都不是一次性任务，而是螺旋上升、周而复始的改进过程；真正的终点不是“做完”，而是“把有效做法固化，并带着新问题进入下一轮”。

## 二、四个阶段与执行要点

| 阶段 | 核心任务 | 关键执行要点 |
| :--- | :--- | :--- |
| **P（Plan）计划** | 明确目标与制定方案 | 现状分析、找出核心问题、分析根本原因（如 5Why）、制定具体方案（SMART 原则）、明确衡量指标与责任人 |
| **D（Do）执行** | 按计划落实推进 | 按既定路径推进；大型项目先小范围试点，验证可行性并积累初步数据，避免全面铺开的高风险 |
| **C（Check）检查** | 评估结果与复盘对照 | 将实际产出与 Plan 的目标及指标对比，检查偏差，确认哪些做法见效、哪些未达预期，总结成功经验与失败教训 |
| **A（Act）处理** | 标准化与沉淀迭代 | ①成功经验标准化：沉淀为流程、规范或自动化脚本，防止问题复发；②遗留偏差或新问题转入下一轮 PDCA |

## 三、三个运作特征

### 3.1 大环套小环

组织层面有一个大 PDCA 循环，拆解到部门、项目、个人，各自都有对应的子循环；小环支撑大环，大环为小环提供方向与资源。

### 3.2 阶梯式上升

PDCA 不是在同一水平面上原地打转。每完成一轮并做好 A 阶段的标准化，管理基准就被抬高一层，下一轮循环从更高的起点出发。

### 3.3 闭环思维

执行不等于完成。缺少 Check 与 Act，事情就没有形成闭环，极易陷入“盲目忙碌但不长进”的状态——这也是判断一件事是否真正做完的最低标准。

## 四、在个人算力管理系统中的落地

把 PDCA 投影到本节所属的算力管理系统：

1. **P**：对应《第一节 算力账本》——先看清基线水位与真实约束，再设定本轮要改的具体参数。
2. **D**：对应《第二节 常态管控闭环》——按既定护栏执行，单次只改一个变量，避免多因素同时变动导致无法归因。
3. **C / A**：对应《第六节 复盘迭代》的《复盘四问》——在 L0 满电状态下对照指标检查偏差，并把有效改动写回护栏、阈值或配额表，完成标准化。

一轮走完，下一轮从更新后的护栏参数开始，而不是从“重新痛下决心”开始。
